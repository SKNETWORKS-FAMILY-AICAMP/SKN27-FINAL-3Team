## 1. 공통 결정 사항

- ERD는 화면설계서와 반드시 연결한다.
- 개인 화면은 화면별 플로우가 있어야 한다.
- 챗봇 관련 산출물은 `플로우차트`, `LangGraph 관점 흐름`, `시퀀스 다이어그램`까지 포함한다.
- RAG 호출, 상담 다시 호출하기, 리포트 저장/다운로드, 사건 상태값, 코드테이블 조회 흐름을 빠뜨리지 않는다.
- 기본 정렬 기준은 `상태 -> 날짜` 순서로 맞춘다.
- 내일까지 챗봇 시퀀스 다이어그램과 플로우를 우선 정리한다.
- 웹 관련 ERD는 1차 애자일 범위에서 화면설계서와 함께 본다.
- 경찰 API, 대법원 API는 MCP 관점으로 정리하고 변경 주기를 관리한다.
- 챗봇 적재 데이터는 3개월 기준으로 보고, 최신 질문은 최신 데이터 MCP 호출 전략을 별도로 둔다.
- 서버는 RunPod 기준으로 보고, 인증은 `JWC`로 기록되었으나 실제 구현 전 정확한 인증 방식 확인이 필요하다.
- 이슈 이름은 한글 기준으로 정리하고, 담당자가 변경한다.
- 주석 이름은 브랜치 명 기준으로 맞춘다.
- Supervisor에는 최종 검증 노드를 추가한다.

## 2. 담당자별 액션

### 2.1 이혜림 (`hi20260204-maker`)

- 진행 중인 Django 프로젝트 관련 이슈 상태를 다시 확인한다.
- 현재 주간 작업 이슈는 `In progress` 반영 우선순위로 본다.
- 이슈 close는 문서/설계/검증 근거를 나눠 순차적으로 진행한다.
- 로그인 개발을 진행한다.
- RunPod에 인증 절차를 검증할 수 있는 최소 함수 1개를 먼저 띄워본다.
- 챗봇 시퀀스 다이어그램, 챗봇 플로우, RAG 호출/재호출 흐름, 리포트 저장/다운로드 흐름, 사건 상태값 흐름, 코드테이블 조회 흐름을 정리한다.

### 2.2 재강 (`leejaegang27`)

#### 과실비율 데이터 파이프라인

- 시퀀스 다이어그램은 이미지로만 두지 않고 코드화한다.
- 서브 이슈를 더 세분화한다.
- 시퀀스 다이어그램을 더 상세하게 만든다.
- 에이전트 및 연계 설계를 필수 산출물로 둔다.
- 범위를 데이터 수집 중심에서 에이전트 관련 설계/구현 중심으로 바꾼다.
- 5주차에는 데이터 수집 작업으로 이관된 범위를 반영한다.

#### 마이페이지

- 마이페이지는 단순 서칭보다 상태 관리가 먼저 보이게 조정한다.
- 상태 관련 수정 요청을 반영한다.
- 기본 정렬은 `날짜 -> 상태`가 아니라 `상태 -> 날짜`로 바꾼다.

#### 기타

- LangGraph 개발을 시작한다.

### 2.3 주희 (`ohjuheecode`)

- 딥러닝 데이터셋 문제는 RunPod에서 진행한다.
- Google Drive와 RunPod 연동 가능 여부를 먼저 확인한다.
- 차선책은 AWS S3 연동으로 둔다.
- 이미지 데이터를 어떻게 추출/적재할지 먼저 정리한다.
- 식별 처리는 우선순위를 낮춘다.
- 이미지 분류 데이터셋은 충분하다는 가정 하에 학습 파이프라인부터 본다.
- 영상은 적절한 프레임 캡처 기준으로 대체하고, 영상 원본 수집은 우선 제외한다.
- Epoch별 일부 데이터 샘플링, 500개 단위 추출 전략을 검토한다.
- 사전학습 모델 위에 레이어를 쌓는 구조를 우선 검토한다.
- 학습 시 파라미터 변경, 레이어 수 변경, freezing 여부, 비교 모델까지 함께 기록한다.
- 가능하면 다다음 주까지 완료하고, 5주차에 트래킹한다.

### 2.4 동혁 (`techshin31`)

- 법률/법령/규칙 34개 조항 관련 수집 범위를 정리한다.
- 법률 판례 업무를 추가한다.
- 전체 판례에 대한 기한을 설정한다.
- 임베딩 모델은 유료 모델과 Hugging Face 모델 AB 테스트 후 결정한다.
- 성능 차이가 크지 않으면 비용/운영 관점 비교 후 선택한다.
- 유사도 스코어 기준을 조사한다.
- 테스트 시나리오를 작성한다.
- 수집 주기는 매달 1일로 두고, 중복 여부는 날짜 기준으로 본다.
- RAG 청킹 전략은 `조항 -> 1000자` 기준으로 테스트한다.
- KAG 전략은 아직 없으므로 노드/엣지 설계를 먼저 문서화한다.
- Neo4j 키워드 확장 전략과 콜백 질문 전략을 반영한다.
- 부정확한 질문은 Supervisor로 다시 돌려보내는 역질문 흐름을 고려한다.
- Neo4j 설계는 다음 주 월요일까지 업데이트 후 보고한다.
- 에이전트 구현을 빠르게 시작한다.
