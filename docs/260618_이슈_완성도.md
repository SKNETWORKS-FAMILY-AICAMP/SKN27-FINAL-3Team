## 8. 남은 리스크

- 이슈별 직접 연결 커밋이 없어 GitHub에서 자동 추적되는 작업 증거가 부족하다.
- 기능 구현 이슈는 대부분 문서/계획 단계이며, 실제 코드 또는 데이터 산출물 커밋은 아직 확인되지 않는다.
- 금요일까지 모델 확정이 아니라 후보 조사와 판단 근거 문서화가 목표임을 팀 전체가 동일하게 이해해야 한다.
- API 명세서, Agent schema, 데이터 schema가 늦어지면 다음 주 구현에서 병목이 발생할 수 있다.
- Project 보드 권한은 별도 토큰 권한이 필요할 수 있어, 현재 문서는 이슈 상태와 Git commit 기준으로만 작성했다.

## 9. 결론

현재 프로젝트는 구현 완료 단계가 아니라 WBS, 역할, 이슈, 화면설계, Supervisor/Agent 구조를 정렬하는 단계다.

문서와 이슈 관리 기준의 진척은 확인되지만, 기능 구현 커밋은 아직 거의 없으므로 다음 단계에서는 각 담당자가 금요일 전까지 input/output schema, 모델/Agent 후보, API 방향, 적용 이유를 문서화해야 한다.

커밋 관점에서는 현재 브랜치에 2개 추가 커밋이 있으며, 이 커밋들은 주로 WBS/문서/화면설계/PDF/이슈 템플릿 정리에 해당한다. 이슈 번호와 직접 연결된 커밋은 없으므로, 앞으로는 커밋 메시지에 관련 이슈 번호를 포함하는 방식이 필요하다.
