# 오늘 한 일 — 면제·감경(relief_type) 판정 정확도 개선

> 대상 코드: `ai/agents/appeal_decision_flow/{merit_gate.py, prompts.py}`
> 배경: `merit_relief_type`(면제/감경 구분) 기능을 붙인 직후, 코드 리뷰 중
> "키워드 안전장치가 문맥을 안 본다"는 지적이 나왔고, 이를 고치는 과정에서 두 번째
> 오탐까지 추가로 발견해 총 2단계로 수정했다. 상세 근거·실측 로그는
> `면제·감경 사유 merit 구분 설계.md` §7-3~§7-6 참고 — 이 문서는 "무엇이 바뀌었는지"만
> 간단히 정리한 것이다.

---

## 1. 문제 제기

기존 구현(`_downgrade_relief_type_if_hedged`)은 사유 텍스트 전체에서 "미약/약간/다소/조금/일부"
같은 정도완화 단어를 찾으면 무조건 `relief_type`을 "면제"→"감경"으로 낮췄다. 이 방식은
문맥을 안 봐서, 아래처럼 **감경 개념 자체가 없는 순수 면제형 사유**에서도 오작동했다:

- "장애인 승하차를 돕느라 **다소** 시간이 걸렸습니다" (142조5호)
- "표지판이 나뭇가지에 **일부** 가려져 있어서 몰랐습니다" (8조)
- "제 차를 도둑맞았는데 **약간** 파손된 채로 발견됐습니다" (도난, 160조4항1호)

## 2. 1차 수정 — 키워드 안전장치에 문맥 조건 추가

`merit_gate.py`에 `_CAPACITY_CONTEXT_WORDS = ("심신", "판단", "의식", "정신")`를 추가하고,
정도완화 단어와 능력-판단 문맥 단어가 **함께** 있을 때만 재보정하도록 좁혔다. 위 3개 오탐
전부 해소, 원래 목표(제10조② 케이스)는 그대로 잡히는 것을 실측 확인했다.

## 3. 2차 수정 — relief_type 판단을 별도 LLM 호출로 분리

"키워드 목록으로는 제각각인 문맥을 다 못 잡는다"는 후속 지적에 따라 아키텍처를 바꿨다.

- `prompts.py`: `MERIT_CLASSIFICATION_PROMPT`에서 `relief_type` 관련 지시를 전부 제거하고,
  `RELIEF_TYPE_CLASSIFICATION_PROMPT`를 신설.
- `merit_gate.py`: `_call_llm_relief_type()` 추가. **merit="강함"일 때만** 이 2차 호출을
  실행 (보류/낮음이면 호출 자체를 생략해 비용·지연시간 절약).
- 근거: RG가 예전에 `is_identity_related`+`category`를 한 호출에서 같이 물었다가 모순
  응답이 나와서 `category` 하나로 쪼갠 선례(ARCH-001 §11-1)와 같은 교훈 — "판단 하나당
  호출 하나"가 정확도를 높인다.

### 3-1. 분리 직후 발견한 두 번째 오탐

`RELIEF_TYPE_CLASSIFICATION_PROMPT` 초안이 "사유에 다소/약간이 있으면 감경"이라는 규칙을
**참조 조문과 무관하게 일반화**해서 적용해, 142조5호(감경 항 자체가 없음)를 또 감경으로
잘못 냈다 — 코드의 키워드 안전장치는 "심신/판단" 문맥이 없어서 개입하지 않았는데, 프롬프트
자체가 §2와 같은 실수를 반복한 것.

**최종 수정**: 프롬프트에 판단 순서를 명시했다.
1. 사유가 정확히 어느 조·항에 해당하는지 먼저 특정
2. **그 항 자체의 법률 효과만** 따름 — 사유의 정도완화 표현으로 임의 판단 금지
3. 같은 조문 안에 정도가 다른 항이 **실제로 공존하는 경우에만**(현재는 제10조뿐)
   예외적으로 정도 구분 적용

`matched_clause`(실제 해당 조·항) 필드도 추가해서 모델이 판단 근거를 먼저 특정하도록
유도했다.

## 4. 최종 검증 (실제 OpenAI API, 2회 반복 결정론적 확인)

| 사유 | 결과 |
|---|---|
| "판단능력이 **미약한** 상태였습니다" (제10조②) | ✅ `relief_type=감경` |
| "의식이 완전히 없는 상태였습니다" (제10조①) | ✅ `relief_type=면제` |
| "장애인 승하차를 돕느라 **다소** 시간이 걸렸습니다" (142조5호) | ✅ `relief_type=면제` |
| "제 차를 도둑맞았는데 **약간** 파손된 채로" (도난) | ✅ `relief_type=면제` |

## 6. 남은 한계 (별도 사안, 이번엔 안 건드림)

- 검증 중 "판단능력이 미약한 상태"류 사유가 1차 merit 호출에서 `merit="보류"`로 나온
  적이 있었다(merit="강함"이 아니면 relief_type 호출 자체가 생략됨). 감경형 사유를
  모델이 과소평가하는 경향으로 보이는데, 이건 `MERIT_CLASSIFICATION_PROMPT` 자체의
  "강함" 판정 기준 문제라 relief_type과는 별개 사안. 사용자에게 불리한 방향은 아니라
  (과대평가가 아닌 과소평가) 급하지 않다고 판단해 이번엔 안 건드렸다.
- 키워드 안전장치(`_downgrade_relief_type_if_hedged`)는 여전히 "면제→감경" 한 방향,
  제한된 문맥 단어에만 반응하는 최후 방어선이다 — 주력 판단은 2차 LLM 호출로 옮겼지만
  완전히 대체하진 않았다.
