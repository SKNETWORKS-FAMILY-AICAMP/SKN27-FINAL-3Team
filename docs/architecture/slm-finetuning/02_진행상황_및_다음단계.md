## 1. 지금까지 한 일

### 1-1. 방향 설정

- SLM/파인튜닝 개념(SLM, LoRA/QLoRA, SFT, DPO)을 먼저 학습한 뒤, 이 프로젝트(교통분쟁 AI
  서비스)의 그래프DB(Neo4j)·벡터DB(pgvector)를 파인튜닝에 활용하는 방향으로 논의를 좁혔다.
- 핵심 원칙을 확정했다: **법 지식은 계속 RAG(pgvector+Neo4j)가 담당하고, 파인튜닝은 "검색된
  근거를 가지고 어떻게 인용하고 어떻게 판단을 유보할지" 행동만 학습시킨다.** 법령은 계속
  개정되므로 조문 내용 자체를 모델 파라미터에 암기시키는 건 목적으로 삼지 않는다.
- 학습 방법은 **QLoRA 기반 SFT를 RAFT(Retrieval-Augmented Fine-Tuning) 방식으로** 적용하는
  것으로 결정. DPO는 SFT가 안정화된 이후의 **옵션(범위 밖)**으로만 남겨뒀다.
- 대상 태스크는 `law_ground_search` Agent의 **근거 인용 충실도(citation faithfulness)** — 검색된
  조문 중 정답만 인용하고 오답(distractor)은 무시하며, 근거가 약하면 단정하지 않는 행동.

### 1-2. 설계 문서 작성

`docs/architecture/slm-finetuning/01_SFT설계서.md`(SFT-ARCH-001)를 팀 컨벤션(문서번호·버전표·
미결사항 섹션 포함)에 맞춰 작성했다. 핵심 내용:

- 목표/비목표(§3): 근거 인용 정확도·포맷 준수·저신뢰도 시 한정 문구가 목표, 법 지식 암기와 DPO는
  비목표.
- 데이터 파이프라인(§4): `law_chunks`/`law_embeddings`/Neo4j 그래프 확장 관계를 소스로 사용.
- **§4-4 생성 규칙 구체화**: `storage/rag/law_query_terms.yaml`의 27개 카테고리(차종 7·위반유형
  16·처벌유형 4)를 커버리지 매트릭스로 재사용. 카테고리별 질의 템플릿, gold 선정 기준(top-1
  score ≥ 0.6), distractor 선정 규칙(오답 조문 score 0.3~0.5 구간 + Neo4j 그래프 확장 노이즈,
  감가 공식 `base_score × 0.9` 실제 코드값 재사용), 파일럿 규모(약 350건) → 1차 정식 학습셋
  (1,500~2,000건) 계획을 확정.
- 평가 설계(§7): 인용 정밀도/재현율, 포맷 준수율, 저신뢰도 문구 정확도, latency/비용 비교 지표
  정의(하네스 구현은 아직 미착수).

### 1-4. 파일럿 데이터 생성 스크립트 구현 및 검증

`etl/legal_sft/build_pilot_dataset.py` + `README.md`를 작성했다.

- **mock 모드**: DB 없이 파이프라인 구조(질의 생성 → gold/distractor 구성 → output 템플릿 →
  층화 분할)만 검증. 381건 생성, train/val/test 전 구간 27/27 카테고리 커버리지 확인.
- **real 모드**: `etl.legal.search.search_laws()` + Neo4j 그래프 확장으로 실제 데이터 사용.
  팀이 실제 환경에서 실행해 **381건 생성, 27/27 카테고리 커버리지, 저신뢰도(한정 문구) 예시
  94/381건(약 25%)** 확인 — end-to-end 검증 완료.
- 검증 과정에서 실제 버그 1건 발견·수정: distractor 선정 로직이 `article_no`로 "다른 조문"을
  판별했는데, 별표류 조문은 `article_no=None`이라 `None != None`(False)이 되어 오답을 건너뛰는
  문제가 있었다 → `chunk_id` 기준 판별로 수정, mock 모드 재검증 완료.

### 1-5. gold 오염 발견 및 수정 (100% 사람 검수 착수 직전)

100% 사람 검수를 시작하기 전 자동 스캔을 먼저 돌려 범위를 좁혔다 — 27개 카테고리의 gold
`source_name`이 `law_query_terms.yaml`의 해당 카테고리 `search_terms`(기대 법령명)와
일치하는지 대조.

- **발견**: 1차 스캔(evidence 배열 전체를 gold 여부 구분 없이 대조)에서 4개 카테고리
  (hit_and_run·bus_lane_violation·uninsured_driving·criminal_penalty, 54건)를 의심
  대상으로 잡았다. `is_gold`/`low_confidence` 플래그까지 반영한 정밀 재확인 결과, 실제로
  "확신을 갖고 틀린 법을 인용"한 건 hit_and_run·bus_lane_violation 두 카테고리(train
  기준 22건)뿐이었다 — 무관한 법("여객자동차 운수사업법 시행령" 별표5, 예:
  `"뺑소니 하면 처벌이 어떻게 돼?"` 질의의 gold가 여객운송사업자 행정처분표)을 gold로
  가리키고 있었다. uninsured_driving은 애초에 전부 저신뢰도(gold 없음)였고,
  criminal_penalty의 gold 3건은 이미 정답을 인용하고 있었다 — 둘 다 1차 스캔의 과다
  계상이었다.
- **근본 원인**: `search_laws()`가 top1 점수(≥0.6)만으로 gold를 승격시키는데, 별표5(큰
  처벌표 하나를 120개+ part 청크로 쪼갠 것)가 위반·처벌 계열 질의 다수에 애매하게 높은
  점수(0.58~0.60)로 걸린다. 실측: hit_and_run 검색 쿼리의 top-8 전부가 이 표의 조각이고,
  실제 정답 법(특정범죄가중처벌법 34개 currently-valid 청크)은 top-15 안에도 들지 못했다.
  (부수 발견: `search_laws()`가 `top_k` 요청값과 무관하게 7~8건 근처에서 결과가 잘리는
  별도 인프라 이슈가 있음 — 이번 수정 범위 밖으로 남겨둠.)
- **수정**: `etl/legal_sft/build_pilot_dataset.py`에 카테고리별 기대 법령명(이미 있는
  `search_terms` 재사용) 검증 안전장치(`_expected_law_names`/`_matches_expected_law`)를
  추가 — top1이 기대 법령과 무관하면 gold로 승격시키지 않고, top_k=15 안에서 기대 법령과
  일치하는 후보를 다시 찾아 그 후보가 점수 기준(0.6)을 넘을 때만 gold로 쓴다. 못 찾으면
  gold 없이 저신뢰도로 정직하게 처리한다.
- **검증**: 파일럿 381건 재생성 후 27개 카테고리 전부 gold mismatch 0건(자동 스캔 재확인).
  저신뢰도 비율은 94/381(25%) → 123/381(32%)로 증가했는데, 이는 회귀가 아니라 실제 오염
  건이 "확신 있게 틀린 법 인용"에서 "모른다"로 정직하게 바뀐 것이다. `storage/rag/sft_pilot/
  {train,val,test}.jsonl`을 수정본으로 교체 완료. `test/unit/test_legal_sft_build_pilot_dataset.py`
  회귀 테스트 10건 추가(전체 통과).

### 1-6. 카테고리별 사람 검수 진행 중 — 추가 발견사항 (법령명 대조로는 못 잡는 문제)

§1-5 수정본을 기준으로 카테고리별 사람 검수를 27개 카테고리 전부(대표 샘플 기준) 훑었다.
17개에서 법령명 대조만으로는 안 잡히는 문제(조문 단위 오류·표 조각·gold 없음)를 추가로
발견해 [`03_파일럿_품질검수_발견사항.md`](./03_파일럿_품질검수_발견사항.md)에 상세
정리했다 — 요약: 🔴 조문 자체가 틀리거나 폐지·공백인 카테고리 3개(32건, 가장 심각),
🟡 gold는 맞지만 별표를 텍스트로 평면화하며 표 조각이 된 카테고리 8개(92건, 그중 2개는
내용 자체도 무관), ⚪ 점수 미달로 gold가 아예 없는 카테고리 6개(66건, 무해하나 긍정
학습 신호 부재). 10개 카테고리는 문제없이 확인됨.

### 1-7. 조문 단위 문제 재탐색·수정 (§1-6 우선순위 A그룹 + B-2그룹)

§1-6에서 발견한 5개 카테고리(seatbelt_violation·freight_vehicle·bicycle·bus·taxi)를
"코퍼스에서 정답을 다시 찾아보고, 못 찾으면 저신뢰도로" 원칙으로 재검토했다.

- **seatbelt_violation**: 실제 정답(도로교통법 제50조, 좌석안전띠 규정)이 검색 결과
  안에 있었지만 점수(0.5891)가 GOLD_MIN_SCORE(0.6)를 근소하게 못 넘었고, 대신 무관한
  조문(제32조, 안전모 규정 — 점수 0.6074로 임계값을 넘김)이 gold로 잘못 승격돼 있었다.
- **freight_vehicle**: gold였던 제47조가 2015년에 삭제된 조문(본문이 "삭제 <2015.6.22>"
  뿐)이었다. 대체 검색(여러 질의 표현 시도)에도 화물자동차 운수사업법·도로법 인근에
  쓸만한 대체 조문을 찾지 못함 — 해당 법 영역 자체가 삭제된 조문이 많은 것으로 보임.
- **bicycle**: gold였던 제9조가 본문 없이 조문번호만 남은 빈 청크였다 — 자전거법 관련
  조문 다수가 삭제되거나 비어있었고, 유일하게 쓸만한 후보는 "제1조(목적)" 조항이었다.
- **bus·taxi**: gold였던 내용이 사업 인허가 신청서 서식(체크리스트에 우연히 "버스"
  같은 키워드가 섞여 있었음)이었다. bus는 대체 조문을 못 찾음, taxi는 "제52조(운전자격
  시험)"를 찾았으나 사고·처벌 질의에 완벽히 들어맞진 않는 절충안이다.

`etl/legal_sft/build_pilot_dataset.py`에 두 안전장치를 추가했다:

- `_has_valid_content(item)` — 조문 전체가 삭제됐거나("제N조 삭제 <날짜>" 패턴, 항 일부만
  삭제된 경우는 오탐 방지를 위해 제외), 본문이 10자 미만으로 사실상 비어있거나, 별표
  번호 없는 표 조각(서식 등 행정 문서로 추정)이면 gold 후보에서 제외한다.
- `_is_trustworthy(item)` — 별표(appendix_no 있음)는 점수·법령명만으로 신뢰한다(표는
  위반유형을 코드·번호로 표기해 카테고리 키워드가 문자 그대로 안 나오는 게 정상 —
  signal_violation의 정답인 별표8이 실제로 그렇다). 일반 조문(appendix_no 없음)은
  카테고리 키워드(user_terms)가 본문에 실제로 등장해야 신뢰한다.

**결과**: 재생성·재검증 후 27개 카테고리 전부 gold mismatch 0건 유지. seatbelt_violation·
freight_vehicle·bus는 코퍼스에 신뢰할 만한 대체 조문이 없어 정직하게 저신뢰도로 전환됐고
(확신 있는 오답보다 안전 — §1-5부터 이어온 원칙과 동일), bicycle·taxi는 더 나은 조문을
찾아 gold로 승격했다(다만 taxi는 완벽한 매치는 아니라는 한계가 있음, 아래 §2-3 참고).
저신뢰도 비율 123→180/381건. `test/unit/test_legal_sft_build_pilot_dataset.py`에 회귀
테스트 16건 추가(총 26개, 전체 통과). `storage/rag/sft_pilot/{train,val,test}.jsonl`을
이 수정본으로 교체 완료.

### 1-8. 평가 하네스 구현 (§7)

`ai/evaluation/`에 §7의 4개 절대 지표(인용 정밀도·재현율·포맷 준수율·저신뢰도 문구 정확도)
채점 로직을 구현했다 — `citation_metrics.py`(채점 함수), `latency_cost.py`(참고 가격표
기반 비용 추정 + latency 타이머), `run_eval.py`(CLI). `python -m ai.evaluation.run_eval
--self-check`로 `test.jsonl`(27건) gold를 그대로 채점해 하네스 정합성을 자가 검증했다 —
전 지표 만점, gold가 없는(저신뢰도) 카테고리는 정밀도·재현율이 정확히 N/A로 구분됨. 합성
오답 예측으로 `--predictions` 경로(실제 모델 채점용)도 확인했다. 단위 테스트 23건 추가
(`build_output_text()`와의 저신뢰도 문구 교차 검증 포함), 저장소 전체 296 passed.

이 하네스는 §7-1이 제안한 "QLoRA 착수 전 게이트"(gpt-4o-mini/GPT-4o 프롬프트 전용

### 1-12. 파일럿 레코드 전수 검수 착수 직후 회귀 발견·수정 (2026-07-14)

§2-1 항목1(파일럿 레코드 전수 검수)을 시작하자마자, 재생성된 데이터의 카테고리별 gold 유무가
전날 문서화된 상태와 어긋나는 걸 발견했다(`bus`·`hit_and_run`·`special_vehicle`·
`bus_lane_violation`이 전부 뒤집혀 있었음). `search_laws()`를 반복 호출해 점수 자체는
안정적임을 먼저 확인한 뒤(§8-9 "실행 간 결과 변동"은 재현 안 됨), `bus`의 gold를 직접
열어보니 **B-2에서 이미 수정 완료 처리했던 문제(사업 인허가 신청서 조각이 gold로 승격)가
재발**해 있었다.

원인: §1-11의 `clean_ascii_table`이 `search_laws()` 안에서 박스 드로잉 문자를 조회
시점에 미리 `" | "`로 치환해버리는데, `build_pilot_dataset.py::_looks_like_table_fragment()`
는 원본 박스 문자 개수로 표/서식 조각을 판별하는 함수라 — 문자가 이미 치환된 뒤엔 그 개수를
셀 수 없어 조용히 무력화됐다. **§1-11 자체가 만든 회귀**였다. `clean_ascii_table`이 남기는
파이프(`|`) 구분자 개수를 표 조각 신호로 추가해 수정했고(`_PIPE_SEPARATOR_THRESHOLD=2`,
회귀 테스트 2건 추가), 재검증 결과 `bus`는 저신뢰도로 재전환, `taxi`(같은 클래스 문제)는
서식이 아닌 실제 프로즈 조문(개인택시운송사업 대리운전 허용 요건)으로 재배정됐다 — 다만
"사고·처벌" 질의 대비 "사업면허" 성격이라 완벽한 매치는 아니다(의미적 관련성 문제, 구조적
결함 아님 — 범위 밖).

이 사례는 레코드 전수 검수가 왜 필요한지를 바로 증명했다 — 자동 안전장치(`_has_valid_content`/
`_is_trustworthy`)가 있어도 그 안전장치 자체가 조용히 깨질 수 있다.

### 1-13. 파일럿 레코드 전수 검수 — 카테고리별 대표 gold 훑기 결과 (2026-07-14)

수정 반영본(`storage/rag/sft_pilot_cleaned_check/`)의 27개 카테고리 대표 gold를 질의와
대조해 전수 확인했다.

- **정상 확인(12개)**: `dangerous_driving`·`demerit_points`·`drunk_driving`·`fine_notice`·
  `helmet_not_worn`·`intersection_passage_violation`·`license_suspension_or_revocation`·
  `mobile_phone_driving`·`parking_violation`·`school_zone_violation`·`signal_violation`·
  `traffic_accident` — gold가 질의와 실제로 합치.
- **이미 알려진 절충안(새 문제 아님, 3개)**: `bicycle`·`taxi`(완벽한 매치는 아니나 실질
  내용 있는 조문 — 기존 문서에 이미 절충안으로 기록), `criminal_penalty`(gold 3/15만
  있고 나머지는 정직한 저신뢰도, 기존 §7-1 분석 참고).
- **§8-9("실행 간 결과 변동") 실측 재확인(3개)**: `hit_and_run`·`special_vehicle`·
  `bus_lane_violation`이 이번 재생성에서 gold 0건으로 나왔다 — 이 세 카테고리는 문서상
  정상이어야 하는데, 확인해보니 top1 점수가 0.60~0.63 사이로 `GOLD_MIN_SCORE`(0.6) 바로
  근처에 몰려 있었다. `search_laws()`를 같은 프로세스 안에서 반복 호출했을 때는 점수가
  완전히 안정적이었으므로(§1-12에서 확인), 이건 **서로 다른 프로세스 실행 사이**에서
  OpenAI 임베딩 API 결과가 소수점 4자리 수준으로 미세하게 달라지는 현상으로 보인다 — 새
  버그가 아니라 §8-9의 실측 재확인이다. 임계값 바로 위/아래를 걸치는 카테고리는 재생성할
  때마다 gold 유무가 뒤집힐 수 있다는 뜻이라, §8-9를 실제로 해결하기 전까지는 이 세
  카테고리의 상태를 어느 한 시점 스냅샷으로 확정 짓지 않는 게 맞다.
- **나머지(저신뢰도, 11개)**: `bus`(§1-12에서 재전환)·`freight_vehicle`·`motorcycle`·
  `night_light_violation`·`personal_mobility`·`seatbelt_violation`·`speeding`·
  `uninsured_driving`·`unlicensed_driving` 등 — 기존에 문서화된 A그룹/C그룹 상태와 일치.

**결론**: 레코드 전수 검수에서 카테고리 대표 샘플 기준 "명백히 틀린" gold는 §1-12에서 발견한
bus/taxi 회귀가 유일했고, 그 외엔 이미 알려진 상태(절충안·§8-9 변동성·A/C그룹)와 일치했다.

이어서 질의별 세부 변형(같은 카테고리 안 12~15건 각각)까지 확인한 결과, 카테고리 안에서는
gold 조문이 하나로 고정돼 모든 질의에 재사용되는 구조임을 확인했고(§4-4 참고), 그 재사용
과정에서 **새 결함**을 발견했다 — `dangerous_driving`·`drunk_driving`·`helmet_not_worn`
3개 카테고리는 gold가 카테고리 주제와는 맞지만 "벌점 몇 점"·"과태료 얼마" 질의가 요구하는
구체 수치를 담고 있지 않은 일반 금지행위 조문이다(실제 수치는 별도 별표에 있음). 반면
`demerit_points`·`fine_notice`·`intersection_passage_violation`·`mobile_phone_driving`·
`parking_violation`·`school_zone_violation`·`signal_violation`은 gold 자체가 수치표라
문제없다. `03_파일럿_품질검수_발견사항.md` 🟠 D그룹으로 신규 기록 — 문서화만 하고 코드
수정은 후속 과제로 남기기로 함(질의 템플릿별 gold 필터링 또는 `build_output_text()`
evidence 합성 재설계 중 택일 필요, §2-3 참고).

### 1-14. D그룹 해결 (2026-07-14)

§1-13에서 발견한 D그룹(gold는 주제만 맞고 질의가 요구하는 벌점/과태료 수치가 없는 문제)을
실제로 고쳤다. 먼저 검색어에 "벌점"/"과태료 범칙금" 키워드를 추가하는 실험을 해봤으나
카테고리·질의 유형별로 성공/실패가 갈리고(`dangerous_driving`·`helmet_not_worn`은
"+과태료"만 성공, "+벌점"은 정답 표로 이동해도 점수가 임계값 미달로 떨어짐,
`drunk_driving`은 아예 안 움직임) 일관된 해법이 아니라고 결론지었다.

이어서 SQL로 직접 벌점표(별표28)를 조사한 결과, `dangerous_driving`(난폭운전 구속 시
면허취소 기준)·`drunk_driving`(혈중알코올농도별 단계적 취소·정지 기준)은 애초에 "벌점 몇
점"이라는 단순 질문에 조문 하나로 깔끔하게 답할 수 있는 구조가 아님을 확인했다 — 법 자체가
조건별로 갈리는 것이라, 검색을 아무리 고쳐도 없는 답을 찾아낼 수 없다.

그래서 방향을 바꿔 **검색이 아니라 gold 승격 조건**에 질의-인식 체크를 추가했다 — 질의가
"벌점"/"과태료"를 묻는데(`_query_asks_for_penalty_number`) 후보 조문 본문에 숫자+단위
패턴(`\d+\s*점`, `\d+\s*(?:만\s*)?원`, `_has_penalty_number`)이 없으면 그 후보를 이 질의에
한해 신뢰하지 않는다. 검색 자체(`search_terms`)는 안 건드리므로 일반화된 규칙이고, "처벌이
어떻게 돼?"류 일반 질의는 영향받지 않는다(`etl/legal_sft/build_pilot_dataset.py`, 단위
테스트 8건 추가).

파일럿 재생성으로 검증한 결과, 원래 발견한 3개 카테고리가 정직하게 저신뢰도로 전환됐을 뿐
아니라, **이 필터가 §1-13 사람 검수에서 놓쳤던 2개 카테고리(`mobile_phone_driving`·
`traffic_accident`)도 추가로 잡아냈다** — `traffic_accident`는 §1-13에서 "정상"으로
잘못 분류돼 있었는데(gold가 "교통사고처리 특례법 제1조(목적)"로 수치 없는 텍스트였음),
자동 필터가 이를 정확히 재발견했다. 최종적으로 5개 카테고리가 D그룹 패턴이었다.

### 1-15. 1차 정식 학습셋 확장 완료 (2026-07-14)

§2-2 항목3(1차 정식 학습셋, 1,500~2,000건)을 실행했다.

**구현**:
- **검색 캐시**: `real_evidence()`가 카테고리당 매번 동일한 검색어(`search_terms`)로
  OpenAI 임베딩 API를 반복 호출하던 낭비를 발견 — `_cached_search_laws()`로 캐시해
  카테고리당 실제 호출을 1회로 줄임(381건 규모에서 실측: 381회 → 27회). paraphrase로
  질의 수가 늘어날수록 이 캐시의 절감 효과가 커진다.
- **Paraphrase 증강**: `generate_paraphrases()` 신설 — 카테고리당 1회 배치 채팅 API
  호출(gpt-4o-mini)로 기존 질의 전부의 paraphrase를 한 번에 생성. 최초 구현은 응답
  JSON의 키로 원본 질의 문자열을 그대로 요구했는데, GPT가 echo하며 공백을 미세하게
  바꾸는 경우가 있어 27개 카테고리 중 5개가 조용히 증강 0건 처리되는 회귀가 있었다 —
  문자열 키 대신 번호(인덱스) 매핑으로 교체해 해결. `etl/legal_sft/build_pilot_dataset.py`
  에 `--paraphrase-factor`/`--paraphrase-model` CLI 옵션 추가, 단위 테스트 9건 추가.

**실행 결과**: `--paraphrase-factor 5`로 카테고리당 질의를 5배 증강 —
**1,905건 생성**(train 1,524 / val 200 / test 181, 80/10/10 층화 분할), **27/27 카테고리
커버리지**(전 구간), 고유 질의 1,880/1,905(중복률 1.3%). D그룹 5개 카테고리 필터가 확장
규모에서도 정확히 동작함을 재확인(벌점/과태료 질의의 gold 오염 0건). **실측 비용
$0.0188**(사전 추정 수십 센트~1달러보다 훨씬 저렴 — 배치 호출 + 검색 캐시 덕분).
결과물: `storage/rag/sft_pilot_v1/{train,val,test}.jsonl`.
