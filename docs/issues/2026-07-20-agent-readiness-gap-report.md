# Agent Implementation Gap Report (OCR & Appeal Decision)
**작성일**: 2026-07-20
**관련 작업자**: kama42
**관련 체크리스트**: `docs/ops/project-readiness-master-checklist.md`

## 개요
이 문서는 과태료 OCR 에이전트와 이의신청 판단 에이전트(Appeal Decision Flow)의 구현 내역을 마스터 체크리스트와 비교하여, 기능 구현 외에 프로덕션 수준의 완성도를 위해 보완해야 할 **미비점(Gap)**을 정리한 문서입니다. 리포트 생성(Objection Report Generation) 관련 항목은 제외되었습니다.

---

## 1. 과태료 OCR 관련 (체크리스트 D-1)
에이전트 런타임 안정화(예: 손상된 PDF 및 invalid base64 예외 처리)는 완료되었으나, 실제 서비스 투입을 위한 품질 검증 및 UX 방어 로직이 누락되어 있습니다.

### 미비 항목 (To-Do)
- [ ] **OCR 모델 선정 근거 지표화**: 현재 사용 중인 OCR 모델의 비용, 성능, 속도 비교 지표 문서화.
- [ ] **악조건 문서 평가 세트 구축**: 기관 양식, 저해상도, 촬영 각도 틀어짐, 구겨지거나 흐려진 실제 현장 사진 등 테스트용 Ground Truth 데이터셋 마련.
- [ ] **문서 유형별 정확도 측정**: 위 평가 세트를 기반으로 필드 추출률(정확도)을 수치화하여 기록.
- [ ] **저신뢰도 시 UX 대처 흐름 (Human-in-the-loop)**: OCR 신뢰도가 낮을 경우 즉시 실패(failed) 처리하기 전, 사용자에게 재촬영을 요구하거나 직접 입력을 유도하는 프론트엔드 연동 흐름.
- [ ] **중요 필드 사용자 확인**: 금액, 기한, 처분 번호 등 치명적인 필드는 판단 로직으로 넘어가기 전 사용자에게 한 번 더 맞는지 승인받는 절차.

## 2. 이의신청 판단 에이전트 및 데이터 검증 (체크리스트 C-2, B)
하드코딩 제거 및 법령 변경 탐지 로직(`reference_drift_check.py`) 등 백엔드/데이터 정합성 기능은 훌륭하게 구현되었으나, 이 결과가 파이프라인 및 실제 사용자 안내(UX)로 연결되는 부분이 비어 있습니다.

### 미비 항목 (To-Do)
- [ ] **법령 최신성 메타데이터 저장 체계**: CLI 툴로 만들어진 법령 변경점 탐지 로직의 결과를 실제 Vector DB나 서비스 DB의 메타데이터(마지막 검증일 등)로 상시 기록하는 파이프라인 구축.
- [ ] **오래된 법령 기반 판단 시 경고 노출**: 160조 결함 등 드리프트가 발생한 상태이거나 데이터가 오래된 경우, 판단 결과 화면에 "과거 법령 기준일 수 있음"을 경고하는 로직 추가.
- [ ] **판단 불가 사례의 표준화된 안내**: 정보 부족 등으로 에이전트가 `merit_gate`나 `verdict`에서 판단 불가 판정을 냈을 때, 사용자에게 명확한 다음 행동(Next Action)을 안내하도록 프롬프트 및 정책 표준화.
- [ ] **긴급 기한 강조 로직**: 제출 기한이 임박한 경우 판단 결과 상단에 이를 최우선으로 강조하여 보여주는 명시적 처리.

## 향후 권장 액션
1. **평가 체계(Evaluation)**: OCR 악조건 테스트셋을 구축하여 객관적인 정확도 지표를 확보합니다.
2. **에지 케이스 방어(Edge Case UX)**: OCR 인식률 저하 또는 판단 불가 시, 시스템 에러로 처리하지 않고 자연스럽게 사용자에게 되묻는(역질문) 상태(State)를 설계합니다.
