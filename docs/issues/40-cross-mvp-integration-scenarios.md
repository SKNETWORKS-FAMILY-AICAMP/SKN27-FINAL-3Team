| 항목 | 내용 |

| 작성일 | 2026-06-19 |

## 1. 목적

홈/챗봇 화면, Agent 결과 schema, Supervisor 라우팅, 고지서 OCR, 감경 판단, 법령 근거 metadata, 과실비율 ML, 영상·이미지 분석 결과, 이의신청서 생성 흐름이 하나의 MVP 사용자 여정으로 연결되는지 검증한다.

현재 단계에서는 실제 API와 모델이 확정되지 않았으므로 자동 E2E 테스트가 아니라 통합 시나리오와 검증 기준을 먼저 정의한다.

## 2. 공통 검증 원칙

| 원칙 | 설명 |
|---|---|
| 확정 전 표현 금지 | 모델, API, Agent 호출 순서는 실험 전 `검증 필요`로 표시 |
| 근거와 한계 동시 표시 | Supervisor 최종 답변은 `evidence`와 `limitations`를 함께 보여야 함 |
| 법률 단정 금지 | 법령 근거가 있어도 최종 법률 판단처럼 표현하지 않음 |
| 과실비율 수치 단정 금지 | 정성 라벨과 유사 사례 중심으로 표시 |
| 추가 질문 우선 | 필수 입력이 부족하면 잘못된 답변보다 추가 질문을 생성 |
| 법률 근거 항상 호출 | 고지서 흐름에서는 법률 근거 호출 여부를 나누지 않고, `law_code` exact 입력 또는 `violation_text` semantic 입력으로만 분기 |

| `INT-006` | 법령 근거만 질문 | 법률 근거 검색 노드 → Supervisor | 관련 법령 후보, 적용 한계, 다음 확인 사항 | 검증 필요 |

## 4. 시나리오별 상세 기준

### 4.1 `INT-001` 고지서 업로드 분석

| 항목 | 기준 |
|---|---|
| 입력 | 고지서 이미지 또는 PDF |
| 필수 추출 | 위반 일시, 장소, 유형, 통지일, 납부기한, 관할 기관 |
| 호출 순서 | 고지서 OCR·과태료/범칙금 분석 노드(필주 `law_search_node` 항상 호출, 감경 판단 포함) → Supervisor |
| 법률 근거 입력 방식 | `law_code`가 있으면 조문 기반 exact 입력, `law_code`가 없고 `violation_text`가 있으면 자연어 기반 semantic 입력 |
| 통과 기준 | `summary`, `structured_result`, `evidence`, `next_actions`, `limitations`가 모두 존재 |
| 실패 처리 | OCR 실패 시 재업로드 또는 OCR 텍스트 직접 입력 요청 |
| 남은 검증 | 샘플 고지서 5~6개 결과 필요 |

### 4.2 `INT-002` OCR 텍스트 부족 필드 보완

| 항목 | 기준 |
|---|---|
| 입력 | OCR 텍스트 직접 입력 |
| 필수 분기 | 필수 필드 누락 시 추가 질문 |
| 호출 순서 | 고지서 OCR·과태료/범칙금 분석 노드 → 추가 질문 → Supervisor |
| 통과 기준 | 누락 필드명이 `missing_inputs` 또는 `limitations`에 표시 |
| 실패 처리 | 위반 유형이 없으면 추가 질문으로 보완한 뒤 `violation_text` semantic 입력으로 법률 근거 호출 |
| 남은 검증 | OCR 텍스트 품질별 샘플 필요 |

### 4.3 `INT-003` 사고 설명 기반 과실비율 흐름

| 항목 | 기준 |
|---|---|
| 입력 | 사고 경위 텍스트 |
| 호출 순서 | 텍스트 ML/판례·사례 검색 노드 → Supervisor |
| 통과 기준 | 사고 유형 후보, 쟁점 태그, 유사 사례가 반환됨 |
| 금지 | 과실비율 수치 확정 |
| 남은 검증 | 판례/자막/심의사례 데이터 수집 결과 필요 |

### 4.4 `INT-004` 영상/이미지 분석 흐름

| 항목 | 기준 |
|---|---|
| 입력 | 사고 사진, 차량 이미지, 블랙박스 영상 |
| 호출 순서 | 영상·이미지 분석 노드 → 텍스트 ML/판례·사례 검색 노드 → Supervisor |
| 통과 기준 | key frame 또는 scene summary가 텍스트 근거로 병합 |
| 실패 처리 | 품질 낮음, 프레임 누락, 객체 탐지 실패를 limitations에 표시 |
| 남은 검증 | 영상·이미지 분석 POC 샘플 필요 |

### 4.5 `INT-005` 이의신청서 초안 생성

| 항목 | 기준 |
|---|---|
| 입력 | 고지서 OCR·과태료/범칙금 분석 결과, 법률 근거 결과, 필주 감경 판단 결과, 사용자 사실관계 |
| 호출 순서 | 고지서 OCR·과태료/범칙금 분석 노드(법률 근거 항상 호출, 필주 감경 판단 포함) → 이의신청서 생성/리포트 노드 → Supervisor |
| 통과 기준 | 수신 기관, 사건 정보, 사실관계, 이의신청 취지, 근거, 첨부 증거, 면책 문구 포함 |
| 실패 처리 | 사용자 사실관계 부족 시 초안 생성 대신 추가 질문 |
| 남은 검증 | 초안 문구 guardrail 필요 |

### 4.6 `INT-006` 법령 근거 질문

| 항목 | 기준 |
|---|---|
| 입력 | 법령 근거 질문 |
| 호출 순서 | 법률 근거 검색 노드 → Supervisor |
| 통과 기준 | 법령 후보, 조문 metadata, 적용 한계 표시 |
| 실패 처리 | 검색 근거 부족 시 “추가 확인 필요” 표시 |
| 남은 검증 | 법률 데이터 source와 metadata 필요 |
