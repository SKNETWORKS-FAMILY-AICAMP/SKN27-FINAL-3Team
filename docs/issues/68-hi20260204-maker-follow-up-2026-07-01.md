## 2026-07-01 chat-first screen update

User flow decision:

- Do not force login at entry.
- Open the chat first as a guest session because accident or fine users may be too stressed to complete account steps before getting help.
- After the first meaningful chat response, ask whether the user wants to save the conversation.
- If the user chooses save, connect the current guest session to Google login and route the user to My Page history.
- If the user chooses not to save, keep the conversation as a temporary session and do not treat it as My Page history.

  - Save after login now fetches My Page summary with the newly issued token and opens My Page.
- Updated `app/web/styles.css`.

  - Added save choice panel styles and mobile layout handling.

## 2026-07-01 Supervisor LLM API/model 결정

결정:

- 1차 실서비스 전환에서는 Supervisor LLM provider를 `openai`로 둔다.
- 기본 모델은 `gpt-5.4-mini`로 둔다.
  - 이유: Supervisor의 핵심 역할은 자유 대화를 읽고 `supervisor_conversation.v1`, `agent_input_schema.v1`, `reporting_payload.v1` 형태의 구조화 JSON을 안정적으로 만드는 것이다.
  - 이 단계에서는 긴 리포트 문장 생성보다 대화 분류, 사실관계 추출, 역질문 생성, Agent input schema 생성이 중요하므로 저지연/저비용 모델을 우선한다.
- Gemma는 지금 바로 기본값으로 쓰지 않고, 추후 `SUPERVISOR_LLM_PROVIDER=openai_compatible`와 `SUPERVISOR_LLM_BASE_URL`을 통해 OpenAI-compatible endpoint로 갈아끼울 후보로 남긴다.
  - 이유: Gemma는 비용/자체호스팅/온프레미스 측면에서 장점이 있지만, 현재 #68의 병목은 모델 호스팅보다 API contract와 화면 리포팅까지 이어지는 end-to-end 안정성이다.

필요 API/env:

- `OPENAI_API_KEY`: OpenAI API 키. 로컬 `.env`에만 넣고 커밋하지 않는다.
- `SUPERVISOR_LLM_ENABLED=1`: 실제 API 호출을 켠다. 기본값은 `0`이다.
- `SUPERVISOR_LLM_PROVIDER=openai`: 현재 기본 provider. OpenAI-compatible Gemma serving을 붙일 때는 `openai_compatible`을 쓴다.
- `SUPERVISOR_LLM_MODEL=gpt-5.4-mini`: Supervisor 기본 모델.
- `SUPERVISOR_LLM_API_KEY`: 별도 키를 쓰고 싶을 때만 설정한다. 비워두면 `OPENAI_API_KEY`를 사용한다.
- `SUPERVISOR_LLM_BASE_URL`: OpenAI-compatible endpoint를 붙일 때 사용한다. 기본 OpenAI API는 비워둔다.
- `SUPERVISOR_LLM_TEMPERATURE=0.1`: 구조화 출력 안정성을 위해 낮게 둔다.
- `SUPERVISOR_LLM_TIMEOUT_SECONDS=12`: 채팅 응답이 오래 묶이지 않도록 timeout을 둔다.

구현 정책:

- API 키나 SDK가 없거나, 호출 실패/계약 검증 실패가 발생하면 기존 rule-based Supervisor 결과로 fallback한다.
- LLM이 Agent owner를 잘못 반환해도 기존 fallback의 `node_code -> owner`를 기준으로 병합한다.
- 알 수 없는 Agent node는 버리고, 기존 Agent 구현 파일은 건드리지 않는다.
- 이 작업은 `app/services/supervisor_llm_service.py`, Supervisor mock 연결부, 설정/env 문서만 다룬다.

## 2026-07-01 Redis/PostgreSQL Docker 연결 수정

문제:

- 로컬에서 떠 있던 것은 Python `runserver` 백엔드와 Vite 프론트였고, Docker compose의 Redis/PostgreSQL은 떠 있지 않았다.
- Docker compose에는 frontend 컨테이너만 실행 중이었다.
- PostgreSQL 기본 이미지가 `pgvector/pgvector:16-pgvector`로 되어 있었는데, 해당 태그가 없어 `docker compose up -d redis postgres`가 실패했다.
- Django settings는 SQLite 고정이라 PostgreSQL 컨테이너가 떠도 백엔드가 사용하지 못하는 상태였다.

수정:

- PostgreSQL 이미지를 `pgvector/pgvector:pg16`으로 수정했다.
- `docker compose up -d redis postgres`로 Redis/PostgreSQL 컨테이너를 시작했다.
- Django settings에 `DJANGO_DATABASE_ENGINE=postgres` 스위치를 추가했다.
- Docker backend 환경변수에 PostgreSQL 접속 정보를 연결했다.
- Redis는 `REDIS_URL`이 있으면 Django cache backend로 사용하고, 없으면 기존처럼 `LocMemCache` fallback을 유지한다.
