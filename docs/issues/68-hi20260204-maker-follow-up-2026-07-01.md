## 2026-07-01 chat-first screen update

User flow decision:

- Do not force login at entry.
- Open the chat first as a guest session because accident or fine users may be too stressed to complete account steps before getting help.
- After the first meaningful chat response, ask whether the user wants to save the conversation.
- If the user chooses save, connect the current guest session to Google login and route the user to My Page history.
- If the user chooses not to save, keep the conversation as a temporary session and do not treat it as My Page history.

Local implementation:

- Updated `app/web/FrontendAppShell.jsx`.
  - Entry route now uses `EntryScreenV2` with chat-first copy.
  - Chat route now uses `ChatScreenV2` with a save-or-temporary decision panel.
  - Message submit now keeps the active guest identity when a session is bootstrapped immediately before submit.
  - Save after login now fetches My Page summary with the newly issued token and opens My Page.
- Updated `app/web/styles.css`.
  - Added entry flow panel styles.
  - Added save choice panel styles and mobile layout handling.

Agent connection status on `origin/dev`:

- Active backend/app routes still execute the mock envelope path through `agent_node_service`, `analysis_job_mock_service`, and canonical chatbot views.
- Vision and fault-ratio related work appears on unmerged remote branches, not connected to `origin/dev`.
- No non-`hi20260204-maker` Agent implementation was changed.

## 2026-07-01 Docker/screen follow-up

Root cause:

- The running screen was started with local Vite, not Docker, so it did not appear in `docker ps`.
- `docker-compose.yml` had `redis` and `depends_on` under `volumes`, making `docker compose config` fail.
- `docker-compose.yml` also had no frontend service, so Docker could not expose the React screen.
- The in-app browser showed a blank page on the dev server, while the production preview build rendered correctly.

Local implementation:

- Fixed `docker-compose.yml` structure.
  - Moved `redis` under `services`.
  - Added backend `depends_on: redis`.
  - Added a `frontend` service on port `5173`.
  - Added `FRONTEND_PORT` override support to avoid conflicts with a local preview server.
  - Kept frontend independently runnable so screen-only Docker checks do not require backend build first.
  - Added `frontend_node_modules` volume.
- Updated `app/web/vite.config.js`.
  - Added `VITE_API_PROXY_TARGET`.
  - Local default remains `http://127.0.0.1:8000`.
  - Docker frontend uses `http://backend:8000`.

Verification:
