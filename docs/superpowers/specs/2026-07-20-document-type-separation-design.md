# 이의신청·사실관계·보험사 제출 문서 유형 분리 설계

## 결정

분석 리포트 안에 다음 세 종류의 **화면·복사용 문서 카드**를 추가한다.

- `objection_draft`: 이의신청서 초안
- `fact_summary`: 사실관계 정리
- `insurance_submission`: 보험사 제출용 요약

공식 제출 양식인 `objection_form`만 기존의 최종 확인과 appeal gate를 통과한 뒤 DOCX로 내려받을 수 있다. 새 카드에는 다운로드 API, PDF, 별도 파일 저장을 추가하지 않는다.

이 결정은 일반 분석 리포트를 화면에서 열람·저장한다는 #241 정책과, 체크리스트의 문서 종류 분리 요구를 함께 만족한다.

## 범위와 비범위

포함:

- Supervisor 리포팅 결과와 worker 영속화 경로 모두에서 같은 세 카드 구조를 만든다.
- 카드마다 목적, 준비 상태, 표시할 섹션, 복사할 텍스트, 주의사항을 제공한다.
- 기존 `sections`에 이미 있는 안전한 텍스트만 재구성한다.
- 프런트엔드 리포트 작업대에서 카드를 구분해 표시하고, 준비된 카드만 클립보드로 복사한다.
- 더 이상 허용되지 않는 일반 `download_report` 액션을 새 결과에서 만들지 않는다.
- #242 병합 사실을 반영해 최종 확인 체크리스트 항목을 완료 처리한다.

제외:

- 보험 약관 해석, 보험금·합의금·과실 비율 확정, 보험사 RAG를 추가하지 않는다.
- 새 문서 다운로드, PDF 렌더링, 새 저장소·DB 모델·마이그레이션을 추가하지 않는다.
- 차단된 appeal gate를 우회해 이의신청서 초안을 제출 가능한 문서처럼 만들지 않는다.

## 공개 계약

`ReportReportingPayload`와 `PUBLIC_REPORTING_PAYLOAD_KEYS`에 선택 필드 `document_cards`를 추가한다. 기존 리포트와 기존 소비자는 이 필드가 없거나 빈 배열이어도 정상 동작해야 한다.

각 카드의 공개 구조는 다음과 같다.

```json
{
  "type": "fact_summary",
  "title": "사실관계 정리",
  "description": "확인된 사실과 추가 확인이 필요한 내용을 구분해 정리합니다.",
  "status": "ready",
  "sections": [
    {"title": "2. 사실관계", "body": "...", "items": []}
  ],
  "copy_text": "사실관계 정리\n\n2. 사실관계\n...",
  "notice": "확인되지 않은 내용은 제출 전에 보완해 주세요."
}
```

- `type`은 `objection_draft`, `fact_summary`, `insurance_submission` 중 하나다.
- `status`는 `ready`, `partial`, `unavailable` 중 하나다.
- `sections`, `copy_text`, `notice`는 선택 필드이며, `unavailable` 카드에는 제출 가능한 본문이나 복사 텍스트를 넣지 않는다.
- 카드의 `sections`와 `copy_text`는 기존 공개 `sections`에서만 만들고, 비공개 `form_data`, 내부 사용자 식별자, 지문, 원본 첨부파일 값은 새로 노출하지 않는다.

## 카드 생성 규칙

공통 순수 매퍼가 `document_variant`, `sections`, `document_readiness`, `appeal_gate`를 입력으로 받아 두 리포트 생성 경로에서 같은 카드를 만든다.

| 카드 | 소스 섹션 | 상태 규칙 | 사용자 행동 |
| --- | --- | --- | --- |
| 이의신청서 초안 | 신청 취지·사유·법령·첨부자료 섹션 | 공식 이의신청 대상이고 appeal gate가 열려 있으면 `ready` 또는 자료 부족 시 `partial`; 그 외 `unavailable` | 본문 복사, 공식 DOCX는 기존 최종 확인 뒤 별도 버튼으로만 다운로드 |
| 사실관계 정리 | 사실관계·사고 경위·사건 개요 섹션 | 표시 가능한 섹션이 있으면 `ready`, 일부만 있으면 `partial` | 본문 복사 |
| 보험사 제출용 요약 | 사실관계와 근거·첨부자료·다음 확인 섹션 | 표시 가능한 자료가 있으면 `ready` 또는 `partial` | 본문 복사; 보험금·합의금·과실 확정 문서가 아니라는 주의 표시 |

섹션 제목이 충분히 일치하지 않는 기존/부분 리포트는 카드를 억지로 채우지 않는다. 해당 카드는 `partial` 또는 `unavailable`로 표시하고, 기존 리포트 섹션 화면은 그대로 유지한다.

## UI와 동작

`ReportingScreen`에 `DocumentTypeCards` 영역을 추가한다.

- 세 카드는 목적·상태·주의사항을 서로 다른 제목으로 표시한다.
- `copy_text`가 있는 카드만 “내용 복사” 버튼을 노출한다.
- 복사 실패는 현재 리포트 액션 상태 영역에 사용자 친화적으로 표시한다.
- 공식 DOCX 버튼, 네 가지 최종 확인 패널, appeal gate 차단 규칙은 변경하지 않는다.
- 리포트 상세에 `document_cards`가 없는 과거 데이터는 카드 영역을 숨기고 기존 섹션 UI만 보여 준다.

## 생성·저장 흐름

1. 이의신청서 생성 Agent가 기존처럼 `form_sections`, 준비도, appeal gate를 만든다.
2. Supervisor 동기 경로와 worker 경로가 같은 카드 매퍼를 호출해 `reporting_payload.document_cards`를 채운다.
3. 저장소는 기존 민감 정보 정제 흐름을 지난 카드만 저장한다.
4. 리포트 상세 DTO는 카드 필드를 호환성 있게 투영한다.
5. 화면은 카드를 읽어 표시·복사만 하고 다운로드 요청을 만들지 않는다.

## 오류·호환성·보안

- 일반 `download_report` 액션은 생성 단계에서 제거한다. 기존 클라이언트가 이를 보내더라도 #242의 서버 `409 document_download_not_available` 계약은 유지한다.
- appeal gate가 차단되면 이의신청서 초안 카드는 `unavailable`이며 공식 DOCX/확인 경로도 계속 차단된다.
- 카드 텍스트는 새 LLM 호출 없이 기존 결과를 결정적으로 조합한다. 따라서 개인정보가 새 외부 호출이나 별도 저장 위치로 복제되지 않는다.
- 새 필드는 선택적·추가적이다. 기존 리포트 데이터, 목록 API, 공식 DOCX 파일명·MIME·최종 확인 API를 변경하지 않는다.

## 검증 기준

- fine notice와 traffic accident 리포트가 세 카드 유형을 일관되게 생성한다.
- appeal gate 차단 리포트는 제출 가능한 이의신청 초안 카드와 DOCX 액션을 노출하지 않는다.
- 부분/과거 리포트는 카드 생성 실패 없이 기존 섹션으로 계속 표시된다.
- 카드의 공개 JSON에 `form_data`, 확인 지문, 내부 사용자 ID, 원본 첨부파일 메타데이터가 포함되지 않는다.
- 일반 리포트 다운로드 액션은 새 결과에 포함되지 않고, 공식 이의신청서 DOCX의 확인·다운로드 회귀가 유지된다.
- 백엔드 DTO·Supervisor/worker 생성 경로·프런트엔드 카드/복사 동작·정적 계약 테스트를 모두 통과한다.
