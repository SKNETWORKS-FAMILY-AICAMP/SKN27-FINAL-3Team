# 서비스 범위·판단 불가·기한 안내 정합성 검증 설계

## 목적

PR #223이 도입한 서비스 범위와 기한 안내 정책을 현재 `dev`의 실제 응답 계약과 화면에 끝까지 연결한다. 이 작업은 새로운 상담·법률 판단 기능을 추가하지 않는다. 지원하지 않는 요청과 근거가 부족한 결과를 안전하게 멈추고, 사용자에게 한계와 다음 행동을 명확히 전달하는 최소 보완 작업이다.

## 확인된 현황

- `service_scope_policy.v1.json`은 차량 간 사고, 과태료 고지서·절차, 교통 법령 참고를 지원하고 보행자·자전거·시설물·민사 확정 판단·무관 요청을 안전 안내로 분기한다.
- 범위 밖 요청은 Supervisor 계획, 리포팅 payload, 문서 다운로드를 만들지 않고 `scope_guidance`로 종료한다.
- `deadline_guidance.v1`은 `overdue`, `due_soon`, `normal`, `needs_confirmation`을 모두 만들지만, 현재 UI와 결과 카드에서는 `normal`을 별도로 보여주지 않는다.
- 최종 병합 결과의 `limitations`와 `next_actions`는 존재하지만, 조합된 채팅 응답과 화면에서는 일반적인 근거 부족·판단 보류 안내가 일관되게 노출되지 않는다.
- `criminal` 또는 형사상 검토 요청은 범위 정책에 명시돼 있지 않다.

## 범위와 제외 범위

변경 대상은 다음으로 한정한다.

- `app/config/service_scope_policy.v1.json`의 형사상 검토 경계
- `app/services/chat_orchestration_service.py`의 안전 안내·다음 행동 응답 보존
- `app/web/FrontendAppShell.jsx`, `app/web/styles.css`의 최소 안내 패널과 기한 표시
- 서비스 범위, 안전 안내, 기한 표시를 고정하는 최소 Python 계약 테스트
- 검증 완료 후 `docs/ops/project-readiness-master-checklist.md`의 관련 항목과 OCR 후순위 표기

다음은 변경하지 않는다.

- 공식 DOCX 양식·DOCX 렌더러·다운로드 API·appeal gate
- guest credential, App JWT, 세션·소유권·권한 검증
- Agent 라우팅, OCR Provider, 법령·판례 데이터, 모델 호출
- UI 구조·디자인·이미지·더미 데이터 모드의 재설계
- 배포·Docker·DB 스키마·CI workflow

## A. 서비스 범위 정책

`criminal_review` 범위를 `expert_handoff`로 명시한다.

- 형사처벌, 고소·고발, 구속 등 형사상 판단 요청은 에이전트 실행이나 문서 생성을 시작하지 않는다.
- 응답은 서비스가 형사상 결론을 제공하지 않는다는 한계와, 사실관계·증빙 보존 및 전문가 상담이라는 다음 행동을 제공한다.
- 기존 고위험 사고의 응급 우선 처리, 차량 간 사고·과태료·교통 법령의 지원 경로, 보행자·자전거·시설물·민사 경계는 유지한다.

정책 결과의 기존 키와 값은 삭제·변경하지 않는다.

## B. 판단 불가·근거 부족 안내 계약

안전 안내는 두 흐름을 모두 다룬다.

1. `scope_guidance`
   - 기존 `service_scope.reason`, `limitations`, `next_actions`를 그대로 사용한다.
   - top-level `next_actions`에도 같은 값을 호환성 있게 추가해 API 소비자가 별도 중첩 해석 없이 다음 행동을 읽을 수 있게 한다.
   - 계획 단계는 계속 `blocked`, 카드·리포팅 payload·다운로드는 계속 비어 있어야 한다.

2. 최종 Agent 응답
   - `merge_final_response()`가 생성한 `limitations`와 `next_actions`를 `compose_agent_response()`가 누락 없이 보존한다.
   - 새 필드는 추가만 하며, 기존 `assistant_message`, `cards`, `deadline_guidance`, `reporting_payload` 계약을 바꾸지 않는다.

## C. 최소 화면 표시

새 패널은 기존 화면 레이아웃을 재설계하지 않고 최신 Assistant 응답 또는 결과 상단에만 추가한다.

- 채팅에서 `scope_guidance` 또는 제한사항이 있는 응답은 사유·한계·다음 행동을 표시한다.
- 결과 화면은 제한사항·다음 행동이 있는 부분 완료 또는 판단 보류 결과를 같은 형태로 표시한다.
- 결과 화면과 리포트 작업대에는 이 서비스가 법률 자문이나 개별 사건의 확정 판단을 대신하지 않고, 정보·근거·확인 항목을 정리한다는 고지를 표시한다.
- 공식 제출용 DOCX에는 이 화면 고지를 추가하지 않는다. 공식 양식의 내용·형식과 #238의 확정된 DOCX 경로를 보존한다.

## D. 기한 표시

`deadline_guidance.v1`가 존재하면 상태와 무관하게 결과 상단에서 표시한다.

- `overdue`, `due_soon`, `needs_confirmation`은 기존의 주의 안내 성격을 유지한다.
- `normal`은 실제 `deadline_guidance.deadline`과 정책 문구를 중립 스타일로 표시하고, 긴급 경고 ARIA 역할을 사용하지 않는다.
- 결과 요약의 기한 값도 검증된 `deadline_guidance.deadline`을 우선 사용하며, 기존 리포트 섹션 텍스트 탐색은 폴백으로만 유지한다.
- 기한을 새로 계산하거나 법적 기산일 판단을 변경하지 않는다.

## E. 회귀 검증

다음 계약을 테스트로 고정한다.

- 차량 간 사고·과태료·교통 법령은 지원 경로, 보행자·자전거·시설물·민사·형사 요청은 선언된 안전 경로로 분기한다.
- 형사 및 다른 범위 밖 요청은 Supervisor 계획·리포트·다운로드를 만들지 않으며, 제한사항과 다음 행동을 포함한다.
- 최종 Agent 응답의 제한사항·다음 행동이 조합된 API 응답에 보존된다.
- 채팅·결과 화면이 안전 안내를 렌더링하고, 결과 화면이 네 가지 기한 상태를 모두 처리한다.
- `normal` 기한은 중립 접근성 역할을, 다른 상태는 주의 역할을 사용한다.

관련 Python 계약 테스트와 `app/web`의 `npm run build`를 실행한다. 현재 시스템 Python에는 `pytest`가 없으므로, 프로젝트가 제공하는 테스트 실행 환경을 확인해 그 환경에서 실행한다.

## F. 체크리스트

모든 검증이 통과한 경우에만 이 PR 안에서 다음 항목을 완료 처리한다.

- 판단하기 어려운 사례의 표준 처리 방식
- 서비스 범위 명문화와 범위별 지원·참고·제외 정책
- 법률 자문이 아닌 정보·근거 정리 서비스라는 화면·리포트 고지
- 제출·이의신청 기한의 결과 상단 표시
- 판단 불가·근거 부족의 안전 안내와 다음 행동

동일 변경에서 OCR의 모델 비교, 평가 세트, 필드 정확도 항목은 완료 처리하지 않는다. 각각을 `이혜림 후순위`로 표시해 모델 비용 승인과 실제 평가 실행이 필요함을 남긴다. 체크리스트만을 위한 별도 PR은 만들지 않는다.

## 완료 기준

- 형사상 요청이 안전하게 전문가 확인 흐름으로 종료되고 기존 지원·고위험 흐름이 유지된다.
- 범위 밖·근거 부족·판단 보류 응답의 한계와 다음 행동이 API와 화면에서 모두 확인된다.
- 네 가지 기한 상태가 실제 정책 데이터 기준으로 결과 상단에 표시된다.
- 법률 자문·확정 판단 고지가 결과 및 리포트 작업대에 표시되고 공식 DOCX는 변경되지 않는다.
- 관련 계약 테스트와 프런트 프로덕션 빌드가 통과한다.
