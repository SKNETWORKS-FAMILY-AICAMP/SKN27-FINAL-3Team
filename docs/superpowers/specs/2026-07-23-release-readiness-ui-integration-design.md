# PR #296 UI 통합 및 운영 배포 준비 설계

## 상태와 목표

- 기준 브랜치: `origin/dev`
- 기준 커밋: PR #293 병합 커밋 `d326ae8`

- 제품 결정: PR #296의 홈·상담·마이페이지·리포팅 전체 UI 방향을 유지한다.
- 완료 목표: 최신 `dev`에 UI를 안전하게 통합하고, 코드와 자동화로 닫을 수 있는 운영 배포 준비 항목을 완료한다.

실제 운영 계정 생성, 유료 API 키 발급·입력, 도메인·DNS·OAuth 소유권 설정,
비용 승인, 운영 트래픽 전환은 사람의 작업으로 남긴다. 그 밖의 코드, 테스트,
문서, 배포 자동화, 이슈·브랜치·PR·병합 작업은 이 통합 작업에서 수행한다.

## 통합 원칙

1. 현재 사용자의 dirty worktree는 수정하지 않는다.
2. 최신 `origin/dev`에서 만든 격리 브랜치
   `feat-release-readiness-integration`에서만 작업한다.
3. PR #296의 시각적 방향은 유지하되 런타임 오류, 기존 기능 계약 훼손,
   접근성·키보드·모바일 회귀는 수정한다.
4. PR #296 브랜치를 강제 갱신하지 않는다. 통합 브랜치에서 충돌을 해결하고
   검증한 후 별도 PR로 `dev`에 반영한다.
5. 완료 주장은 새 브랜치에서 다시 실행한 검증 증거만 사용한다.

## UI 통합 범위

### 홈

- 회전형 카드와 다크 테마를 유지한다.
- 마우스 휠, 터치, 좌우 방향키, 직접 카드 선택이 같은 상태 전이를 사용한다.
- 포커스 표시, 현재 카드 상태, 작은 화면 레이아웃을 검증한다.

### 상담 및 첨부

- `+` 첨부 메뉴 UI를 유지한다.
- 첨부 옵션은 지원 MIME, 용도, 설명을 하나의 명시적 설정으로 관리한다.
- 파일 선택은 기존 `handleAttachmentFile` 경계를 통과시켜 MIME 검증,
  영상 용도 자동 선택, 선택 상태 초기화가 유지되게 한다.
- 정의되지 않은 `CHAT_ATTACHMENT_OPTIONS`와 자식 컴포넌트의
  `setSelectedUploadFile` 직접 호출을 제거한다.
- 비로그인 첨부 안내, 등록 진행·실패 상태, 파일 제거와 재선택을 검증한다.

### 마이페이지

- 기한 임박 수치는 실제 사건 데이터에서만 계산한다.
- 날짜 파싱 실패, 사용자 입력 출처가 아닌 날짜, 지난 기한을 잘못 표시하지 않는다.
- 조치 필요 필터와 페이지 이동 시 선택 사건이 현재 페이지와 일치하도록 한다.

### 리포팅

- 접을 수 있는 리포트 목록과 문서형 미리보기를 유지한다.
- 저장 리포트 선택, 빈 목록, 인증 상태, 최종 확인 게이트를 기존 API 계약과 맞춘다.
- 공식 문서 다운로드 확인은 서버가 `required`로 반환한 인증 사용자에게만 표시한다.

### 응답 표시

- 스트리밍 표현은 최종 응답 계약을 바꾸지 않는 표시 계층으로 제한한다.
- 빈 응답, 긴 응답, 컴포넌트 언마운트 상황에서 상태 갱신 누수와 과도한 지연을 막는다.
- 429 오류와 일반 오류의 사용자 안내를 구분하되 내부 구현 정보는 노출하지 않는다.

## 테스트 전략

오류를 먼저 재현하는 테스트를 추가한 뒤 구현을 수정한다.

- 정적 계약 검사: 정의되지 않은 UI 심볼과 우회된 첨부 핸들러 검출
- 컴포넌트/브라우저 여정: 첨부 메뉴 열기 → 파일 선택 → 검증 → 등록/제거
- 홈 상호작용: 클릭, 키보드, 휠, 터치 상태 전환
- 마이페이지: 기한 계산, 필터, 페이지 이동
- 리포팅: 목록 접기/펼치기, 선택, 확인 게이트
- 회귀 검증: 프런트 빌드, Django check, 집중 테스트, 전체 수집 가능한 pytest,
  OpenAPI 계약, `git diff --check`

브라우저 자동화 도구가 저장소에 없다면 최소 의존성을 임의로 도입하지 않고,
기존 테스트 구조에 정적·행동 계약 테스트를 추가한 후 Vite 개발 서버에서
핵심 여정을 직접 검증한다.

## 운영 배포 직전 게이트

UI 통합 후 `docs/ops/project-readiness-master-checklist.md`와 관련 운영 문서를
최신 `dev`에서 다시 분류한다.

- 코드로 닫을 수 있는 항목: 테스트 우선으로 구현하고 같은 통합 PR에 포함
- 로컬·Docker에서 검증 가능한 항목: 재현 가능한 명령과 결과를 남김
- 실제 키·계정·운영 데이터가 필요한 항목: 입력 위치, 실행 명령, 성공·실패 판정,
  롤백 절차까지 준비하고 사람 작업으로 명시

릴리스 후보는 다음을 만족해야 한다.

- 집중 테스트와 전체 자동화 검증 통과
- 프런트 빌드와 핵심 사용자 여정 통과
- pgvector migration/readiness/seed 절차와 실패 시 복구 절차 확인
- 컨테이너·Terraform·배포 스크립트의 정적 검증
- 비밀정보·PII·로그·보존·timeout/retry/rollback 경계 확인
- 사람이 제공해야 할 값만 남은 환경변수 목록과 실행 순서 문서화

## 병합과 인계

통합 브랜치를 푸시하고 `dev` 대상 PR을 만든다. CI와 리뷰 상태를 확인하고,
검증 결과와 남은 사람 작업을 PR 본문에 기록한다. 필수 체크가 통과하고
head SHA가 바뀌지 않았을 때 정상 merge 방식으로 병합한다.

최종 인계에는 다음만 남긴다.

- 발급·입력이 필요한 실제 비밀값
- AWS/Google/OpenAI 계정 및 결제 승인
- 도메인·DNS·OAuth 운영 소유권 작업
- 운영 DB migration·유료 재임베딩 실행 승인
- 최종 운영 트래픽 전환과 사후 모니터링 승인
