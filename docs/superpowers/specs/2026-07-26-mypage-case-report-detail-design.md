# 마이페이지 사건별 리포트 상세 설계

## 목표

마이페이지의 각 사건에서 해당 사건의 저장 리포트를 바로 열고, 기존 리포트 기능과 데이터 연결을 유지하면서 `message.txt`의 카드형 구성을 적용한다.

## 화면 흐름

1. 사용자가 마이페이지의 `내 사건`에서 사건을 선택한다.
2. 저장 리포트가 있으면 `리포트 자세히 보기` 버튼을 표시한다.
3. 버튼 클릭 시 사건의 `report_id`로 기존 `openReportDetail()`을 호출하고 `ReportingScreen`으로 이동한다.
4. 저장 리포트가 없으면 `리포트 생성 필요` 상태와 `AI 상담 이어가기` 버튼을 표시한다.

## 마이페이지

- 사건명, 상태, 최근 작업 시각을 기존 사건 데이터로 표시한다.
- `latest_report_id` 또는 `report_id`가 있는 사건만 `리포트 자세히 보기`를 제공한다.
- 사건별 리포트 연결은 기존 사건·리포트 식별자를 사용하며 새로운 API를 추가하지 않는다.
- 사건이 두 개이고 각각 리포트가 있다면 두 사건 모두 독립적인 상세 버튼과 리포트 화면을 제공한다.

## 리포트 상세

기존 `ReportingScreen`의 저장, 다운로드, 로그인 및 리포트 목록 기능을 유지하고 본문을 다음 순서로 구성한다.

1. 사건명, 접수번호, 분석일
2. AI 추정 과실비율과 법적 판단 한계 안내
3. 사용자 진술, OCR 등 사고 정황 요약
4. 관련 법령, 유사 사례, AI 판단 근거
5. 영상 분석 결과와 주요 시점
6. 기존 저장 및 DOCX 다운로드 기능

## 데이터 원칙

- `currentReport`, `reportingPayload`, `analysisCards`, `supervisorExecution` 등 기존 데이터를 재사용한다.
- `message.txt`의 예시 수치, 사건 내용, 외부 동영상 URL은 사용하지 않는다.
- 확인되지 않은 값은 추정하거나 하드코딩하지 않고 `확인된 자료 없음`으로 표시한다.
- 한 사건의 리포트가 여러 개면 기존 리포트 목록에서 선택하여 각각 상세 내용을 연다.

## 오류 처리

- 리포트 식별자가 없으면 상담 화면으로 연결한다.
- 상세 조회 실패 시 기존 목록 요약을 유지하고 현재 상태 메시지를 표시한다.
- 영상 자료가 없거나 재생할 수 없으면 영상 영역에 자료 부재 안내를 표시한다.

## 검증

- 사건 두 개가 서로 다른 `report_id`를 가질 때 각 버튼이 올바른 리포트를 연다.
- 리포트가 없는 사건은 상담 이어가기 버튼을 표시한다.
- 상단 메뉴, 로그인, 파일 업로드, 상담, 저장 및 다운로드 연결이 변경되지 않았는지 확인한다.
- 프론트엔드 프로덕션 빌드를 실행한다.
