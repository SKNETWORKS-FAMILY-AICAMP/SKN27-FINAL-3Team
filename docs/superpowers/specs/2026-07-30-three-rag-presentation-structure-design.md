# 판례·심의사례·인정기준 RAG 발표 구조 설계

## 1. 목적

최종 발표의 기술 파트에서 OCR을 제외하고 판례, 심의사례, 인정기준 RAG를
약 10장으로 설명한다.

발표가 끝났을 때 멘토와 평가자는 다음을 이해해야 한다.

> 세 RAG는 같은 데이터를 세 번 검색하는 구조가 아니라, 서로 다른 법률 근거를
> 수집·구조화·검색한 뒤 과실비율 Agent가 목적에 맞게 조립하는 근거 체계다.

발표의 목적은 구현 목록을 나열하는 것이 아니다. 각 데이터에서 어떤 문제가
있었고, 그 문제 때문에 어떤 수집·구조화·검색 전략을 선택했으며, 결과가 어떻게
달라졌는지를 설명한다.

## 3. 현재 발표의 문제

기존 61장 덱에서는 세 RAG가 다음과 같이 축약되어 있다.

- 슬라이드 42: 심의사례·판례·법령을 분리 검색한다는 공통 원칙
- 슬라이드 52: 판례와 심의사례의 데이터 건수

이 구성만으로는 다음이 드러나지 않는다.

1. 세 데이터가 각각 어떤 질문에 답하는지
2. 데이터별 수집 난점이 무엇이었는지
3. 같은 임베딩 모델을 사용해도 검색 단위와 후처리가 왜 다른지
4. 과실비율 Agent가 세 결과를 어떻게 조립하는지
5. 성능 수치가 검색 품질인지 법률 판단 정확도인지

기존 슬라이드 52의 판례 수치 `973건·10,833청크`는 최종 발표 보고서의
`825판례·3,339 의미 블록`과 일치하지 않으므로 최신 근거로 교체한다.

## 4. 검토한 구성안

### 8장 압축형

- 공통 파이프라인 1장
- 데이터별 수집·검색 2장씩
- Agent 통합 1장

발표 속도는 빠르지만 세 RAG의 역할 차이와 결과 해석이 얕아진다.

### 10장 균형형 — 채택

- 세 근거의 역할 1장
- 공통 파이프라인 1장
- 데이터별 수집·검색 2장씩
- 통합 비교 1장
- 과실비율 Agent 1장

각 데이터의 문제, 전략, 결과를 유지하면서도 반복 설명을 줄일 수 있다.

### 12장 기술형

공통 모델 선정과 평가 계약을 별도 슬라이드로 추가한다. 기술 면접이나
부록에는 적합하지만 최종 발표 본편에서는 지표와 절차가 과밀해진다.

## 5. 채택한 10장 서사

### 슬라이드 1. 하나의 사고를 세 종류의 근거로 검토한다

- 인정기준: 적용 가능한 공식 Rule과 기본 비율
- 심의사례: 유사한 실제 분쟁의 판단과 과실비율
- 판례: 유사 사실관계에 대한 법원의 책임 판단 논리

세 데이터가 중복되는 것이 아니라 서로 다른 판단 공백을 채운다는 점을 먼저
설명한다.

### 슬라이드 2. 공통 파이프라인은 같고 데이터 전략은 달랐다

공통 뼈대:

```text
원천 수집
→ 품질 검증
→ 도메인 구조화
→ 검색 단위 생성
→ Qwen3-Embedding-4B 임베딩
→ 1차 후보 검색
→ 데이터별 후처리
→ 과실비율 Agent
```

이 슬라이드에서 이후 세 데이터의 차이를 미리 색상으로 분기한다.

### 슬라이드 3. 인정기준은 PDF 표를 신뢰 가능한 Rule로 다시 만들었다

- 서로 다른 구조의 공식 PDF 4종
- 1,109행과 고유 Rule 277개의 구분
- Party, Variant, 비율 표현의 오염 문제
- PDF→Core→Search→Embedding→DB→Calculator 계보 재구축

어필 문장:

> 모델보다 먼저, 오염된 인정기준 데이터 구조를 다시 만들었습니다.

### 슬라이드 4. 인정기준은 Rule 검색 뒤 구조 조건과 계산을 검증한다

- Qwen 임베딩으로 Rule 후보 Top-50 회수
- PostgreSQL 구조 조건 재정렬
- Neo4j 관계·경로 보강
- Calculator로 당사자 방향과 조건부 비율 계산
- Recall@50 `30/30`
- 구조 검색 Hit@1 `22/30=73.3%`
- Final Ratio Exact `18/30=60.0%`

100%는 후보 회수율이며 자동 법률 판단 정확도가 아님을 함께 표시한다.

### 슬라이드 5. 심의사례는 사례의 판단 구조를 네 개 의미 단위로 보존했다

- 472쪽 PDF
- 226개 사례
- 사례별 `case_overview`, `arguments`, `evidence_issue`, `decision`
- 총 904개 구조 청크
- 중복, 빈 청크, 사례 누락 없이 구조 감사 통과

어필 문장:

> 심의사례는 원문을 잘게 자른 것이 아니라 판단 과정을 네 단위로 보존했습니다.

### 슬라이드 6. 심의사례는 더 찾는 것보다 정답을 먼저 보여주는 것이 문제였다

- Qwen으로 청크 후보 검색
- 청크를 고유 사례 단위로 병합
- Strict32의 정답은 모두 Top-5 안에 존재
- BGE reranker로 같은 후보만 재정렬
- Hit@1 `20/32→24/32`
- 기존 정답 강등 0건

어필 문장:

> 심의사례는 후보 회수가 아니라 첫 번째 순서의 문제였습니다.

### 슬라이드 7. 판례는 모델보다 수집·분류 품질이 더 큰 병목이었다

- 기존 OLD: 987판례·8,334청크
- 수집 완전성, 교통사고 관련성, 과실 관련성, 의미 블록, 품질 등급 Gate
- 최종 NEW: 825판례·3,339 의미 블록
- 정답 판례 보유율 `27/30→30/30`

어필 문장:

> 판례 검색의 병목은 모델이 아니라 검색할 판례의 품질이었습니다.

### 슬라이드 8. 판례는 넓게 찾고 의미형 리랭커로 Top-5를 고른다

- Qwen으로 의미 블록 Top-200 후보 검색
- 판례 ID 단위 병합
- BGE reranker로 고유 판례 재정렬
- 최종 Top-5 반환
- Hit@1 `46.7%→66.7%`
- nDCG@10 `0.6114→0.7526`

후보 Top-200에 없는 판례는 리랭커도 복구할 수 없다는 한계를 함께 표시한다.

### 슬라이드 9. 같은 모델을 사용해도 세 RAG의 검색 책임은 다르다

| 구분 | 인정기준 | 심의사례 | 판례 |
|---|---|---|---|
| 질문 | 적용 Rule과 비율 | 유사 분쟁 판단 | 법원의 판단 논리 |
| 검색 단위 | Rule·근거 문서 | 사례별 4개 청크 | 판례 의미 블록 |
| 1차 검색 | Qwen vector | Qwen vector | Qwen vector |
| 후처리 | PostgreSQL·Neo4j·Calculator | 사례 병합·BGE rerank | 판례 병합·BGE rerank |
| 출력 | 기준 비율·조건 | 유사사례·결정 | 법리·책임 판단 근거 |

공통 모델을 선택했지만 데이터 성격에 맞춰 후처리를 분리했다는 기술적 결론을
보여준다.

### 슬라이드 10. 과실비율 Agent는 세 근거를 조립해 설명 가능한 범위를 만든다

```text
사용자 사고 사실
→ 인정기준: 기준값·조건
→ 심의사례: 유사사례·결정
→ 판례: 법리·책임 판단 근거
→ 일치점·차이점·근거 강도 비교
→ 과실비율 범위·설명·추가 확인사항
```

Agent는 세 숫자를 단순 평균하지 않는다. 사고 조건, 당사자 방향, 근거 직접성,
데이터별 한계를 함께 검토한다.

최종 출력은 법률 판단 확정값이 아니라 다음을 포함한 검토 자료다.

- 예상 과실비율 범위
- 적용 인정기준
- 유사 심의사례
- 관련 판례
- 사용자 사건과 근거의 차이
- 추가로 확인할 증거

## 6. 시각 디자인 원칙

멘토 피드백을 다음 규칙으로 반영한다.

1. 16:9 비율을 유지한다.
2. 슬라이드당 텍스트 30%, 시각자료 70%를 목표로 한다.
3. 제목은 명사형 목차가 아니라 사람이 말하는 두괄식 결론으로 작성한다.
4. 각 슬라이드는 한 가지 주장만 전달한다.
5. 세 데이터에 동일한 2장 패턴을 사용한다.
   - 첫 장: 수집·구조화 전략
   - 둘째 장: 검색·후처리·결과
6. 긴 표 대신 퍼널, 전후 비교, 검색 흐름, 역할 비교 도식을 사용한다.
7. 수치 표시는 한 슬라이드당 핵심 2~3개로 제한한다.
8. 판례·심의사례·인정기준에 고정 색상을 부여하고 마지막 통합 슬라이드까지
   유지한다.
9. 코드, 파일 경로, 세부 모델 후보표, 전체 실험 로그는 본편에서 제외하고
   부록으로 보낸다.
10. 기존 덱의 네이비·오렌지·오프화이트 톤을 유지하되 기술 도식의 포맷을
    통일한다.

## 7. 주장과 수치 사용 원칙

- `Recall@50 100%`를 최종 과실비율 정확도 100%로 표현하지 않는다.
- `Hit@1`, `nDCG`, `Final Ratio Exact`의 의미를 섞지 않는다.
- 30개 또는 32개 동결 평가셋 결과를 실제 교통사고 전체 성능으로 일반화하지
  않는다.
- RAG 결과는 법률 판단이 아니라 출처가 연결된 검토 근거라고 표현한다.
- 과실비율 Agent가 세 RAG 결과를 단순 평균한다고 표현하지 않는다.
- 판례 데이터는 최신 최종 값인 825판례·3,339 의미 블록을 사용한다.

## 8. 완료 기준

향후 이미지 시안과 PPT는 다음 조건을 만족해야 한다.

- 10장 전체 흐름이 한눈에 이해된다.
- 공통 파이프라인과 데이터별 차이가 동시에 보인다.
- 각 데이터가 `문제→전략→결과` 순서로 설명된다.
- 과실비율 Agent의 입력, 조립 원칙, 출력, 한계가 구분된다.
- 본편에서 OCR과 Vision 상세 설명을 다루지 않는다.
- 멘토 피드백의 텍스트 30%·시각자료 70%, 두괄식 제목, 디자인 통일을 반영한다.
- 모든 성능 수치가 데이터별 최종 발표 보고서와 일치한다.
