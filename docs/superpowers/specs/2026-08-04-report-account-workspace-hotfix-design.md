# 계정 범위 리포트 작업대 핫픽스 설계

## 목표

로그인 사용자가 현재 상담 세션과 무관하게 본인 소유의 저장 리포트를 리포트 메뉴에서 확인하고, 고지서 OCR 확인이 끝나면 별도 키워드나 추가 사실 입력을 필수로 요구하지 않고 검토 가능한 이의신청서 초안을 생성한다.

## 확정 원인

- 프론트엔드 목록 요청이 현재 `session_id`를 항상 전송해 과거 상담의 정상 리포트를 숨긴다.
- 백엔드는 인증 사용자 목록 요청에서 이미 `owner_id` 경계를 강제하므로 `session_id`가 없으면 안전하게 계정 전체 목록을 반환할 수 있다.
- OCR 확인 이후에도 문서 표현과 실행 표현을 함께 요구해 `objection_report_generation`이 누락된다.
- OCR의 `fine_type`과 `notice_stage`가 모두 채워져야만 다음 단계로 가고, 사용자 이의 사유가 없으면 초안 노드 실행 전에 전체 흐름을 중단한다.
- 기한 경과 또는 대상 아님 판단은 다운로드뿐 아니라 검토용 초안과 복사 기능까지 숨긴다.
- 리포트가 아직 없는 상태의 문구가 영구적인 미지원처럼 보여 실제 상태를 오해하게 한다.

## 설계

1. 리포트 목록 API 클라이언트는 목록 조회에 `session_id`를 보내지 않는다. 상세·확인·다운로드 요청은 선택한 리포트의 `session_id`를 계속 사용한다.
2. 목록 보안은 기존 백엔드의 인증 사용자 `owner_id` 필터를 유지한다. 다른 사용자의 리포트는 반환하지 않는다.
3. `fine_notice_analysis`에서 사용자가 OCR 결과를 확인하면 문서·실행 키워드와 무관하게 리포트 계획을 활성화한다. OCR 필드 완성도와 사용자 이의 사유 부족은 실행 차단이 아니라 부분 초안의 `missing_fields`와 검토 안내로 처리한다.
4. 기한 경과 또는 대상 아님 판단에서도 초안 본문과 복사 기능은 제공하되, DOCX 다운로드는 기존 `appeal_gate`로 계속 차단한다.
5. 현재 상담에 리포트가 없을 때는 미지원 단정 대신 아직 생성되지 않았다는 설명과 OCR 확인 후 자동 초안 생성 안내를 표시한다.
6. 프론트엔드 상태는 `currentSessionReport`, `savedReportList`, `selectedSavedReport`로 분리한다. 저장 목록을 조회해도 계정의 최신 리포트를 현재 상담 리포트로 오인하지 않으며, 사용자가 저장 목록에서 선택한 상세만 `selectedSavedReport`가 된다.
7. 로그인 복원은 최신 상담 manifest 복원과 계정 전체 리포트 목록 조회를 독립적으로 수행한다. 새 상담을 시작해도 계정 저장 목록은 유지하고 현재 상담/선택 상세만 초기화한다.
8. OCR 확인 버튼은 `report_generation_requested: true`와 버전이 지정된 `generate_objection_draft` action을 전송한다. 서버는 확인된 OCR 요청에서만 이를 정규화해 세션 `chat_followup_state`와 `AnalysisJob.metadata`에 영속화하고, 이후 재시도에서도 서버 저장 상태를 복원한다.
9. 현재 상담 리포트와 선택한 저장 리포트가 없지만 계정 저장 목록은 있을 때 작업대는 `saved_reports_only` 상태로 표시하고, 현재 상담에는 리포트가 없지만 저장 리포트를 선택할 수 있음을 명시한다.

## 유지하는 필수 경계

- 로그인 사용자 `owner_id` 격리
- 파일 스캔 완료 및 서버 확인 자료 분류
- 사용자의 OCR 확인 행위
- persisted Supervisor handoff 무결성
- 기한 경과·대상 아님 상태에서의 공식 DOCX 다운로드 차단

## 검증

- 프론트 API 단위 테스트에서 리포트 목록 URL에 `session_id`가 없음을 검증한다.
- 백엔드 계약 테스트에서 한 사용자의 서로 다른 세션 리포트가 모두 보이고 다른 사용자 리포트는 보이지 않음을 검증한다.
- 문서·실행 키워드, 완전한 OCR 필드, 사전 사용자 이의 사유가 없어도 OCR 확인 후 초안 노드가 계획되는지 검증한다.
- 이의 가능성 차단 상태에서도 복사 가능한 부분 초안은 보이고 DOCX 다운로드 차단 상태는 유지되는지 검증한다.
- 리포트 작업대 상태 테스트에서 빈 상태 안내가 실제 상태와 일치함을 검증한다.
- 상태 계약 테스트에서 현재 상담·계정 목록·선택 상세가 별도 state로 유지되고 새 상담이 계정 목록을 삭제하지 않음을 검증한다.
- 로그인 복원 계약 테스트에서 resume manifest 이후 계정 전체 목록 API가 별도로 호출됨을 검증한다.
- OCR 확인 E2E에서 구조화 action이 세션 follow-up 상태와 분석 작업 metadata에 모두 영속화됨을 검증한다.
- 작업대 테스트에서 `saved_reports_only`가 일반 빈 화면 및 선택된 저장 리포트 화면과 구분됨을 검증한다.
- 전체 프론트 Node 테스트, Django chatbot 테스트, Python 테스트, Vite 빌드를 수행한다.
- 배포 후 로그인 상태에서 과거 리포트 노출, 새 초안 생성, DOCX 다운로드를 브라우저로 검증한다.
