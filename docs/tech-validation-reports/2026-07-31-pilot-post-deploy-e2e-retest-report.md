## 원인 분석

`deploy/aws-pilot/Release-PilotApp-FromPipeline.sh`는 새 이미지 태그를 pull한 뒤 `backend frontend` 서비스만 삭제·기동한다. 그러나 아래 서비스도 같은 백엔드 이미지를 실행한다.

- `agent-worker`: 상담 Agent 작업과 최종 응답 병합을 비동기로 처리
- `file-scan-worker`: 업로드 파일 스캔 처리
- `ops-monitor`: 운영 상태 수집

따라서 PR #349의 `chat_orchestration_service`·`supervisor_control_service` 변경은 새 웹 백엔드에는 반영됐지만, 큐를 소비하는 `agent-worker`에는 반영되지 않았다. 이 불일치가 법령 검색의 구형 요약만 노출한 직접 원인이다. 같은 배포 결함은 파일 스캔과 운영 모니터 코드 업데이트에도 재발할 수 있다.

최근 백엔드 컨테이너의 오류 유형 집계(`ERROR`, `Exception`, `Traceback`, HTTP 500)는 모두 0건이었다. 즉 이번 문제는 웹 백엔드 예외가 아니라 배포 대상 서비스 누락 문제다.

## 재발 방지 핫픽스

새 브랜치 `feat/fix-pipeline-restart-workers`에서 다음을 준비했다.

1. 릴리스 때 `backend frontend agent-worker file-scan-worker ops-monitor` 이미지를 함께 pull하고 기존 컨테이너를 함께 제거한다.
2. 웹 백엔드·프런트를 먼저 기동하고 헬스 검사를 통과한 뒤 세 백그라운드 워커를 새 태그로 기동한다.
3. 롤백 시에도 같은 워커 집합을 기존 이미지 태그로 재생성한다.
4. 릴리스 계약 테스트가 백엔드 이미지를 실행하는 모든 서비스를 포함하도록 변경한다.

## 재배포 후 필수 확인

1. CodePipeline 배포가 완료된 뒤 `skn27-pilot-agent-worker-1` 이미지 태그가 배포 커밋의 앞 12자리와 일치하는지 확인한다.
2. 같은 비회원 과태료 절차 질문에서 `조문 N건 검색됨` 단독 노출이 아닌 실행 가능한 절차 안내가 나오는지 확인한다.
3. OCR 없이 이의신청서 초안을 요청하면 문서 초안을 생성하지 않고 OCR/고지서 확인 게이트로 안내하는지 확인한다.
4. 위 두 시나리오가 통과하기 전에는 이번 PR #349의 사용자 흐름이 해결됐다고 판정하지 않는다.
