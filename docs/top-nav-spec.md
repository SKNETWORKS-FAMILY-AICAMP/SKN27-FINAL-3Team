# 상단 탭 내비게이션 추가 스펙 (홈 / 마이페이지 / 리포트)

Claude Code에게 전달할 작업 지시서. 대상 저장소: `SKN27-FINAL-3Team`, 대상 파일: `app/web/FrontendAppShell.jsx`, `app/web/styles.css`.

## 배경 / 현재 상태

- `app/web/FrontendAppShell.jsx` 14~20행 `ROUTES` 배열에 라우트가 정의되어 있음: `entry`, `chatbot`, `mypage`, `history`, `reporting`.
- 상단 탭바(`<header className="topbar">`, 1040~1068행)는 **`activeRoute === "entry"`일 때만 렌더링됨.** 즉 서비스 소개 화면에만 존재하고, 실제 상담 화면(`chatbot`)·마이페이지(`mypage`)·리포트(`reporting`)에서는 상단바가 사라지고 좌측 `ConversationSidebar`만 남음.
- 좌측 사이드바(`ConversationSidebar`, 1477행~) 안에 `sidebar-mini-nav`라는 보조 내비게이션이 있어 마이페이지/리포트로 이동은 가능하지만, "지금 내가 어느 화면에 있는지"를 알려주는 상단 탭 형태의 UI는 없음.
- 그 결과 캡처 화면(상담 화면)에는 정식 서비스 같은 상단 탭 구조가 보이지 않고, 좌측 상단에 로고만 있고 우측에 로그인 버튼만 떠 있는 상태.

## 목표

모든 주요 화면(홈=상담, 마이페이지, 리포트)에서 **상단에 고정된 탭바**가 항상 보이도록 만든다. 탭은 3개로 단순화: `홈`(상담 화면), `마이페이지`, `리포트`. 우측에는 로그인 상태에 따른 버튼(Google 로그인 / 로그아웃)을 유지한다.

## 화면 구조 (프로토타입 기준)

```
┌──────────────────────────────────────────────────────────┐
│ [AI] 교통분쟁 AI     홈  마이페이지  리포트     Google 로그인 │  ← 상단 탭바 (모든 라우트에서 표시)
├───────────┬──────────────────────────────────────────────┤
│ 새 상담    │                                              │
│ 상담 검색  │              (기존 화면 내용 그대로)           │
│ ─ 최근 ─  │        예: 상담 화면 / 마이페이지 / 리포트      │
│ 게스트 상담│                                              │
│           │                                              │
│ 내 사건 전체│                                             │
└───────────┴──────────────────────────────────────────────┘
```

- 상단 탭바는 좌측 로고 + 탭 3개, 우측 인증 버튼 1개로 구성. 폭이 좁아지면 탭 라벨만 남기고 나머지는 기존 반응형 규칙(2367행 근처 미디어쿼리) 따라감.
- 활성 탭은 배경색 강조(`bg-accent` 톤) + 텍스트 강조색으로 표시, 나머지는 회색 텍스트.
- 사이드바는 그대로 두되, `sidebar-mini-nav`의 마이페이지/리포트 버튼은 상단 탭과 기능이 중복되므로 제거하거나 유지 여부를 판단해 정리한다 (중복 내비게이션 지양).

## 구현 방향

1. **`ROUTES` 조정**: 상단 탭에 노출할 라우트를 3개로 제한.
   - `entry`는 탭에 노출하지 않음(별도 랜딩 화면 유지 또는 폐기 논의 필요).
   - `chatbot` → 라벨 `홈`
   - `mypage` → 라벨 `마이페이지`
   - `reporting` → 라벨 `리포트`
   - 필요하면 탭 노출용 배열을 `ROUTES`와 분리 (`TAB_ROUTES`)해서 `entry`/`history`처럼 탭에 안 보이는 라우트와 구분한다.

2. **`<header className="topbar">` 렌더링 조건 변경** (1039행 `{activeRoute === "entry" && (...)}` 부분):
   - `entry` 전용 조건을 제거하고 모든 라우트에서 렌더링하도록 수정.
   - 단, `entry` 화면 전용 문구("상담 시작" CTA 버튼 등)는 라우트별로 분기 처리.

3. **활성 탭 표시**: 기존 `activeRoute === route.id ? "button active" : "button ghost"` 로직 재사용 가능. `chatbot`이 활성일 때 `홈` 탭이 active 상태가 되도록 매핑.

4. **우측 영역**: 로그인 여부(`authSessionId` 또는 `isAuthenticated`)에 따라 `Google 로그인` / 로그아웃 버튼 토글 (기존 `ConversationSidebar`의 로그인/로그아웃 로직 참고, 1477행 이후).

5. **스타일**: 기존 `styles.css`의 `.topbar`(58행), `.topbar-inner`(67행), `.top-actions`(100행), `.button.active/.primary`(126행), `.button.ghost`(133행) 클래스를 그대로 재사용. 새 색상 정의는 최소화하고 기존 디자인 토큰을 따른다.

6. **사이드바 정리**: `sidebar-mini-nav`(189행)의 마이페이지/리포트 버튼 제거 여부 결정. 제거 시 `ConversationSidebar` 컴포넌트에서 해당 `<nav>` 블록(1543~1550행)을 삭제하고 `onNavigate` prop 사용처 점검.

## 체크리스트

- [ ] 상단 탭바가 `entry` 외 모든 라우트(`chatbot`, `mypage`, `reporting`)에서 표시됨
- [ ] 탭 라벨이 `홈 / 마이페이지 / 리포트` 3개로 정리됨
- [ ] 현재 라우트에 해당하는 탭이 활성 스타일로 표시됨
- [ ] 우측 로그인/로그아웃 버튼이 인증 상태에 맞게 표시됨
- [ ] 모바일 반응형(`mobile-bottom-nav`, 1569행)과 상단 탭이 중복 노출되지 않는지 확인
- [ ] 사이드바 `sidebar-mini-nav`와 상단 탭의 기능 중복 정리
- [ ] 기존 `entry` 랜딩 화면 접근 경로(로고 클릭 등) 유지 여부 결정
