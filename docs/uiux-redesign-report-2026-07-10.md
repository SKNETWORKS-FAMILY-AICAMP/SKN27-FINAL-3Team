# 교통분쟁 AI UI/UX 전면 개선 제안

- 작성일: 2026-07-10
- 대상: `app/web` MVP 및 `app/screen-design-mvp-flow.html`
- 산출물: 화면 전략, 정보구조, 디자인 시스템, 핵심 화면 시안, 구현 우선순위

## 1. 결론

현재 UI는 기능과 API 상태를 보여주는 데에는 충분하지만, 실제 사용자가 해결하고 싶은 질문인 **“내 사건에서 지금 무엇을 해야 하는가”**가 화면의 중심이 아니다. 서비스의 기획 의도에 가장 적합한 방향은 챗봇이나 AI Agent 대시보드가 아니라 **자료 기반 교통 사건 워크스페이스**다.

핵심 전환은 다음과 같다.

| 현재 관점 | 권장 관점 |
|---|---|
| 과태료 분석, 과실비율 분석 등 기능 중심 메뉴 | `내 사건`, `새 분석`, `리포트` 중심 사건 구조 |
| Supervisor, OCR 노드, success/partial 등 기술 상태 노출 | 확인된 사실, 불확실한 부분, 부족 자료, 다음 행동으로 번역 |
| 채팅을 시작점이자 결과 화면으로 사용 | 4단계 접수 → 사건 워크스페이스 → 리포트로 역할 분리 |
| 카드 수와 기능 수로 완성도를 표현 | 기한, 근거 출처, 자료 충족도, 행동 우선순위로 신뢰 형성 |
| 데스크톱 열을 모바일에서 단순 적층 | 모바일은 사건 접수와 다음 행동에 집중한 별도 흐름 |

## 2. 기획 의도 재정의

### 제품 한 문장

> 고지서·사고 자료·상황 설명을 바탕으로 AI가 교통분쟁의 사실관계와 법적 쟁점을 정리하고, 확인 가능한 근거와 다음 행동을 사건 리포트로 안내하는 서비스.

### 핵심 사용자

1. 과태료·범칙금 고지서를 받고 이의제기 여부와 기한이 궁금한 사용자
2. 교통사고 후 보험사의 과실 주장에 대응할 자료와 쟁점이 필요한 사용자
3. 관련 법령과 처리 절차를 일반 언어로 빠르게 확인하려는 사용자
4. 이전 상담과 리포트를 다시 열어 후속 행동을 이어가려는 사용자

### 사용자가 가져가야 할 가치

- **즉시성:** 3분 안에 사건을 접수하고 첫 번째 유용한 안내를 받는다.
- **명확성:** 사실, 추정, 부족 자료, 다음 행동이 섞이지 않는다.
- **신뢰성:** 법령·판례 출처와 확인일, 적용 조건, 한계가 보인다.
- **연속성:** 채팅이 끝나도 사건과 리포트가 남고 후속 행동을 이어갈 수 있다.

## 3. 현재 UI 진단

### 잘 된 점

- 로그인 없이 상담을 시작하고 필요 시 동일 세션을 계정에 연결하는 MVP 흐름이 있다.
- 고지서, 사진, 영상, 법령 질문을 한 상담 안에서 처리하는 제품 방향이 반영돼 있다.
- 결과 카드, 리포트 저장·다운로드, 마이페이지·이력까지 데모 스파인이 연결돼 있다.
- 근거와 한계를 함께 표시하려는 원칙이 이미 존재한다.

### 개선이 필요한 점

| 우선도 | 문제 | 사용자 영향 | 개선 방향 |
|---|---|---|---|
| P0 | Supervisor, Agent node, scan 상태 등 내부 구현이 전면에 노출됨 | 사용자가 무엇을 판단해야 하는지보다 시스템 동작을 해석하게 됨 | 기술 상태를 `확인 중`, `자료 필요`, `검토 완료` 등 사용자 언어로 변환 |
| P0 | 결과의 최우선 정보가 카드 여러 개에 분산됨 | 결론, 기한, 부족 자료, 다음 행동을 빠르게 찾기 어려움 | 상단 4요소 요약 + `지금 해야 할 일` 고정 영역 |
| P0 | 과태료/과실비율/상담/리포트가 각각 메뉴로 병렬 배치됨 | 하나의 사건이 여러 기능으로 찢어져 보임 | 사건 단위 IA로 통합하고 분석 유형은 사건 내부 탭 또는 자동 라우팅으로 처리 |
| P1 | 채팅, 첨부, 분석 상태가 데스크톱 3~4열에 동시에 노출됨 | 집중점이 약하고 작은 노트북에서 정보 밀도가 과도함 | 접수 단계와 검토 단계를 분리하고, 워크스페이스는 결과+행동 중심 2열 구성 |
| P1 | 상태가 색상과 영문 status 값에 의존함 | 부분 결과와 실패, 대기 상태의 의미를 이해하기 어려움 | 아이콘+텍스트+원인+다음 행동을 함께 제공 |
| P1 | 모바일이 데스크톱 열을 순서대로 적층함 | 입력창과 첨부, 상태가 멀리 떨어져 긴 스크롤 발생 | 모바일 전용 접수 흐름, 하단 고정 CTA, 사건 요약 우선 |
| P2 | 브랜드가 일반적인 `AI` 배지와 청록색 중심으로 보임 | 법률·증거 기반 서비스의 신뢰와 차별성이 약함 | 네이비(신뢰) + 블루(행동) + 틸(검증) 역할 팔레트와 사건 리포트 비주얼 도입 |

## 4. 권장 정보구조

```text
홈
├─ 서비스 이해
├─ 무료 분석 시작
└─ 샘플 리포트

새 분석 (4단계)
├─ 1. 사건 유형 선택
├─ 2. 자료 업로드
├─ 3. 상황 설명
└─ 4. 입력 확인 및 분석 시작

내 사건
├─ 사건 요약
├─ 확인된 사실 / 불확실한 부분
├─ 법적 근거
├─ 자료 및 분석 이력
├─ 지금 해야 할 일
└─ 리포트

계정
├─ 저장된 사건
├─ 알림 및 기한
└─ 자료 보관·삭제 설정
```

상단 메뉴에서 `과태료 분석`과 `과실비율 분석`은 제거한다. 사용자가 사건 유형을 선택하면 Supervisor가 필요한 Agent를 자동 구성한다는 제품 장점이 UI에서도 드러나야 한다.

## 5. 핵심 사용자 흐름

### A. 비회원 첫 방문

```text
가치 이해 → 사건 유형 선택 → 선택적 자료 업로드 → 상황 설명
→ 첫 분석 결과 → 저장/다운로드 시 Google 계정 연결 → 같은 session_id 유지
```

로그인은 진입 장벽이 아니라 **가치를 확인한 뒤 사건을 보관하는 순간**에 요청한다. 로그인 전 임시 보관 범위와 만료 시점을 명확히 안내한다.

### B. 고지서 이의제기

```text
고지서 업로드 → OCR 확인 → 제출기한 강조 → 사실관계 확인
→ 이의제기 쟁점 → 부족 자료 요청 → 의견진술서 초안 → 제출 전 체크
```

### C. 사고 과실 쟁점

```text
사고 유형/시간/장소 → 사진·영상 업로드 → 사고 장면 정리
→ 확인된 사실/상충 진술 → 법령·기준 → 보험사 문의 초안 → 리포트 저장
```

## 6. 화면별 권장안

### 홈

- 첫 문장은 AI 기능이 아니라 사용자의 불안과 결과를 말한다: `교통 문제, 근거와 다음 행동이 보여야 안심됩니다.`
- 주요 CTA는 `내 사건 무료 분석`, 보조 CTA는 `샘플 리포트 보기`로 단순화한다.
- `로그인 없이 시작`, `출처 기반`, `불확실성 공개`, `개인정보 마스킹`을 첫 화면 안에서 보여준다.
- 서비스 유형은 기능 메뉴가 아니라 사용자가 가진 문제를 설명하는 카드로 제공한다.

### 사건 접수

- 한 화면에 모든 입력을 요구하지 않고 4단계로 나눈다.
- `잘 모르겠어요` 선택지를 제공해 사용자가 분석 유형을 스스로 분류해야 하는 부담을 줄인다.
- 자료 업로드는 선택으로 시작하되, 결과 품질에 미치는 영향을 바로 설명한다.
- 모바일에서는 하단 고정 CTA를 사용하고 최소 터치 영역을 44px 이상으로 유지한다.

### 사건 워크스페이스

- 상단에 `현재 판단`, `제출 기한`, `자료 충족도`, `리포트 상태`를 고정한다.
- 본문은 `AI 검토 결과`와 `지금 해야 할 일`의 2열로 정리한다.
- 결과 안에서 `확인된 사실`과 `아직 불확실`을 시각적으로 분리한다.
- 법령/판례는 제목, 출처, 확인일, 적용 조건, 원문 링크를 함께 보여준다.
- 내부 Agent 실행 과정은 기본적으로 숨기고 `분석 기준 보기`에서만 선택적으로 공개한다.

### 리포트

- 첫 페이지에서 사건명, 검토일, 자료 수, 근거 수, 리포트 완성도를 확인할 수 있어야 한다.
- `검토 결론 → 사실관계 → 판단 쟁점과 근거 → 권장 행동 → 한계` 순서를 고정한다.
- 부분 결과이면 `부분 리포트`를 숨기지 말고 부족 자료와 영향 범위를 설명한다.
- 법적 결론을 단정하는 표현 대신 `현재 자료 기준`, `추가 확인 필요`, `적용 조건`을 사용한다.

## 7. 콘텐츠 디자인 원칙

| 시스템 표현 | 사용자 표현 |
|---|---|
| `success` | 검토 완료 |
| `partial_report` | 일부 자료가 부족한 부분 리포트 |
| `scan_pending` | 파일 안전 확인 중 |
| `blocked` | 이 자료를 확인해야 다음 단계로 갈 수 있어요 |
| `law_ground_search` | 관련 법적 근거 확인 |
| `async_worker queued` | 분석 대기 중 · 약 1분 |

금지에 가까운 표현은 `승소 가능`, `무조건`, `확실`, `법적으로 문제없음`이다. 대신 판단의 전제와 확인 범위를 함께 제시한다.

## 8. 디자인 시스템 방향

### 색상 역할

| 역할 | 권장 색 | 용도 |
|---|---|---|
| Ink/Navy | `#14263D` | 본문, 리포트 표지, 신뢰 기반 영역 |
| Action Blue | `#235EE7` | 주요 CTA, 선택, 링크 |
| Verified Teal | `#087D68` | 확인 완료, 검증된 자료 |
| Deadline Amber | `#B96500` | 기한 임박, 주의 |
| Risk Red | `#B83D4A` | 오류, 제출 불가, 중요한 누락 |
| Canvas | `#F3F6FA` | 앱 배경 |

청록색 하나가 브랜드, CTA, 성공 상태를 모두 담당하지 않게 역할을 분리한다. 상태는 색상만으로 전달하지 않고 아이콘과 텍스트를 함께 사용한다.

### 형태와 밀도

- 화면 최대 폭: 마케팅 1280px, 사건 워크스페이스 1440px 이하
- 카드 반경: 12~18px, 화면 전체 컨테이너 20~24px
- 기본 간격: 4px 배수, 화면 섹션 24/32/48px
- 버튼 높이: 데스크톱 42~46px, 모바일 최소 44px
- 본문 폭: 긴 설명 65~75자 내외

### 접근성

- 일반 텍스트 대비 4.5:1 이상
- 키보드 포커스 링과 논리적인 탭 순서 제공
- 파일 업로드에 키보드와 스크린리더 대체 입력 제공
- 마감일, 실패, 부분 결과는 색상 외에 텍스트·아이콘·원인을 동시 제공
- 모바일 하단 고정 CTA가 입력창이나 OS 안전 영역을 가리지 않게 처리

## 9. 측정 지표

| 단계 | 핵심 지표 |
|---|---|
| 홈 | 분석 시작률, 샘플 리포트 열람률 |
| 접수 | 단계별 이탈률, 사건 유형 선택 시간, 업로드 성공률 |
| 분석 | 첫 유용한 결과까지 걸린 시간, 진행 상태 이해도 |
| 결과 | 부족 자료 보완률, 법적 근거 열람률, 다음 행동 클릭률 |
| 리포트 | 저장률, 다운로드율, 부분 리포트 보완 전환율 |
| 재방문 | 7일 내 사건 재방문률, 기한 알림 이후 행동 완료율 |

## 10. 구현 우선순위

### Phase 1 · P0, 1~2주

1. 메뉴를 `홈 / 내 사건 / 새 분석`으로 재구성한다.
2. 결과 상단에 현재 판단, 기한, 자료 충족도, 리포트 상태를 추가한다.
3. Supervisor/Agent/worker 상태를 사용자 언어로 매핑한다.
4. 결과를 `확인된 사실 / 불확실 / 부족 자료 / 다음 행동`으로 재배치한다.
5. `partial_report`와 실패 상태에 원인·영향·해결 행동을 표시한다.

### Phase 2 · P1, 2~3주

1. 새 상담을 4단계 접수 흐름으로 분리한다.
2. 사건 워크스페이스와 리포트 화면을 독립 라우트로 만든다.
3. 법령·판례 출처 컴포넌트를 표준화한다.
4. 모바일 접수와 모바일 결과 화면을 별도 최적화한다.
5. 로그인 요청을 저장/다운로드 시점으로 일관되게 이동한다.

### Phase 3 · P2, 1~2주

1. 기한 알림과 오늘 해야 할 일 위젯을 추가한다.
2. 보고서 버전 비교와 자료 추가 후 재분석 흐름을 제공한다.
3. 접근성 점검과 5명 규모 사용성 테스트를 진행한다.
4. 퍼널 이벤트와 UX KPI 대시보드를 연결한다.

## 11. 검증 시나리오

1. 처음 방문한 사용자가 로그인 없이 3분 안에 고지서 사건을 시작할 수 있는가?
2. 사용자가 결과 화면 10초 안에 제출기한과 다음 행동을 찾을 수 있는가?
3. 부분 리포트에서 무엇이 부족하고 결과에 어떤 영향을 주는지 설명할 수 있는가?
4. 법령 근거의 출처와 확인일을 찾고 원문으로 이동할 수 있는가?
5. 모바일에서 자료 업로드 후 다음 단계로 이동할 때 긴 스크롤이나 CTA 분리가 없는가?
6. 로그인 후 기존 `session_id`, 첨부 자료, 분석 상태가 그대로 유지되는가?
