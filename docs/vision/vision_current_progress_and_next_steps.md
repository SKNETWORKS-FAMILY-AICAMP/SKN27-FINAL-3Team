# Vision 1차 분석 진행 현황 및 향후 진행 방향

## 1. 현재 최종 방향

이번 1차 분석에서는 5초 clip 생성 실험을 우선순위에서 제외하고, 사고 장면이 포함되어 있다고 가정된 10초 원본 블랙박스 영상을 그대로 활용하는 방향으로 정리했다.

즉, 1차 목표는 다음과 같다.

```text
입력 데이터: 사고 장면이 포함된 10초 원본 영상
분석 목표: 사고 유형 분류에 사용할 수 있는 학습 데이터 정제
최종 분류 모델: VideoMAE
보조 모델: YOLO, Qwen2.5-VL
```

5초 clip 추출, 사용자 입력 영상에서 사고 후보 구간을 자동으로 찾는 기능, 5초에서 30초 이내 영상 입력 정책은 1차 분석 이후의 고도화 단계에서 진행하는 것으로 분리한다.

현재는 먼저 10초 원본 영상 기준으로 사고 장면이 명확한 데이터와 애매한 데이터를 구분하고, 학습에 사용할 수 있는 데이터만 선별한 뒤 VideoMAE 재학습으로 이어가는 것이 핵심이다.

-> YOLO 모델 버전 변경하여 객체 탐지 결과 비교해보기(bbox, 태그) (차량에 대한 속도를 인지하지 못할 가능성이 있음)
-> 저녁 영상 전처리(화이트로 변경) 밤 -> 낮 으로 영상을 변환해주는 모델이 있을 것 , Qwen 모델로 넘겨줄때, 밤,낮을 같이 넘겨줘야 할 것
-> 저녁 영상만 따로 학습 

## 2. 진행된 사항

### 2.1 10초 원본 영상 기반 분석으로 방향 전환

기존에는 YOLO/ByteTrack으로 사고 후보 구간을 찾고 5초 clip을 생성한 뒤 VideoMAE에 입력하는 구조를 검토했다. 그러나 현재 1차 발표와 1차 분석 단계에서는 clip 생성 자체가 추가 변수가 되기 때문에, 우선 사고 장면이 포함된 10초 원본 영상을 그대로 활용하는 방향으로 정리했다.

이 결정의 이유는 다음과 같다.

- clip 생성이 잘못되면 모델 성능 문제인지, clip 추출 문제인지 구분하기 어렵다.
- 현재 데이터 자체에도 사고 장면이 명확한 영상과 그렇지 않은 영상이 섞여 있을 가능성이 있다.
- 먼저 10초 원본 영상에서 학습 가능한 데이터인지 판단하는 기준을 세우는 것이 필요하다.
- 이후 5초 clip 자동 추출은 1차 분석이 끝난 뒤 별도 실험으로 진행하는 것이 더 안전하다.

따라서 현재 1차에서는 “10초 원본 영상 기반 데이터 품질 검수 및 VideoMAE 학습”을 우선으로 둔다.

### 2.2 Qwen2.5-VL 단독 사고 탐지 방식 보류

Qwen2.5-VL을 단독으로 영상에 적용했을 때, 사람이 보기에는 사고 장면이 명확한 영상에서도 사고를 명확히 탐지하지 못하는 경우가 있었다. 특히 video 입력 방식에서는 Qwen 내부 샘플링이 어떤 프레임을 실제로 보는지 통제하기 어려웠다.

따라서 Qwen2.5-VL은 최종 사고 유형 분류 모델로 사용하지 않고, 다음 역할로 제한한다.

- 사고 장면이 명확한지 보조 판단
- 사람이 검수하기 쉬운 설명 생성
- 도로 상태, 날씨, 조명, 시야 상태 등 부가 정보 추출
- 학습 데이터 필터링을 위한 참고값 생성

최종 사고 유형 분류는 VideoMAE가 담당하고, Qwen2.5-VL은 데이터 품질 필터 및 설명 보조 모델로 사용한다.

### 2.3 YOLO bbox + 100프레임 + Qwen2.5-VL 입력 방식 검증

Qwen이 사고 장면을 놓치는 문제를 줄이기 위해, 10초 영상에서 프레임을 직접 추출해 Qwen에 이미지 묶음으로 전달하는 방식을 실험했다.

처음에는 48프레임을 사용했으나, 사고 장면이 짧게 지나가는 경우 더 촘촘한 프레임이 필요하다고 판단했다. 이후 약 0.1초 단위로 전체 10초 영상을 확인할 수 있게 했다.

또한 YOLO로 탐지된 객체 bbox를 프레임 위에 표시한 뒤 Qwen에 전달했다. 이 방식은 Qwen이 차량, 보행자, 이륜차, 자전거 등 사고 관련 객체를 더 쉽게 볼 수 있게 하기 위한 목적이다.

현재 가장 효과가 있었던 입력 방식은 다음과 같다.

```text
10초 원본 영상
→ 100프레임 균등 추출
→ YOLO bbox 표시
→ bbox 표시 프레임 이미지 묶음을 Qwen2.5-VL에 입력
```



### 2.4 프레임 정렬 버그 수정

100프레임 실험 과정에서 프레임 파일 정렬 문제가 확인되었다. 기존에는 파일명이 문자열 기준으로 정렬될 수 있어 `frame_100` 계열 파일의 순서가 꼬일 가능성이 있었다.

이 문제를 숫자 기준 정렬로 수정해 Qwen에 실제 시간 순서대로 프레임이 들어가도록 정리했다.

확인된 결과는 다음과 같다.

```text
frame_count_for_qwen = 100
last_frame = frame_99_009.80s.jpg
```

즉, 10초 영상의 마지막 구간까지 Qwen 입력에 포함되는 것을 확인했다.

### 2.5 bbox + 100프레임 실험 결과

라벨별 1개씩 총 4개 샘플에 대해 bbox + 100프레임 방식으로 Qwen2.5-VL을 실행했다.

확인된 결과는 다음과 같다.


| 항목                       | 결과           |
| ------------------------ | ------------ |
| 샘플 수                     | 4개           |
| Qwen JSON 유효성            | 4개 모두 유효     |
| accident_visible         | 4개 모두 True   |
| accident_visibility      | 4개 모두 clear  |
| collision_moment_visible | 4개 모두 True   |
| recommended_use          | 4개 모두 review |


해석은 다음과 같다.

- bbox + 100프레임 입력은 Qwen이 사고 장면을 인식하는 데 효과가 있었다.
- 다만 Qwen은 학습 사용 여부를 판단하는 `recommended_use`에서 여전히 보수적으로 `review`를 출력했다.
- 따라서 Qwen 결과만으로 train/exclude를 확정하지 않고, 사람 검수 결과와 함께 판단해야 한다.



### 2.6 사람 검수용 CSV 구조 추가

Qwen 결과를 바로 학습 데이터로 쓰지 않고, 먼저 소량 샘플에 대해서만 사람이 contact sheet를 확인하며 Qwen 판단이 믿을 만한지 검증할 수 있도록 CSV 구조를 추가했다.

중요한 점은, 사람 검수는 실제 서비스 운영 단계에서 매번 사람이 확인하기 위한 절차가 아니라는 것이다. 이 단계의 목적은 자동 필터링 기준을 만들기 위한 초기 검증이다.

현재 사용 중인 검수용 산출물은 다음과 같다.

```text
bbox_clear_human_review_template.csv
bbox_all_human_review_template.csv
qwen_input_frame_check.csv
qwen_bbox_frame_results.csv
raw_vs_bbox_qwen_compare.csv
bbox_frame_summary.csv
```

사람 검수 시 확인해야 할 주요 컬럼은 다음과 같다.

- `human_judgement`: train / review / exclude
- `human_note`: 사람이 본 판단 근거
- `lighting`: day / night / low_light / tunnel
- `accident_visibility`: Qwen 판단값
- `recommended_use`: Qwen 추천값
- `contact_sheet_path`: 사람이 직접 확인할 프레임 이미지 묶음

이 검수는 라벨별 소량 샘플에서만 진행한다. 사람 검수 결과를 바탕으로 Qwen 프롬프트와 자동 필터링 기준을 보정한 뒤, 전체 데이터에는 자동 필터링을 적용한다.

실제 서비스에서는 사람이 매번 영상을 확인하지 않는다. 서비스 단계에서는 자동 분석을 기본으로 하고, 신뢰도가 낮거나 사고 장면이 불명확한 경우에만 사용자에게 사고 전후가 포함된 5초에서 30초 이내 영상을 다시 업로드하도록 안내한다.

### 2.7 야간 영상 문제 확인

야간 영상에서는 YOLO 객체 탐지가 불안정할 수 있다는 문제가 확인되었다. 원인은 다음과 같다.

- 블랙박스 야간 영상은 노이즈가 많고 대비가 낮다.
- 보행자, 자전거, 이륜차가 어둡게 묻힐 수 있다.
- 헤드라이트, 가로등, 반사광 때문에 bbox가 흔들릴 수 있다.
- 작은 객체는 원본 해상도에서도 잘 보이지 않으며, 모델 입력 과정에서 더 약해질 수 있다.

다만 야간 영상을 모두 밝게 보정해서 원본 대신 학습하는 것은 권장하지 않는다. 실제 추론 시에는 어두운 원본 영상이 들어오기 때문에, 밝게 보정된 영상만 학습하면 실제 입력 분포와 차이가 생길 수 있다.

따라서 원본 야간 영상은 유지하고, augmentation 또는 전처리 비교 실험을 추가하는 방향이 적절하다.

## 3. 앞으로 진행해야 하는 사항



### 3.1 1차 범위 확정

1차에서는 다음 범위까지만 진행한다.

```text
10초 원본 영상
→ 100프레임 추출
→ YOLO bbox 표시
→ Qwen2.5-VL 보조 판단
→ 사람 검수
→ train/review/exclude 분리
→ train 데이터로 VideoMAE 재학습
```

다음 항목은 1차 이후로 미룬다.

- 5초 clip 자동 생성
- 사용자 입력 영상에서 사고 후보 구간 자동 탐지
- 5초에서 30초 이내 사용자 입력 정책 구현
- 30초 초과 영상에 대한 재업로드 요청 로직
- bbox crop 기반 사고 후보 구간 추출 고도화

현재는 10초 원본 영상 기반으로 데이터 품질과 학습 가능성을 먼저 정리하는 것이 우선이다.

### 3.2 사람 검수 진행

가장 먼저 해야 할 일은 `bbox_all_human_review_template.csv`를 열고 contact sheet를 직접 확인하는 것이다.

각 영상에 대해 다음 값을 기록한다.

```text
human_judgement = train / review / exclude
lighting = day / night / low_light / tunnel
human_note = 판단 이유
```

판단 기준은 다음과 같이 둔다.


| human_judgement | 기준                             |
| --------------- | ------------------------------ |
| train           | 사고 또는 사고 직전/직후 상황이 비교적 명확하게 보임 |
| review          | 사고 가능성은 있으나 객체가 작거나 장면이 애매함    |
| exclude         | 사고 장면이 보이지 않거나 학습 신호가 거의 없음    |


이 단계에서 중요한 것은 Qwen의 판단을 그대로 믿는 것이 아니라, 사람이 먼저 기준을 세우는 것이다.

### 3.3 Qwen 프롬프트 기준 수정

사람 검수 결과, 사람이 보기에도 사고가 명확한데 Qwen이 `recommended_use=review`로 보수적으로 판단한다면 프롬프트 기준을 수정한다.

수정 방향은 다음과 같다.

```text
accident_visibility = clear
collision_moment_visible = true
```

위 조건을 만족하고 사람이 보기에도 사고 장면이 명확하다면, Qwen이 `recommended_use=train`을 선택하도록 기준을 강화한다.

다만 프롬프트 수정은 사람 검수 결과를 확인한 뒤 진행한다. 현재 단계에서는 Qwen 출력보다 사람 판단 기준을 먼저 확정하는 것이 중요하다.

### 3.4 라벨별 5개 실험으로 확장

현재는 라벨별 1개, 총 4개 샘플만 확인했다. 다음 단계는 라벨별 5개, 총 20개 샘플로 확장하는 것이다.

목표는 다음과 같다.

- bbox + 100프레임 방식이 라벨 전체에서 안정적으로 작동하는지 확인
- Qwen 결과와 사람 검수 결과가 얼마나 일치하는지 확인
- 야간/저조도 영상에서 bbox가 얼마나 흔들리는지 확인
- train/review/exclude 비율을 대략적으로 파악

이 결과를 보고 라벨별 25개 또는 100개로 확장할지 결정한다.

### 3.5 야간 영상 별도 실험

야간 영상은 별도 실험으로 분리한다. 낮 영상과 야간 영상을 같은 기준으로 평가하면 문제 원인을 찾기 어렵다.

추천 실험 조합은 다음과 같다.

```text
A. 원본 프레임 + YOLO_CONF=0.25
B. 원본 프레임 + YOLO_CONF=0.15
C. CLAHE 보정 프레임 + YOLO_CONF=0.15
```

비교 기준은 다음과 같다.

- 사고 관련 객체가 bbox로 잡히는가
- false positive가 지나치게 늘어나는가
- Qwen이 사고 장면을 더 잘 설명하는가
- 사람이 봤을 때 contact sheet가 더 검수하기 쉬운가

주의할 점은 보정 영상을 원본 대신 사용하는 것이 아니라, 원본은 유지하고 보정 버전을 augmentation 또는 보조 입력으로 추가하는 것이다.

### 3.6 라벨별 25개 또는 100개로 확장

라벨별 5개 실험에서 방향이 안정적이면 라벨별 25개 또는 100개로 확장한다.

이때 확인해야 할 지표는 다음과 같다.

- 라벨별 train/review/exclude 개수
- 주간/야간별 train/review/exclude 개수
- Qwen JSON valid 비율
- Qwen 판단과 사람 판단의 일치율
- 야간 영상에서 bbox 탐지 성공률

이 결과를 기반으로 VideoMAE 학습에 사용할 데이터셋을 정리한다.

### 3.7 VideoMAE 재학습

사람 검수 또는 확정된 기준에 따라 `human_judgement=train`인 영상만 모아 VideoMAE 재학습을 진행한다.

재학습 비교 대상은 다음과 같다.


| 실험            | 설명                               |
| ------------- | -------------------------------- |
| 기존 raw 100 실험 | 라벨별 100개 원본 영상 기반 기존 결과          |
| 기존 raw 700 실험 | 라벨별 700개 원본 영상 기반 기존 결과          |
| 정제 train 실험   | Qwen + 사람 검수로 선별된 train 영상 기반 결과 |
| 야간 보강 실험      | 원본 야간 영상 유지 + augmentation 추가 결과 |


성능 비교는 accuracy만 보지 않고 다음 지표까지 확인한다.

- validation accuracy
- test accuracy
- macro F1-score
- confusion matrix
- 라벨별 precision/recall
- 주간/야간 분리 성능



### 3.8 augmentation 적용

데이터 수를 늘리는 방향은 타당하지만, 야간 영상 전체를 밝게 바꿔서 원본을 대체하면 안 된다. 원본은 유지하고 변형 데이터를 추가하는 방식으로 augmentation을 적용한다.

추천 augmentation은 다음과 같다.

- 밝기 조절
- 감마 조정
- 대비 변화
- 노이즈 추가
- 블러 추가
- 헤드라이트 번짐 효과

예시는 다음과 같다.

```text
원본 야간 영상 1개
+ 밝기 증가 버전 1개
+ 감마 조정 버전 1개
+ 노이즈 추가 버전 1개
```

augmentation은 1차 기준 데이터 정제가 끝난 뒤 적용한다. 먼저 데이터 품질과 학습 기준을 정리한 뒤 augmentation을 넣어야 효과를 판단할 수 있다.

### 3.9 1차 이후 고도화

1차가 끝난 뒤에는 실제 서비스 입력을 고려한 구조로 확장한다.

서비스 입력 정책은 다음과 같이 정리한다.

```text
사용자 입력 영상: 5초 이상 30초 이하
30초 초과 영상: 사고 지점이 포함된 5초에서 30초 이내 영상으로 다시 업로드 요청
```

1차 이후 고도화 단계에서는 다음을 진행한다.

- YOLO/ByteTrack으로 사고 후보 구간 자동 탐지
- bbox overlap, 거리 변화, 객체 급정지/사라짐 등을 활용한 사고 후보 시점 추정
- 후보 시점 기준 5초 clip 생성
- clip 기반 VideoMAE 추론
- Qwen2.5-VL 설명 생성
- Supervisor/Report Agent 연동



## 4. 최종 파이프라인 정리



### 4.1 1차 학습 데이터 정제 파이프라인

```text
10초 원본 영상
→ 100프레임 추출
→ YOLO bbox 표시
→ Qwen2.5-VL로 사고 명확도 보조 판단
→ contact sheet 생성
→ 사람 검수
→ train/review/exclude 분리
→ train 데이터로 VideoMAE 재학습
→ 기존 raw 100/700 결과와 비교
```



### 4.2 최종 서비스 파이프라인

```text
사용자 5~30초 영상 업로드
→ 영상 품질/길이 확인
→ YOLO/ByteTrack으로 객체 탐지 및 추적
→ 사고 후보 구간 또는 주요 프레임 추출
→ VideoMAE 사고 유형 분류
→ Qwen2.5-VL 장면 설명/도로 상태/날씨 상태 추출
→ Supervisor/Report Agent 전달
```

단, 최종 서비스 파이프라인은 1차 이후 단계에서 구현한다.

## 5. 현재 결론

현재는 5초 clip 실험보다 10초 원본 영상 기반 데이터 정제가 우선이다. 1차에서는 사고 장면이 포함된 원본 영상을 기준으로 학습 가능한 데이터와 제외해야 할 데이터를 나누고, 이 데이터를 활용해 VideoMAE 재학습 성능을 확인해야 한다.

Qwen2.5-VL은 사고 유형을 직접 분류하는 최종 모델이 아니라, 학습 데이터 품질을 판단하고 장면 설명을 보조하는 역할로 사용한다. 현재까지는 YOLO bbox + 100프레임 이미지 묶음 방식이 Qwen 입력으로 가장 효과적이었다.

앞으로는 라벨별 소량 샘플만 사람 검수해 Qwen 판단 기준을 보정하고, `Qwen + YOLO bbox + 100프레임` 기반 자동 필터링 기준을 확정한다. 이후 전체 데이터에는 자동 필터링을 적용하고, `train`으로 분류된 데이터만 활용해 VideoMAE를 재학습한다. 실제 서비스에서는 사람 검수 없이 자동 분석을 수행하며, 신뢰도가 낮은 경우에만 사용자에게 사고 전후가 포함된 5초에서 30초 이내 영상을 다시 업로드하도록 안내한다.

## 6. 어제 실험 결과 및 변경 사항 (2026-07-14)



### 6.1 실험 목적

어제 실험의 핵심 목적은 Qwen2.5-VL이 사고 장면을 제대로 보지 못하는 원인을 확인하는 것이었다. 단순히 모델 성능 문제인지, 아니면 Qwen에 전달되는 입력 프레임 자체가 사고 순간을 충분히 포함하지 못하는 문제인지 분리해서 확인했다.

확인한 질문은 다음과 같다.

- 10초 원본 영상에서 사고 순간이 실제로 프레임에 포함되는가
- Qwen video 입력 방식이 사고 순간을 놓치고 있는가
- 프레임 수를 늘리면 사고 장면 인식이 개선되는가
- YOLO bbox를 표시하면 Qwen이 사고 객체를 더 잘 찾는가
- 야간 영상에서는 bbox 탐지가 흔들리는가



### 6.2 실험 1: Qwen video 입력 방식 확인

초기에는 Qwen2.5-VL에 영상을 직접 전달하고 `fps`를 지정하는 방식으로 사고 장면을 분석했다.


| 항목  | 내용                                                            |
| --- | ------------------------------------------------------------- |
| 입력  | 10초 원본 영상                                                     |
| 방식  | Qwen video 입력                                                 |
| 목적  | Qwen이 영상에서 사고 장면을 직접 인식하는지 확인                                 |
| 결과  | 사람이 보기에는 사고가 명확한 영상에서도 `unclear`, `exclude`, `review`가 자주 출력됨 |


이 결과로 보아 Qwen이 사고를 못 보는 이유가 반드시 영상 자체의 문제가 아니라, Qwen 내부 샘플링에서 사고 순간을 놓칠 가능성이 있다고 판단했다.

### 6.3 실험 2: 직접 프레임 추출 방식으로 변경

Qwen 내부 샘플링을 그대로 신뢰하는 대신, 우리가 직접 프레임을 추출해 이미지 묶음으로 Qwen에 전달하는 방식으로 변경했다.


| 항목       | 내용                               |
| -------- | -------------------------------- |
| 입력       | 10초 원본 영상                        |
| 방식       | 직접 프레임 추출 후 Qwen에 이미지 리스트로 전달    |
| 초기 프레임 수 | 48프레임                            |
| 목적       | Qwen이 실제로 보는 입력을 사람이 확인 가능하게 만들기 |
| 결과       | 사고 순간이 프레임에 포함되는지 직접 확인 가능해짐     |


48프레임은 약 0.2초당 1프레임 수준이다. 이 방식으로 사고 순간이 일부 포함되는 것을 확인했지만, 사고 장면이 매우 짧게 지나가는 경우 더 촘촘한 프레임이 필요하다고 판단했다.

### 6.4 실험 3: 100프레임으로 확대

사고 순간이 짧게 지나가는 문제를 줄이기 위해 100프레임으로 확대했다. 10초 영상 기준 약 0.1초당 1프레임을 확인하는 방식이다.


| 항목    | 내용                             |
| ----- | ------------------------------ |
| 입력    | 10초 원본 영상                      |
| 프레임 수 | 100프레임                         |
| 간격    | 약 0.1초당 1프레임                   |
| 확인 결과 | 마지막 프레임이 약 9.80초까지 포함됨         |
| 의미    | 10초 전체 구간이 Qwen 입력에 들어가는 것을 확인 |


확인값은 다음과 같다.

```text
frame_count_for_qwen = 100
last_frame = frame_99_009.80s.jpg
```

이 실험을 통해 Qwen에 전달되는 프레임이 실제로 10초 전체를 커버한다는 점을 확인했다.

### 6.5 실험 4: 프레임 정렬 버그 수정

100프레임 실험 중 프레임 파일명이 문자열 기준으로 정렬되면 순서가 꼬일 수 있는 문제가 있었다. 예를 들어 `frame_100` 계열 파일이 시간 순서가 아니라 문자열 순서로 정렬될 수 있었다.

이를 숫자 기준 정렬로 수정했다.


| 항목     | 변경 전                           | 변경 후                 |
| ------ | ------------------------------ | -------------------- |
| 프레임 정렬 | 문자열 기준 정렬 가능성                  | 프레임 번호/시간 기준 숫자 정렬   |
| 문제     | Qwen 입력 순서가 실제 시간 순서와 달라질 수 있음 | 0초부터 9.8초까지 시간 순서 유지 |
| 영향     | 사고 순간 누락 또는 순서 왜곡 가능           | Qwen 입력 신뢰도 개선       |


이 수정 이후 Qwen 입력 프레임의 시간 범위와 순서가 정상적으로 확인되었다.

### 6.6 실험 5: YOLO bbox 표시 프레임을 Qwen에 전달

Qwen이 사고 객체를 더 쉽게 인식하도록 YOLO bbox가 표시된 프레임을 Qwen에 전달했다.


| 항목    | 내용                                             |
| ----- | ---------------------------------------------- |
| 입력    | 100프레임 이미지 묶음                                  |
| 추가 처리 | YOLO bbox overlay                              |
| 목적    | 차량, 보행자, 이륜차, 자전거 등 사고 관련 객체를 Qwen이 더 쉽게 보도록 함 |
| 비교 대상 | 원본 프레임 Qwen 결과 vs bbox 표시 프레임 Qwen 결과          |


라벨별 1개씩 총 4개 샘플에서 확인된 결과는 다음과 같다.


| 지표                       | 결과           |
| ------------------------ | ------------ |
| 샘플 수                     | 4개           |
| Qwen JSON 유효성            | 4개 모두 유효     |
| accident_visible         | 4개 모두 True   |
| accident_visibility      | 4개 모두 clear  |
| collision_moment_visible | 4개 모두 True   |
| recommended_use          | 4개 모두 review |


해석은 다음과 같다.

- bbox + 100프레임 입력은 Qwen이 사고 장면을 인식하는 데 효과가 있었다.
- 기존 video 입력보다 사고 장면 인식이 개선되었다.
- 다만 `recommended_use`는 여전히 `review`로 보수적으로 출력되었다.
- 따라서 Qwen 판단만으로 학습 데이터를 확정하지 않고 사람 검수를 함께 진행해야 한다.



### 6.7 실험 6: 사람 검수용 contact sheet/CSV 생성

Qwen 결과를 그대로 학습 데이터로 사용하지 않고, 사람이 직접 프레임 묶음을 보고 판단할 수 있도록 검수용 CSV를 생성했다.


| 파일                                     | 목적                          |
| -------------------------------------- | --------------------------- |
| `qwen_input_frame_check.csv`           | Qwen에 들어간 프레임 수와 마지막 프레임 확인 |
| `qwen_bbox_frame_results.csv`          | bbox 프레임 기반 Qwen 판단 결과 저장   |
| `raw_vs_bbox_qwen_compare.csv`         | 원본 프레임과 bbox 프레임 결과 비교      |
| `bbox_frame_summary.csv`               | bbox 프레임 실험 요약              |
| `bbox_clear_human_review_template.csv` | clear로 판단된 샘플 사람 검수용        |
| `bbox_all_human_review_template.csv`   | 전체 샘플 사람 검수용                |


사람 검수 시 기록할 값은 다음과 같다.

```text
human_judgement = train / review / exclude
lighting = day / night / low_light / tunnel
human_note = 판단 이유
```

이 구조를 통해 Qwen 결과와 사람 판단을 비교할 수 있게 되었다.

### 6.8 실험 7: 야간 영상 문제 확인

실험 중 야간 영상에서 YOLO bbox가 제대로 잡히지 않거나 사고 관련 객체가 약하게 잡히는 문제가 확인되었다.

주요 원인은 다음과 같다.

- 야간 블랙박스 영상은 노이즈가 많고 대비가 낮다.
- 보행자, 자전거, 이륜차가 어두운 배경에 묻힐 수 있다.
- 헤드라이트와 반사광 때문에 bbox가 흔들릴 수 있다.
- 작은 객체는 Qwen과 VideoMAE 모두에서 약한 신호가 될 수 있다.

따라서 야간 영상은 낮 영상과 같은 기준으로만 평가하지 않고 별도 실험이 필요하다고 정리했다.

추천 비교 실험은 다음과 같다.

```text
A. 원본 프레임 + YOLO_CONF=0.25
B. 원본 프레임 + YOLO_CONF=0.15
C. CLAHE 보정 프레임 + YOLO_CONF=0.15
```

단, 야간 영상을 모두 밝게 바꿔 원본을 대체하는 방식은 사용하지 않는다. 원본 야간 영상은 유지하고, 보정본은 augmentation 또는 보조 실험으로만 추가한다.

### 6.9 어제 실험으로 변경된 사항


| 기존 방향              | 변경된 방향                      |
| ------------------ | --------------------------- |
| Qwen에 video를 직접 입력 | 직접 추출한 프레임 묶음을 Qwen에 입력     |
| 48프레임 중심 확인        | 100프레임으로 확대                 |
| Qwen 단독 판단 검토      | Qwen + 사람 검수 조합으로 변경        |
| 단순 Qwen 사고 탐지      | YOLO bbox 표시 프레임 기반 Qwen 판단 |
| 전체 영상을 같은 기준으로 평가  | 야간/저조도 영상 별도 표시 및 실험 필요     |
| 5초 clip 실험 병행      | 1차에서는 10초 원본 영상 기준으로 고정     |


결론적으로 어제 실험 이후의 1차 방향은 다음과 같이 정리된다.

```text
10초 원본 영상
→ 100프레임 추출
→ YOLO bbox 표시
→ Qwen2.5-VL 보조 판단
→ contact sheet 기반 사람 검수
→ train/review/exclude 분리
→ train 데이터만 VideoMAE 재학습
```



## 7. 자동화 기준 확정 후 진행 방향

사람 검수는 전체 데이터나 실제 서비스 운영을 사람이 직접 처리하기 위한 절차가 아니다. 현재의 사람 검수는 Qwen 판단 기준을 검증하고 자동 필터링 기준을 만들기 위한 소량 샘플 검증 단계이다.

앞으로 진행 순서는 다음과 같다.

```text
1. 라벨별 소량 샘플만 사람 검수
2. Qwen 판단 기준 보정
3. Qwen + YOLO bbox + 100프레임 자동 필터링 기준 확정
4. 전체 데이터에는 자동 필터링 적용
5. train으로 분류된 데이터만 VideoMAE 재학습
6. 서비스에서는 사람 검수 없이 자동 분석
7. 신뢰도 낮은 경우만 사용자에게 재업로드 요청
```

실제 서비스에서는 사용자가 영상을 업로드하면 자동으로 분석한다. 다만 다음과 같은 경우에는 분석 결과를 확정하지 않고 재업로드 또는 추가 확인을 요청한다.

- 사고 장면이 너무 어둡거나 흐림
- 사고 객체가 너무 작음
- Qwen 판단과 VideoMAE 판단이 충돌함
- 사고 장면이 명확하지 않음
- JSON 파싱 또는 모델 추론 결과가 불안정함

이 경우 사용자에게는 다음과 같이 안내하는 방향이 적절하다.

```text
사고 장면이 명확하지 않아 자동 분석 신뢰도가 낮습니다.
사고 전후가 포함된 5초에서 30초 이내 영상을 다시 업로드해 주세요.
```
