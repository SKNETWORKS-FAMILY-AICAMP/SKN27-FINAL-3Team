# 학습한 ML/DL 모델

## 1. 작성 목적

본 문서는 Vision/DL 파트에서 사용한 머신러닝/딥러닝 모델의 역할을 정리한다. 실제 학습한 모델과 학습하지 않고 추론 또는 전처리에 사용한 모델을 구분한다.

## 2. 모델 요약

| 구분 | 모델 | 학습 여부 | 사용 목적 | 현재 위치 |
|---|---|---|---|---|
| 이미지 분류 | ResNet18 pretrained | 학습 완료 | frame-level 사고 유형 분류 baseline | 기준선 |
| 영상 분류 | VideoMAE | 학습 진행 | clip/raw video 기반 사고 유형 분류 | 핵심 학습 모델 |
| 객체 탐지 | YOLOv8 | 별도 학습 없음 | 차량/보행자 등 객체 탐지 | POC/고도화 |
| 객체 추적 | ByteTrack | 별도 학습 없음 | 객체 이동 흐름 추적 | 긴 영상 clip 고도화 |
| Vision-language | Qwen2.5-VL | 별도 학습 없음 | 장면 설명, 도로/날씨/시야 상태 JSON 생성 | 설명 보조 모델 |

## 3. 실제 학습한 모델

### 3.1 ResNet18 pretrained

| 항목 | 내용 |
|---|---|
| 입력 | 영상에서 추출한 frame image |
| 출력 | 사고 유형 4개 클래스 |
| 학습 목적 | 프레임 이미지 기반 baseline 성능 확인 |
| 장점 | 빠른 학습, 구조 단순, 기준선 확보 용이 |
| 한계 | 영상의 시간 흐름을 직접 반영하지 못함 |

ResNet18은 초기 학습 파이프라인 검증과 기준선 확보를 위해 사용했다. 사고는 시간 흐름이 중요한 문제이므로 최종 핵심 모델보다는 baseline 성격이 강하다.

### 3.2 VideoMAE

| 항목 | 내용 |
|---|---|
| 모델명 | MCG-NJU/videomae-base-finetuned-kinetics |
| 입력 | 5초 clip 또는 원본 10초 raw video에서 추출한 16프레임 |
| 출력 | 사고 유형 4개 클래스 |
| 학습 목적 | 영상 기반 사고 유형 분류 |
| 장점 | 프레임 간 시간 흐름을 반영 가능 |
| 한계 | 입력 frame_count와 체크포인트 구조 제약이 있음 |

VideoMAE는 현재 Vision/DL 파트의 핵심 학습 모델이다. 기존 5초 clip 기반 실험과 원본 raw video 기반 실험을 모두 진행했다.

## 4. 학습하지 않고 사용한 모델

### 4.1 YOLOv8

| 항목 | 내용 |
|---|---|
| 역할 | 객체 탐지 |
| 탐지 대상 | 차량, 보행자 등 사고 장면 객체 |
| 학습 여부 | 별도 학습 없음 |
| 사용 목적 | bbox 탐지, 시각화, 사고 후보 구간 탐색 |

YOLOv8은 사고 유형 분류 모델이 아니라 객체 탐지 모델이다. 현재는 POC 근거 생성과 긴 영상 자동 clip 고도화 후보로 둔다.

### 4.2 ByteTrack

| 항목 | 내용 |
|---|---|
| 역할 | 객체 추적 |
| 입력 | YOLO bbox 결과 |
| 학습 여부 | 별도 학습 없음 |
| 사용 목적 | 객체 이동량 변화 기반 사고 후보 시점 탐색 |

ByteTrack은 YOLO 탐지 결과를 시간 순서로 연결해 객체 이동 흐름을 보는 데 사용한다. 사용자 입력을 5~30초 사고 포함 영상으로 제한하는 1차 MVP에서는 필수 구성은 아니다.

### 4.3 Qwen2.5-VL

| 항목 | 내용 |
|---|---|
| 역할 | Vision-language 추론 |
| 입력 | 사고 영상 또는 샘플 영상 |
| 출력 | 장면 설명 JSON |
| 학습 여부 | 별도 학습 없음 |
| 사용 목적 | 사고 상황, 도로 상태, 날씨/시야 상태, 불확실성 설명 |

Qwen2.5-VL은 사고 유형을 학습하는 모델이 아니라 설명 생성 모델이다. VideoMAE가 분류한 사고 유형에 대해 사람이 읽을 수 있는 근거와 장면 설명을 보완한다. 현재 라벨별 100개 manifest 기반 샘플 12건 확인 결과 JSON 형식은 안정화되었지만, 출력 언어가 영어 중심으로 남고 사고 여부를 단정하는 경향이 있어 Supervisor에는 검증된 보조 근거로만 전달한다.

## 5. 모델 조합 방향

### 5.1 현재 MVP 방향

```text
사용자 입력 영상 5~30초
→ VideoMAE 사고 유형 분류
→ Qwen2.5-VL 장면 설명/도로상태/날씨 추출
→ Supervisor handoff schema 생성
```

현재는 사용자가 사고 지점이 포함된 5~30초 영상을 업로드한다는 전제를 둔다. 따라서 긴 영상에서 사고 지점을 자동으로 찾는 YOLO/ByteTrack은 1차 MVP 필수 요소가 아니다.

### 5.2 고도화 방향

```text
긴 원본 영상
→ YOLOv8 객체 탐지
→ ByteTrack 객체 추적
→ 사고 후보 시점 탐색
→ 5~30초 clip 생성
→ VideoMAE 분류
→ Qwen2.5-VL 설명 생성
```

긴 영상 자동 분석이 필요해지면 YOLO/ByteTrack이 다시 필수 구성으로 들어간다.

## 6. 최종 정리

| 모델 | 최종 판단 |
|---|---|
| ResNet18 | baseline으로 유지 |
| VideoMAE | 사고 유형 분류 핵심 모델 |
| YOLOv8 | 객체 탐지 및 긴 영상 고도화용 |
| ByteTrack | 사고 후보 시점 자동 탐색 고도화용 |
| Qwen2.5-VL | 설명/리포트 생성을 위한 보조 모델 |

현재 학습 결과서에는 ResNet18과 VideoMAE 학습 결과를 중심으로 기록하고, Qwen2.5-VL과 YOLO/ByteTrack은 학습 모델이 아닌 추론/전처리 모델로 구분한다.
