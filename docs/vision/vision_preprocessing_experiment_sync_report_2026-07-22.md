# Vision 분석 진행 방향 및 RunPod 산출물 동기화 보고서

- 작성일: 2026-07-22
- 대상: Vision/DL Agent
- 데이터 기준: 사고 유형 4개 카테고리별 100건, 총 400건 고정

## 기존

### 데이터와 모델

- 사고 유형은 `car_vs_car`, `car_vs_pedestrian`, `car_vs_motorcycle`, `car_vs_bicycle` 4개이다.
- 카테고리별 100건, 총 400건을 Qwen2.5-VL로 분석했다.
- 카테고리별 선정 YOLO는 다음과 같다.

| 사고 유형 | 선정 YOLO |
|---|---|
| 차대차 | `yolov8m.pt` |
| 차대보행자 | `yolo11n.pt` |
| 차대이륜차 | `yolov8m.pt` |
| 차대자전거 | `yolo11s.pt` |

### 기존 전처리와 프레임 선택

- 프레임 밝기 상태를 기록했지만 상태에 따른 처리 분기는 충분하지 않았다.
- 대부분의 프레임에 CLAHE와 unsharp mask 선명화를 동일하게 적용했다.
- 야간 노이즈 제거와 과노출 억제가 명시적으로 분리되지 않았다.
- Qwen 입력 프레임은 주로 영상 전체에서 균등하게 선택된 4개 프레임이었다.
- 충돌 순간이나 객체 움직임 변화가 큰 프레임을 우선 선택하지 못할 수 있었다.

### 기존 Qwen 400건 결과

| 지표 | 결과 |
|---|---:|
| 전체 분석 건수 | 400/400 |
| JSON 정상 파싱 | 351/400 |
| 사고 유형 정답 | 77/400, 19.2% |
| `uncertain` | 167/400 |
| JSON 파싱 오류 | 49/400 |

카테고리별 사고 유형 정답 수는 차대차 63건, 차대보행자 12건, 차대이륜차 0건, 차대자전거 2건이다. 따라서 Qwen의 사고 유형 분류 결과를 최종 자동 분류값으로 사용하는 것은 적절하지 않다. 기존 결과는 비교 기준선으로 보존한다.

### 기존 학습 상태

- VideoMAE는 사전학습 모델을 4개 사고 유형 라벨로 지도 파인튜닝하는 방향이다.
- 과거 기록상 최고 검증 정확도는 56.25%였지만 동일 실험을 재현할 split, 설정, 클래스 매핑 등 핵심 파일이 충분히 보존되지 않았다.
- 이 수치는 1차 POC 결과로만 취급하며 운영 모델 완료 기준으로 사용하지 않는다.
- LLaVA 비교는 일부 고정 test 실험을 시작했으나 현재는 중단하고 결과를 보존했다.

## 현재

### 진행 중인 실험

- 동일한 400개 asset ID를 사용하여 적응형 전처리 Qwen 실험을 별도 폴더에서 실행 중이다.
- LLaVA 실행은 잠시 중단하여 GPU와 시간을 Qwen 전처리 개선 검증에 우선 배정했다.

현재 변경된 전처리는 다음과 같다.

1. 프레임별 밝기와 명암을 측정한다.
2. 야간·저조도 프레임에만 gamma/CLAHE를 적용한다.
3. 야간 노이즈는 bilateral filter로 완화한 뒤 약한 선명화를 적용한다.
4. 과노출 프레임은 gamma 방식으로 밝기를 낮춘다.
5. 정상 프레임은 불필요한 과보정을 줄인다.
6. 시작·종료 프레임과 프레임 차이가 큰 구간을 조합하여 충돌 후보 프레임을 선택한다.
7. 원본 결과와 적응형 전처리 결과를 서로 다른 경로에 저장한다.

### 현재 확인된 제한사항

- 촬영 시점이 사고 차량 블랙박스, 제3자 차량 블랙박스, 제3자 CCTV 중 무엇인지 신뢰할 수 있는 메타데이터가 아직 없다.
- 따라서 현재 실험에는 임의의 `viewpoint` 값을 생성하지 않았다.
- 같은 사고의 유사 영상이 학습과 테스트에 동시에 포함되지 않도록 하려면 `incident_id` 또는 동일 사고 그룹 식별 정보가 추가로 필요하다.
- 전처리 개선이 사고 유형 분류 정확도까지 높인다는 보장은 없으므로 기존 400건과 동일한 평가 조건으로 검증해야 한다.

## 수정방향

### 1단계: 적응형 Qwen 결과 완료 및 기존 결과와 비교

동일한 400건을 사용하여 기존 전처리와 적응형 전처리를 비교한다.

- Accuracy
- Macro F1
- 카테고리별 Precision/Recall
- JSON 성공률과 파싱 오류율
- `uncertain` 및 검토 필요 비율
- 영상당 처리 시간
- 가능하면 day/night/low-light별 성능

단순히 탐지 객체 수가 가장 많은 보정본을 선택하지 않는다. 오탐이 증가할 수 있으므로 정답 라벨 기준 성능, 파싱 안정성, 처리 시간을 함께 비교하여 전처리를 선정한다.

### 2단계: 촬영 시점 메타데이터 보강

400건 manifest에 다음 필드를 추가한다.

| 필드 | 설명 |
|---|---|
| `viewpoint` | `ego_dashcam`, `third_party_dashcam`, `third_party_cctv`, `unknown` |
| `incident_id` | 같은 사고에 속하는 영상 그룹 ID |
| `lighting` | `day`, `night`, `low_light`, `overexposed`, `unknown` |
| `category` | 4개 사고 유형 정답 라벨 |

신뢰할 수 없는 경우 억지로 추정하지 않고 `unknown`으로 둔다. 학습·검증·테스트 분할은 영상 프레임 단위가 아니라 `incident_id` 단위로 수행하고, 각 split에 카테고리와 촬영 시점이 가능한 한 고르게 포함되도록 한다.

### 3단계: 라벨 기반 VideoMAE 파인튜닝

- 적응형 Qwen 비교에서 선정된 전처리 방식을 적용한다.
- 사전학습된 VideoMAE를 4개 사고 유형 라벨로 지도 파인튜닝한다.
- 고정 split, random seed, 클래스 매핑, 전처리 설정, 학습 이력과 체크포인트를 함께 저장한다.
- 고정 test set에서 Accuracy, Macro F1, 카테고리별 Recall, confusion matrix와 저신뢰도 비율을 평가한다.
- 저신뢰도 결과는 강제 분류하지 않고 `unknown` 또는 `requires_review=true`로 처리한다.

### 4단계: Qwen과 LLaVA 비교

- 최종 선정된 전처리를 두 VLM에 동일하게 적용한다.
- 비교 데이터는 한 모델만 400건, 다른 모델은 60건으로 두지 않고 동일한 400건으로 맞춘다.
- 입력 프레임, 프롬프트, 출력 JSON 스키마와 지표도 동일하게 유지한다.
- VLM은 자동 사고 유형 최종 판정보다 상황 설명, 충돌 시점, 객체 관계와 불확실성 생성 역할을 우선한다.

### 5단계: Python 모듈 기반 Vision Agent 완성

- `.py`: 데이터 준비, 전처리, 학습, 추론, 평가, 결과 직렬화
- `.ipynb`: 실행 과정과 결과를 사람이 확인하는 용도
- 자동 분류: VideoMAE
- 객체 탐지: 예측 카테고리별 선정 YOLO
- 상황 설명: 최종 선정 VLM
- 출력: Supervisor 담당자가 소비할 수 있는 안정적인 JSON 계약

Supervisor/Django/Worker 코드는 다른 담당자의 영역이므로 Vision 쪽에서는 모듈과 출력 계약, 예시 fixture까지만 제공한다.

적응형 Qwen은 RunPod에서 진행 중이다. `ALL_DONE` 확인 전에는 중복 실행하지 않는다.
