# 📄 교통사고사실확인원 OCR 파이프라인 (LangGraph) 실행 흐름

## 1. 개요
본 모듈은 사용자가 업로드한 **'교통사고사실확인원'** 이미지를 분석하여 과실 비율 판단에 필요한 핵심 정보를 정형화된 데이터(JSON)로 추출하는 AI 에이전트 파이프라인입니다. 
비용 효율과 처리 속도를 극대화하기 위해 최적화된 최신 Vision LLM(`gpt-5.4-nano`)을 도입하였으며, 개인정보 유출 방지를 위한 자동 마스킹 시스템을 탑재했습니다.

## 2. 전체 실행 흐름도 (LangGraph)

전체 프로세스는 크게 **[OCR 추출 노드]** -> **[문서 판별 및 검증 노드]** 두 단계로 이루어집니다.

### 📍 Step 1: 입력 (Input)
- 사용자가 업로드한 이미지(Base64)와 파일 형식(MIME Type)을 입력받습니다.
- PNG, JPEG 등 지원하는 이미지 형식이 아닐 경우, 불필요한 API 호출을 막고 즉시 **실패(Failed)** 처리합니다.

### 📍 Step 2: 정보 추출 (OCR Node)
- **Vision 모델 호출:** `gpt-5.4-nano` 모델을 호출하여 이미지를 읽습니다. 이때 약도나 불필요한 정보는 무시하고, 사고 장소, 일시, 원인 등 텍스트 정보만 JSON 형태로 100% 강제 추출합니다.
- **개인정보 완벽 차단 (Masking):** 추출된 텍스트 내용 중에 전화번호(010-XXXX-XXXX)나 주민등록번호가 섞여 있을 경우, 정규식을 통해 `[MASKED]` 기호로 영구 치환하여 보안 사고를 원천 차단합니다.

### 📍 Step 3: 문서 판별 (Verification Node)
- 추출된 제목과 발급기관 도장(경찰서장 등)을 분석하여, **"이 문서가 진짜 '교통사고사실확인원'이 맞는가?"**를 100점 만점으로 스코어링합니다.
- 만약 다른 문서(예: 진단서, 영수증)를 잘못 올렸다면 즉시 **실패(Failed)** 처리하고 재업로드를 유도합니다.

### 📍 Step 4: 품질 평가 및 상태 결정 (Evaluator)
추출된 필드의 완성도에 따라 3가지 상태 중 하나를 반환합니다.
- ✅ **Success (성공):** 핵심 정보(사고 일시, 장소, 사고 내용 등)와 보조 정보가 완벽하게 추출된 상태.
- ⚠ **Partial (부분 성공):** 문서가 맞긴 하지만, 이미지가 잘리거나 흐릿해서 핵심 정보 일부가 누락된 상태. (이 경우 Supervisor 에이전트가 사용자에게 "사고 일시가 안 보입니다. 다시 입력해주세요" 라고 질문할 수 있습니다.)
- ❌ **Failed (실패):** OCR 자체 실패 또는 전혀 다른 문서인 경우.

### 📍 Step 5: 최종 반환 (Envelope)
- 다음 단계(과실비율 판단 에이전트 등)에서 바로 사용할 수 있도록 데이터를 규격화된 "봉투(Envelope)" 구조로 감싸서 반환합니다.

---

## 3. 핵심 도입 효과 (Why gpt-5.4-nano?)
철저한 5개 모델 벤치마크 테스트 결과, 프로덕션 모델로 `gpt-5.4-nano`를 채택했습니다.
- **압도적인 가성비:** 기존 무거운 모델 대비 **약 8~13배 저렴한 비용**으로 동일한 수준의 필수 필드 추출률(95%)을 달성했습니다.
- **사용자 경험(UX) 극대화:** 무거운 모델보다 **최대 1.7배 빠른 처리 속도**를 보여주어, 사용자가 사진을 올리고 결과를 기다리는 대기 시간을 대폭 단축했습니다.
- **안정성:** 환각(거짓 정보 생성) 및 개인정보 누출 건수 **0건**으로 엔터프라이즈급 서비스에 즉시 투입 가능한 안정성을 입증했습니다.
