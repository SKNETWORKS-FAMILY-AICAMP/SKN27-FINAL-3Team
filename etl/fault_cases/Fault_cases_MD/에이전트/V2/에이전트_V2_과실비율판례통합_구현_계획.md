# text_ml_case_search Agent V2 구현 계획 - 과실비율 판례 통합

작성 기준일: 2026-07-05

---

## 0. 문서 목적

이 문서는 `text_ml_case_search` Agent V2를 실제 코드에 어떻게 구현할지 정리한다.

RAG V2 계획의 핵심은 아래와 같다.

```text
active source:
  review_case
  fault_ratio_precedent

standby source:
  traffic_precedent

excluded source:
  standard / 인정기준
```

구현 목표:

```text
1. V1 review_case BM25+Nori 검색은 유지한다.
2. fault_ratio_precedent BM25+Nori 검색을 새 source로 추가한다.
3. 두 source 결과를 같은 evidence schema로 변환한다.
4. source quota 기반으로 evidence를 병합한다.
5. Supervisor가 source별 근거 개수를 알 수 있도록 source_summary를 추가한다.
```

---

## 1. 구현 원칙

```text
1. 기존 V1 review_case 파일명은 유지한다.
2. fault_ratio_precedent용 신규 파일만 추가한다.
3. traffic_precedent와 standard는 active pipeline에 연결하지 않는다.
4. fault_ratio_precedent 검색 field는 실제 ES mapping 기준으로만 사용한다.
5. source_summary를 output에 추가한다.
6. BM25 raw score를 source 간 직접 비교하지 않고 quota 기반으로 병합한다.
7. V1 테스트가 깨지면 V2 구현을 멈추고 먼저 복구한다.
```

---


## 8. 5단계 - evidence_merger.py 작성

파일:

```text
rag/evidence_merger.py
```

기본 전략:

```text
review_case 최대 5개
fault_ratio_precedent 최대 5개
final_top_k = 10
source_reference 기준 중복 제거
```

5+5를 기본값으로 두는 이유:

```text
1. Agent V2는 review_case만 강화하는 단계가 아니라 fault_ratio_precedent를 실제 output에 함께 포함하는 단계다.
2. review_case는 심의사례 기반 과실비율 설명에 강하고, fault_ratio_precedent는 판례상 과실상계/책임 제한 설명에 강하다.
3. 두 source의 역할이 다르므로 초기 구현에서는 동일 후보 수를 보장하는 것이 안정적이다.
4. 4+4는 출력이 가볍지만 근거 다양성이 부족할 수 있고, 6+6 이상은 Supervisor 후처리 부담이 커질 수 있다.
5. 5+5 = 총 10개는 active 10개 샘플 실행에서 source별 결과를 비교하기에 적당한 초기 균형값이다.
```

예상 코드:

```python
SOURCE_QUOTA = {
    "review_case": 5,
    "fault_ratio_precedent": 5,
}


def merge_evidence(
    *,
    evidence_by_source: dict[str, list[dict]],
    final_top_k: int = BM25_FINAL_TOP_K,
) -> list[dict]:
    ...
```

BM25 score를 직접 비교하지 않는 이유:

```text
review_case index와 fault_ratio_precedent index는 corpus, field, 문서 길이, analyzer 결과가 다르다.
```

## 15. V2 완료 기준

```text
1. V1 review_case 테스트가 깨지지 않는다.
2. fault_ratio_precedent retriever 테스트가 통과한다.
3. fault_ratio_precedent mapper 테스트가 통과한다.
4. evidence_merger 테스트가 통과한다.
5. unified_retriever 테스트가 통과한다.
6. Agent output에 source_summary가 포함된다.
7. active 10개 실행 결과에서 source_type이 review_case/fault_ratio_precedent로 구분된다.
8. traffic_precedent는 active evidence에 들어가지 않는다.
9. standard는 active evidence에 들어가지 않는다.
10. Supervisor가 V2 output을 V1 계약의 확장으로 해석할 수 있다.
```
