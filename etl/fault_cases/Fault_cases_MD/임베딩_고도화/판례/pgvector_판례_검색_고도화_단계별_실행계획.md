# pgvector 판례 검색 고도화 단계별 실행계획

> 2026-07-20 실행 권한: 사용자 요청에 따라 실행 에이전트가 검수 기준 수립, 산출물 검증, 단계 승인·불승인을 자율적으로 수행한다. 이 권한은 기존 v1 질문지·qrels를 수정하거나 삭제할 권한은 포함하지 않는다.

> 현재 자동 판정: v1 법률관련성 Top-10 기준의 현재 검색 순위 승자는 B-1 키워드 보강안이다. 메타데이터 C의 v1·v2는 품질 게이트 미달로 운영에서 제외하고 별도 연구 경로로 보류한다. 현재 주 실행 경로는 `B-1 → 실패 9개 원인 분리 → B-3 키워드 후보 회수 → 전체 50문항에서 B-1 대 B-3 검색 순위 비교 → W-K 결정 → A·B-1·B-3 고유 판례 Recall@50 비교 → W-C50 Top-50 동결 → 리랭커 → 최종 후보 W-R 결정 → 신규 질문 F 검증 후 운영 결정`이다. 직접사고장면 정답 20개 조건은 메타데이터 C/v3 재개에만 적용하며, 메타데이터를 사용하지 않는 B-3와 리랭커 실행을 막지 않는다.
>
> 사전 파일 형식: 사고상황 분류체계·동의어·키워드 규칙·메타데이터 허용값·충돌 규칙은 모두 **JSON**을 표준으로 한다. 기존 YAML은 내용 보존용 이전 초안이며, 실행·검수·운영 입력으로 사용하지 않는다.

> 작성 기준일: 2026-07-19  
> 대상 코퍼스: 과실비율 판례 987건 / 8,334청크  
> 기준 임베딩 모델: `Qwen/Qwen3-Embedding-4B`, native 2,560차원  
> 실험 성격: 임베딩 모델 선정이 끝난 뒤 수행하는 판례 검색 후속 고도화  
> 실행 단위: 완료된 A·B-1·B-2 참조 → B-3 1회 → W-K 검색 순위 승자 결정 → W-C50 고유 판례 Top-50 동결 → 리랭커 1회 → W-R 최종 후보 결정 → 신규 질문 F 검증. 메타데이터 C·메타데이터 포함 D는 보류한다.

> [!IMPORTANT]
> 기존 `track_a_6models_native_3repeats`는 6개 임베딩 모델 비교 결과이고, `track_b_5models_fixed1024`는 이전 5모델 고정 1,024차원 실험 코드다. 이름 충돌을 피하기 위해 이 문서의 판례 검색 고도화 작업은 **Track C**로 명명한다. 기존 Track A/B의 코드·벡터·검색 결과·질문지·정답지는 수정하거나 덮어쓰지 않는다.

> [!IMPORTANT]
> 이 계획은 판례 검색에만 적용한다. 동일한 공통 질문을 사용하는 인정기준과 심의사례 검색에는 키워드, 판례 메타데이터, 후보 결합 점수 또는 리랭커를 적용하지 않는다. 모든 적용 코드는 `corpus_key == "precedent"`를 확인해야 한다.

## 1. 문서 목적

기존 Qwen3-Embedding-4B 판례 검색은 정답 판례가 있는 질문 34개 중 Top-1 정답 9개, Top-10 정답 22개를 검색했다. 판례 검색에서 큰 사고 주제는 비슷하지만 신호, 진행 방향, 합류·차로변경, 차량 종류와 같은 세부 법률 조건을 충분히 구별하지 못했다.

다만 B-1 실패 9개를 정답 판례 원문과 대조한 결과, 일부 정답은 법률적으로 관련 있어도 현재 색인 청크에 질문의 세부 사고 장면이 직접 들어 있지 않았다. 따라서 기존 정답지를 부정하거나 덮어쓰지 않고, **법률관련성 평가 v1**과 **사고장면 직접일치 평가 v2**를 분리한다.

현재 주 실행 경로의 목적은 다음 두 가지다.

1. B-1의 Top-10 실패 9개를 원인별로 분리하고, 일반화된 B-3 상황 키워드로 **고유 판례 Top-50** 밖 정답 판례를 후보 안으로 회수한다.
2. B-1과 B-3의 검색 순위 승자 W-K를 결정하되, 리랭커 후보 풀은 A·B-1·B-3 중 고유 판례 Recall@50이 가장 안전한 W-C50을 별도로 동결한다. 리랭커는 W-C50의 후보 순서만 다시 비교해 정답 판례를 Top-1에 가깝게 올린다.

메타데이터 C/v3는 이 주 경로의 필수 단계가 아니다. 별도 사건구조 평가셋과 품질 게이트를 갖췄을 때만 독립 연구 경로로 재개한다.

다만 현재 질문지의 정답을 외우는 하드코딩, 특정 판례로 결과가 몰리는 쏠림, 관련도 1의 약한 정답을 강제로 올리는 과적합을 금지한다.

## 1.1 판례 평가축 분리: v1 보존과 v2 신설

| 구분 | 법률관련성 평가 v1 | 사고장면 직접일치 평가 v2 |
|---|---|---|
| 목적 | 질문의 법률 쟁점과 참고 가치가 관련된 판례를 찾는지 평가 | 질문의 차량·행동·도로·신호 관계가 색인 원문에 직접 있는 판례를 찾는지 평가 |
| 현재 입력 | 승인 질문 50개와 기존 qrels | v1 질문을 출발점으로 하되, 원문 근거를 검수해 승인한 질문·qrels·negative 집합 |
| 기존 A/B 결과 | 그대로 보존하고 해석 기준으로 사용 | 재사용하지 않으며 v2 snapshot으로 새로 측정 |
| 정답 승인 조건 | 기존 승인 관련도 기준 | 동일 사고 이벤트의 원문 근거 문장과 사건 관계가 확인됨 |
| 금지 | v2 결과로 v1 qrels 수정·삭제 | Query ID→판례 ID 규칙화, 현재 실패만으로 qrels 구성 |

### 1.1.1 v2 생성 순서

1. 기존 정답 가능 34문항을 전수 감사한다.
2. 각 qrels를 `사고장면 직접 근거 있음`, `법률 쟁점 관련만 있음`, `현재 색인 원문 근거 부족`으로 분류한다.
3. 직접 근거가 있는 후보만 자동 분류로 확정하지 않고, 근거 문장·사건 관계를 사람이 검수한다.
4. 검수 승인된 질문·qrels·negative를 `precedent_scenario_direct_v2` snapshot으로 동결한다.
5. 향후 v2 snapshot의 양성이 충분해질 때만 A·B-1을 다시 측정하고, 그 뒤 C 메타데이터 파일럿을 별도 연구로 진행한다. 현재 B-3·리랭커 경로에는 적용하지 않는다.

### 1.1.3 v2 1차 검수 결과와 제한

- 기존 v1 positive 42건을 기존 `matched_facts`·`different_facts` 기록과 근거 청크 개념 커버리지로 보수적으로 재검수했다.
- 사실 차이가 0건인 `v2_direct_candidate`는 3건(q01-110371, q26-76859, q43-76572)이었다.
- 사실 차이가 있으나 근거가 일부 있는 `v2_unknown`은 27건, 사실 차이가 있고 현재 사고 장면 근거도 약한 `v1_legal_only_candidate`는 12건이었다.
- 이 1차 결과만으로 v2 snapshot을 만들면 positive가 3건으로 지나치게 작아 모델 비교 평가셋으로 사용할 수 없다. 따라서 v2는 현재 **승인 전 진단용 초안**이며, v1의 50문항 성능 결과를 대체하지 않는다.
- v2를 정식 평가로 쓰려면 `v2_unknown` 27건의 핵심 관계를 추가 원천·사람 근거로 검수해 충분한 positive 수를 확보하거나, 별도 사고장면 판례 원천으로 새 질문·정답을 구성해야 한다.

### 2.2 법률관련성 v1 기준선 수치

현재 실행 결과에서 `relevance >= 1`인 정답 가능 질문은 34개다.

| 검색 범위 | 성공 | 실패 | 성공률 | 실패율 |
|---|---:|---:|---:|---:|
| Top-1 | 9개 | 25개 | 26.5% | 73.5% |
| Top-5 | 15개 | 19개 | 44.1% | 55.9% |
| Top-10 | 22개 | 12개 | 64.7% | 35.3% |
| 청크 후보창 50개 | 27개 | 7개 | 79.4% | 20.6% |
| 고유 판례 Top-50 | 30개 | 4개 | 88.2% | 11.8% |

`청크 후보창 50개`는 과거 실행이 상위 청크 50개만 가져온 결과다. 같은 판례의 여러 청크가 포함되므로 판례가 50건이라는 뜻이 아니다. 전체 8,334청크를 점수순으로 확인하고 동일 `case_id`는 최고 점수 청크 하나만 남겨 고유 판례 50건을 채운 값을 `고유 판례 Top-50`과 `Recall@50`의 정식 정의로 사용한다.

기존 A의 청크 후보창에는 질문당 고유 판례가 평균 약 29건만 있었다. 리랭커 입력과 B-3 후보 회수 평가는 반드시 고유 판례 50건 기준으로 새로 생성한다.

| 순위 지표 | 기준선 |
|---|---:|
| MRR@10 | 0.3645 |
| nDCG@10 | 0.3949 |

34개 질문의 중복 없는 상태 분포는 다음과 같다.

| 상태 | 질문 수 | 비율 |
|---|---:|---:|
| Top-1 정답 | 9개 | 26.5% |
| Top-1 오답·Top-10 정답 | 13개 | 38.2% |
| Top-10 오답·고유 판례 Top-50 정답 | 8개 | 23.5% |
| 고유 판례 Top-50에도 정답 없음 | 4개 | 11.8% |

검색이 개선될수록 질문은 아래 흐름에서 오른쪽이 아니라 왼쪽으로 이동해야 한다.

```text
고유 판례 Top-50 실패
  → 고유 판례 Top-50 성공·Top-10 실패
  → Top-10 성공·Top-1 실패
  → Top-1 정답
```

### 2.3 관련도 등급을 분리해 보고한다

현재 qrels는 다음 세 집단을 포함한다.

| 집단 | 질문 수 | 처리 |
|---|---:|---|
| strict positive: relevance 2 이상 존재 | 21개 | 핵심 성능과 리랭커 평가 |
| weak-only: relevance 1만 존재 | 13개 | 별도 참고 지표와 정답지 검토 |
| negative: relevance 1 이상 없음 | 16개 | 오탐·쏠림 검사 |

전체 34개 지표만 보면 약한 관련 판례를 강제로 올리는 문제가 숨을 수 있다. 모든 단계에서 `relevance >= 1` 전체 지표와 `relevance >= 2` strict 지표를 나란히 보고한다.

### 2.4 A 결과 재사용 방식

기존 대용량 벡터와 검색 결과를 Track C로 복사하지 않는다. 새 실행은 `baseline_reference.json`에 기존 경로와 SHA-256만 기록한다.

| Qwen3-4B 문서 임베딩 | 문서 재임베딩 방지 |
| 기존 질문 임베딩 | A 기준선 확인 |
| `raw_top50.jsonl` | 과거 상위 청크 50개 결과 확인용; 고유 판례 Top-50으로 오인 금지 |

단계별 재계산 범위는 다음과 같다.

| 단계 | 문서 임베딩 | 질문 임베딩 | 검색 | 리랭킹 |
|---|---|---|---|---|
| A. 기존 pgvector | 기존 결과 참조 | 기존 결과 참조 | 기존 결과 참조 | 없음 |

| D. 메타데이터 포함 통합 후보 | 재사용 | 재사용 | 현재 보류·운영 입력 금지 | 없음 |

| E-R. 리랭커 | 재사용 | 재사용 | W-C50 고유 판례 Top-50 고정 | 순위만 변경 |

## 3. 공통 안전 원칙

### 3.1 금지사항

- `query_id -> case_id` 직접 매핑
- 판례 ID를 키워드 가점 조건으로 사용
- 정답 판례의 고유 문장을 검색어로 그대로 복사
- 원본 질문을 보강 질문으로 덮어쓰기
- 키워드·메타데이터 하드 필터로 판례를 완전히 제외
- 관련도 1의 약한 정답을 강제로 Top-1로 이동
- 현재 실패 질문만 평가하고 기존 성공·negative 질문을 무시
- 사용자 승인 없이 다음 단계 자동 실행
- Track A/B 코드와 산출물 수정

### 3.2 원본 검색 보존

키워드 검색은 원본 검색을 대체하지 않고 별도 후보 채널로 실행한다.

```text
원본 질문 벡터 후보
  + 키워드 보강 질문 후보
  → A·B-1·B-3의 독립 검색 결과
  → 검색 순위 승자 W-K와 후보 풀 승자 W-C50을 별도 결정
```

메타데이터 후보는 현재 주 실행 경로에 포함하지 않는다. 향후 사건 구조 v3가 별도 품질 게이트를 통과한 경우에만 C/D 연구 경로에서 다시 검토한다.

이 단계에서는 `벡터 70% + 키워드 15% + 메타데이터 15%`와 같은 점수 가중치를 두지 않는다. 키워드 강도는 검색 점수에 더하는 비율이 아니라 **상황 규칙이 요구하는 의미 조건의 구체성**으로 정의한다.

| 키워드 규칙 강도 | 의미 |
|---|---|
| 넓은 규칙 | 대표 사고 개념과 최소 핵심 조건만 요구하며 누락은 적지만 오적용 위험이 큼 |
| 균형 규칙 | 서로 독립된 핵심 조건 2~4개와 행위자 관계를 함께 요구 |
| 엄격한 규칙 | 모든 필수 조건과 핵심 구별 조건까지 요구하며 정밀하지만 표현 차이로 정답을 놓칠 수 있음 |

B단계에서는 동일 시나리오의 넓은·균형·엄격 규칙을 검증해 가장 적합한 구체성을 선택한다. 현재는 B-3까지 키워드 검색만 비교하고, 메타데이터 C와 결합 D는 별도 보류한다. 리랭커는 A·B-1·B-3의 고유 판례 Recall@50을 비교해 확정한 W-C50 후보 풀을 입력으로 사용하므로 C/D 완료를 기다리지 않는다.

### 3.3 단계별 중단

각 단계는 한 번 실행한 뒤 다음을 수행한다.

1. 현재까지 채택된 승자(incumbent)와 비교한다.
2. 최초 기준선 A와 누적 비교한다.
3. 성공·실패·회귀·쏠림을 보고한다.
4. 신규 단계와 기존 승자 중 다음 단계에 사용할 승자를 결정한다.
5. 사용자 승인을 기다리며 중단한다.

| C50 | 고유 판례 Top-50 후보 출처 선택 | A·B-1·B-3 Recall@50 비교 | 각 후보 - A | `W-C50 = A 또는 B-1 또는 B-3` |

| F | 신규 질문으로 A와 최종 후보 W-R 검증 | A 대 W-R 신규셋 | W-R - A | 운영 승인·불승인 판정 |

각 단계는 전체 판례 질문 50개를 1회 평가한다. 기존 모델 A/B 실험의 3회 반복 규칙을 이 후속 고도화에 적용하지 않는다.

### 5.1 승자 유지 원칙

후속 단계라는 이유만으로 자동 채택하지 않는다. 각 단계에서 신규 결과가 더 나쁘거나 유의미한 개선이 없으면 기존 승자를 그대로 유지한다.

```text
A 대 B-1 → B 내부 잠정 후보
B-1 대 B-2 → B-1 유지(완료)
B-1 실패 9개 원인 분리
B-1 대 B-3 전체 50문항 → W-K
A·B-1·B-3 고유 판례 Recall@50 비교 → W-C50
W-C50 고유 판례 Top-50 동결
W-K 대 E-R 전체 50문항 → W-R(최종 후보)
A 대 W-R 신규 질문 F 검증 → 최종 운영 결정
```

B-3가 Top-10을 개선하더라도 기존 성공 회귀, strict 성능 하락 또는 오답 쏠림이 발생하면 검색 순위 승자 W-K는 B-1을 유지한다. B-3가 검색 안전 조건을 통과하고 순위 품질이 우세할 때만 W-K를 B-3로 정한다.

리랭커 후보 풀은 검색 순위 승자와 별도로 정한다. A·B-1·B-3의 고유 판례 Recall@50과 Query별 회귀를 비교해 W-C50을 확정한다. E-R은 W-C50의 고정 후보 50건 밖 문서를 새로 추가하지 않은 채 순서만 변경하며, 최종 순위는 현재 검색 순위 승자 W-K와 비교한다.

### 5.2 승자 판정 기준

승자는 지표 하나의 최고값만으로 정하지 않는다. 먼저 다음 안전 조건을 검사한다.

- 입력·정답·기준선 무결성 오류 0건
- 기존 Top-10 성공 회귀 0건 원칙
- 서로 다른 사고유형의 동일 오답 판례 쏠림 없음
- negative 질문 오탐의 설명되지 않은 증가 없음
- strict positive 성능 악화 없음 원칙

안전 조건을 통과한 결과끼리는 단계 목적에 맞춰 판정한다.

| 단계 | 1차 판정 지표 | 2차 판정 지표 | 동률·미미한 개선 시 |
|---|---|---|---|
| B-1·B-2 | Top-10 성공·실패, 기존 성공 회귀 | Top-50, Top-1, MRR@10, nDCG@10 | 기존 승자 유지 |
| B-3 검색 순위 | Hit@10, 기존 성공 회귀 | Hit@1·5, MRR@10, nDCG@10, 쏠림 | B-1 유지 |
| C50 후보 풀 | 고유 판례 Recall@50, 후보 회수 회귀 | 후보 다양성, 검색시간 | A의 후보 풀 유지 |
| E-R | Hit@1, MRR@10 | Hit@5·10, nDCG@10, 기존 성공 회귀, 지연·비용 | W-K 유지 |
| C·D | 메타데이터 품질 게이트 | 별도 연구 지표 | 현재 보류 |

제안 목표를 달성했더라도 안전 조건을 위반하면 자동 승자로 채택하지 않는다. 반대로 특정 지표가 조금 낮더라도 단계의 핵심 목표와 안전 조건에서 우세한 경우에는 Query별 변화표와 근거를 공개하고 사용자가 최종 승인한다.

### 5.3 승자 결정 보고표

각 단계 종료 시 다음 형식으로 승자 결정 근거를 남긴다.

| 비교 | 기존 승자 | 신규 후보 | Top-1 변화 | Top-10 변화 | 고유 판례 Top-50 변화 | 기존 성공 회귀 | 오답 쏠림 | 결정 |
|---|---|---|---:|---:|---:|---:|---|---|
| A 대 B-1 | A | B-1 | +1건 | +3건 | -1건 | 1건(q37) | Top-10 통과·후보 풀 미통과 | B-1은 검색 순위 승자만 유지 |
| B-1 대 B-2 | B-1 | B-2 | 0건 | 0건 | 정식 고유 판례 기준 미재계산(과거 청크 후보창은 0건) | 1건 | 검사 | B-1 유지 |
| B-1 대 B-3 | B-1 | B-3 | 실험값 | 실험값 | 실험값 | 실험값 | 검사 | W-K |

| W-K 대 E-R | W-K | W-C50 리랭커 | 실험값 | 실험값 | W-C50 고정 | 실험값 | 검사 | W-R |

## 7. 키워드 사전 생성·검수 계획

### 7.1 생성 책임

키워드 사전은 사용자가 직접 작성하지 않는다. 실행 에이전트가 정답·오답 판례를 분석해 초안을 만들고, 선정 근거와 오적용 위험을 공개한다. 사용자는 초안을 승인하거나 수정 요청한다. 승인 전에는 검색에 적용하지 않는다.

### 7.2 사전 구성

질문 하나에 키워드 하나를 연결하거나 `Query ID → 규칙 → 정답 판례`로 연결하지 않는다. 키워드 사전은 여러 질문과 신규 질문에 재사용할 수 있도록 **사고 진행 유형**과 **상황 구성 요소**의 두 층으로 설계한다.

#### 7.2.1 1차 분류: 사고 진행 유형

| 사고 진행 유형 | 대표 상황 |
|---|---|
| 교차로 통행 | 직진 대 직진, 좌회전 대 직진, 신호·비신호 교차로 |
| 차로변경 | 변경 차량 대 변경 차로의 선행·후행 직진 차량 |
| 본선 합류 | 진입로·가속차로 합류 차량 대 본선 직진 차량 |
| 추돌 | 주행 차량 대 정상 정차·감속·고장 정차 차량 |
| 회전 | 좌회전·우회전 차량 대 직진·추월 차량 |
| 유턴·중앙선 | 유턴·중앙선 침범 차량 대 정상 진행 차량 |
| 도로 진출입 | 도로 외 장소·주차장·골목에서 본선 도로로 진입 |
| 보행자·개문·주정차 | 횡단, 보도 침범, 문 열림, 출차, 주정차 주변 사고 |

`차로변경`과 `본선 합류`, `교차로 진입`과 `도로 외 장소 진입`처럼 법률상 의무와 사고관계가 다른 상황은 같은 규칙으로 합치지 않는다.

#### 7.2.2 2차 분류: 상황 구성 요소

| 분류 | 예시 |
|---|---|
| 도로 환경 | 고속도로, 일반도로, 교차로, 진입로, 주차장 |
| 교통 통제 | 신호 있음·없음, 적색점멸, 황색점멸, 일시정지 표지 |
| 사용자 행동 | 직진, 차로변경, 합류, 좌·우회전, 유턴, 정차 |
| 상대 행동 | 직진, 추월, 차로변경, 진입, 정차 |
| 차량 관계 | 선행·후행, 본선·진입로, 좌측·우측 접근 |
| 차량 종류 | 자동차, 이륜차, 자전거, 보행자 |
| 진행 방향 | 동일 방향, 대향 방향, 교차 방향 |
| 충돌 형태 | 추돌, 측면 충돌, 정면 충돌 |
| 특수 조건 | 야간, 시야 제한, 불법주정차, 급정지 |
| 법률 쟁점 | 우선통행, 안전거리, 진로변경 의무, 일시정지 의무 |

사고 진행 유형 하나를 중심으로 여러 상황 요소가 함께 발동할 수 있다. 예를 들어 `차로변경` 시나리오에 `후행차`, `이륜차`, `동일방향`, `측면충돌` 속성을 붙인다. 서로 모순되는 두 사고 진행 유형이 동시에 발동하거나 핵심 문맥이 모호하면 자동 적용하지 않고 `review_required: true`로 보낸다.

#### 7.2.3 규칙 구성 단위

각 시나리오 규칙에는 개수를 기계적으로 고정하지 않고 다음 의미 단위를 둔다.

- 대표 시나리오 코드와 사람이 읽는 이름
- 반드시 일치해야 하는 필수 개념군
- 있으면 구별력이 높아지는 선택 개념군
- 반대 상황을 식별하는 충돌·배제 개념군
- 각 개념을 판별하는 동의어와 문맥 조건
- 질문과 판례에서 확인한 근거 문구
- 넓은·균형·엄격 규칙안과 각 규칙의 선정·기각 근거
- 신뢰도, 검토 필요 여부, 활성 상태

규칙의 강도는 키워드 점수의 퍼센트가 아니다. 다음처럼 의미 조건의 구체성을 조절한다.

| 규칙안 | 구성 원칙 | 주된 위험 |
|---|---|---|
| 넓은 규칙 | 대표 개념과 최소 필수 조건만 요구 | 관련 없는 상황에도 발동할 수 있음 |
| 균형 규칙 | 서로 독립된 필수 조건과 행위자·상대방 관계를 함께 요구 | 문맥 분석 오류 시 일부 누락 가능 |
| 엄격한 규칙 | 모든 필수 조건과 핵심 구별·충돌 조건까지 확인 | 판례 표현 차이 때문에 정답 누락 가능 |

가장 엄격한 규칙을 자동 채택하지 않는다. 정답 회수, 오답 발동, 기존 성공 회귀, negative 오탐, 신규 표현 일반화를 함께 비교해 시나리오별로 가장 적합한 규칙안을 승인한다.

### 7.3 동의어 개념군과 중복 방지

#### 7.3.1 대표 개념으로 정규화

같거나 실질적으로 같은 표현은 하나의 대표 `concept_id`에 연결한다.

```json
{
  "concept_id": "vehicle_motorcycle",
  "representative_name": "이륜차",
  "aliases": ["이륜차", "오토바이", "원동기장치자전거", "이륜자동차"]
}
```

질문이나 판례에 `이륜차`와 `오토바이`가 모두 등장해도 `vehicle_motorcycle` 개념은 한 번만 일치한 것으로 기록한다. 동의어 개수와 출현 횟수를 적합성이나 강도의 증가로 계산하지 않는다.

#### 7.3.2 문맥 의존 표현

`진입`처럼 문맥에 따라 의미가 달라지는 단어는 전역 동의어로 합치지 않는다.

| 표현과 문맥 | 정규화할 개념 |
|---|---|
| 진입로·가속차로 + 본선 + 직진차량 | 본선 합류 |
| 골목길·주차장 + 일반도로 | 도로 외 장소 진입 |
| 교차로 + 신호·통행방향 | 교차로 진입 |

문맥을 충분히 확인할 수 없으면 `unknown` 또는 `ambiguous`로 남기며 임의로 하나의 상황에 배정하지 않는다.

#### 7.3.3 중복 계산 금지 규칙

- 하나의 `concept_id`는 질문·판례 각각에서 최대 한 번만 인정한다.
- 긴 구체 표현을 짧은 부분 표현보다 먼저 인식한다.
- 상위 시나리오와 하위 속성을 같은 의미로 두 번 계산하지 않는다. 예: `고속도로 본선 합류`는 `본선 합류` 시나리오와 `고속도로` 속성으로 분리한다.
- 동일 문구를 여러 개념에 무조건 중복 배정하지 않는다.
- 서로 독립된 사실 근거가 확인된 경우에만 복수 개념 태그를 허용한다.
- 동의어 출현 횟수, 문서 길이, 같은 표현의 반복은 일치 강도를 높이지 않는다.
- 개념군 간 동의어가 겹치면 문맥 우선순위와 충돌 규칙을 명시하고, 해결되지 않으면 자동 적용하지 않는다.

2. 질문과 판례 양쪽에서 근거를 확인할 수 있는지
3. 특정 Query가 아닌 여러 질문과 신규 표현에 재사용할 수 있는지
4. 동의어와 문맥 조건을 안정적으로 정의할 수 있는지
5. 비슷하지만 법률 조건이 다른 반대 상황을 구별할 수 있는지
6. 판례번호, case ID, 과실비율 또는 정답 결론을 직접 노출하지 않는지

### 7.5 관련도 1 정답 처리

q06·q36·q41·q44는 관련도 1의 약한 정답이며 질문과 판례 사이에 핵심 사실 차이가 있다.

| q06 | 정답 판례에 적색·황색점멸 조합과 당사자 관점이 명확하지 않고 주된 법률 쟁점도 다름 |

### 7.6 키워드 사전 파일

사람이 검수하고 Python이 읽는 사전은 JSON으로 관리하며, Query별 발동 결과는 JSONL로 기록한다. YAML 파일은 이전 초안 보존용이며 실행 입력에서 제외한다.

```json

  enabled: false
  confidence: low
  review_required: true
  scenario_concept_id: maneuver_mainline_merge
  representative_name: 본선합류
  concept_groups:
    road_context:
      required: true
      concept_id: road_expressway
      aliases: [고속도로, 자동차전용도로]
    entering_actor_action:
      required: true
      concept_id: action_merge_into_mainline
      aliases: [본선 합류, 본선으로 진입]
      context_required: [진입로 또는 가속차로, 본선]
    counterpart_action:
      required: true
      concept_id: action_mainline_straight
      aliases: [본선 직진, 주행차로 진행]
    collision_shape:
      required: false
      concept_id: collision_side
      aliases: [측면 충돌, 옆부분 충돌]
  conflict_concepts:
    - maneuver_lane_change
    - action_exit_mainline
  rule_variants:
    broad: 대표 개념과 최소 필수 문맥
    balanced: 도로환경·합류행동·본선직진 관계 동시 확인
    strict: 모든 필수 관계와 충돌 개념 부재까지 확인
  selected_variant: null
  selection_evidence: null
  restrictions:
    direct_query_id_mapping: false
    direct_case_id_mapping: false
    count_aliases_once_per_concept: true
```

## 8. 판례 메타데이터 구축 계획

### 8.1 구축 규모와 단위

현재 판례 코퍼스는 987건, 8,334청크다.

| 청크 유형 | 개수 |
|---|---:|
| reasoning | 6,491 |
| holding | 801 |
| summary | 796 |
| main_text_fallback | 246 |

메타데이터는 평면 태그만 붙이지 않고 다음 계층으로 구축한다.

```text
청크의 근거 문장
  → 사고 이벤트
  → 판례 case_id 단위 통합 메타데이터
```

태그 근거는 청크에 남기고, 실제 후보 적합성 판정은 판례 단위 메타데이터를 사용한다.

### 8.2 기존 원본과 파생 메타데이터 분리

기존 판례 원문·청크·기술 메타데이터는 수정하지 않는다. 검색용 파생 메타데이터는 별도 버전으로 생성한다.

모든 생성물에는 다음을 기록한다.

- 입력 판례·청크 SHA-256
- 메타데이터 스키마 버전
- 추출 규칙 버전
- 생성 시각
- 근거 chunk_id
- 근거 문장
- 추출 방식
- 신뢰도
- 검수 상태

### 8.3 메타데이터 스키마

#### 도로 환경

- 일반도로, 고속도로, 자동차전용도로
- 교차로, 주차장 출입구, 진입로, 진출로
- 사거리, 삼거리
- 같은 폭, 넓은 도로 대 좁은 도로
- 주행차로, 추월차로, 가속차로
- 야간, 우천, 결빙 등 특수조건

#### 신호·교통통제

- 신호기 있음·없음
- 녹색·황색·적색
- 적색점멸·황색점멸
- 중앙선·황색실선·황색점선
- 양보·일시정지 표지

#### 참여 차량

- 자동차, 화물차, 버스
- 이륜차, 자전거
- 보행자, 기타, 불명

판례의 원고·피고를 질문의 사용자·상대방으로 직접 매핑하지 않는다. 중립적인 `actor_01`, `actor_02`를 사용한다.

#### 차량 행동

- 직진, 좌회전, 우회전, 유턴
- 차로변경, 본선 합류, 진출로 이탈
- 추월, 정차, 후진
- 도로 외 장소에서 진입

#### 차량 간 관계

- 선행·후행
- 대향
- 우측·좌측 도로 진입
- 변경 대상 차로 후행
- 본선 차량과 진입 차량
- 같은 방향 우측 진행
- 교차 진행·추월 관계

#### 충돌 형태와 법률 쟁점

- 후방·측면·정면·교차·연쇄 충돌
- 양보, 안전확인, 전방주시, 안전거리 확보
- 일시정지, 서행, 우측차 우선, 선진입 우선
- 본선차 우선, 중앙선 침범, 사고 후 안전조치

### 8.4 평면 태그 대신 사고 이벤트·관계를 보존한다

판례 하나에 선행사고와 후속 추돌이 함께 있을 수 있다. 단순 합집합은 서로 다른 사고의 태그를 하나로 잘못 결합한다.

```json
{
  "case_id": "171923",
  "events": [
    {
      "event_id": "event_01",
      "event_type": "prior_accident"
    },
    {
      "event_id": "event_02",
      "event_type": "secondary_collision",
      "road_type": "highway",
      "maneuvers": ["stopped", "rear_end"],
      "legal_issues": ["post_accident_safety_measures"]
    }
  ]
}
```

차량 종류와 행동도 관계로 묶는다.

```json
{
  "actors": [
    {"actor_id": "actor_01", "vehicle_type": "car", "maneuver": "right_turn"},
    {"actor_id": "actor_02", "vehicle_type": "motorcycle", "maneuver": "straight"}
  ],
  "relations": [
    {
      "subject_actor": "actor_02",
      "relation": "following_on_right_side",
      "object_actor": "actor_01"
    }
  ]
}
```

이 구조를 사용해야 자동차 우회전·이륜차 직진과 자동차 직진·이륜차 우회전을 구별할 수 있다.

### 8.5 질문 메타데이터

질문에도 판례와 동일한 구조의 도로, 신호, 차량, 행동, 관계와 법률 쟁점을 생성한다.

판례 actor 방향은 고정하지 않고 두 방향을 모두 비교한다.

```text
질문 사용자 ↔ 판례 actor_01, 질문 상대 ↔ actor_02
질문 사용자 ↔ 판례 actor_02, 질문 상대 ↔ actor_01
→ 더 잘 일치하는 방향을 사용
```

### 8.6 생성 절차

1. 입력 스냅숏과 메타데이터 버전을 동결한다.
2. holding, summary, reasoning, fallback에서 근거 문장을 추출한다.
3. 명시적 표현은 Python 규칙으로 high 태그 후보를 만든다.
4. 차량 주체·행동·상대관계를 사고 이벤트로 연결한다.
5. 정보가 없으면 `unknown`으로 두고 추측하지 않는다.
6. 같은 case_id의 여러 청크를 이벤트 단위로 통합한다.
7. 인용 판례 사실과 현재 판례 사실이 섞이지 않았는지 검사한다.
8. 충돌·과다·근거 누락 태그를 검수 대상으로 분리한다.

메타데이터 생성기는 Query ID, qrels, 관련도, 기존 검색 순위와 정답 여부를 읽지 않는다. 실패 분석은 스키마에 필요한 필드를 찾는 용도로만 사용한다.

### 8.7 신뢰도와 검색 적용

| 신뢰도 | 기준 | C단계 처리 |
|---|---|---|
| High | 판례 사실관계에 직접 명시되고 근거 문장 존재 | 승인 후 메타데이터 후보 생성에 사용 가능 |
| Medium | 여러 문장을 결합하면 충분히 추론 가능 | 저장·감사만 수행 |
| Low | 단어만 있거나 주체·관계 불명확 | 미적용 |
| Conflict | 청크·이벤트 간 충돌 | 검수 전 미적용 |

`unknown`은 불일치가 아니므로 배제하거나 불일치로 판정하지 않는다. 질문과 판례가 명시적으로 반대일 때만 `conflict` 근거를 기록하며, 이를 순위에 어떻게 사용할지는 D단계에서 결정한다.

### 8.8 파일럿·전체 생성·검수

메타데이터 작업을 검색 실행과 분리한다.

1. 스키마 설계: 필드·허용값·충돌 규칙만 작성
2. 파일럿: 실패 Query의 정답 및 Top-1~Top-3 오답 판례에 태그 생성
3. 전체 생성: 판례 987건·청크 8,334개 처리
4. 검수·동결: high 태그 승인, medium/low/conflict 비활성
5. C 검색 실험: 승인된 High 메타데이터만 사용해 독립 후보와 적합성 등급 생성

필수 전수검수 대상:

- 실패 Query의 정답 판례
- 실패 Query의 Top-1~Top-3 오답 판례
- 충돌 태그 판례
- 여러 사고 이벤트가 있는 판례
- high이지만 근거가 모호한 판례

전체 987건에서는 사고유형·차량·신호·법률 쟁점별 층화 표본 약 100건을 추가 검수한다.

### 8.9 메타데이터 자체 품질 게이트

| 지표 | 초기 통과 기준 |
|---|---:|
| 태그 근거 문장 보유율 | 100% |
| High 태그 표본 정확도 | 95% 이상 |
| 차량 행동·관계 정확도 | 90% 이상 |
| 근거 없는 추론 태그 | 0건 |
| Query ID·정답 정보 사용 | 0건 |
| 미검수 충돌 태그 검색 적용 | 0건 |
| Low 태그 검색 적용 | 0건 |
| 다른 이벤트 태그의 잘못된 결합 | 검수 대상 전부 해소 |

커버리지를 높이려고 조건을 억지로 추론하지 않는다. `unknown` 비율도 품질 지표로 공개한다.

#### 8.9.1 2026-07-20 High 태그 100건 검수 결과

- 태그별 희소 규칙을 포함하도록 만든 층화 표본 100건을 원문 청크 문맥과 전수 대조했다.
- 승인 69건, 거절 30건, 보류 1건이며 보류 제외 정확도는 **69.7%**로 High 기준 95%에 미달했다.
- 행위·관계 태그는 승인 38건, 거절 19건으로 **66.7%**이며 기준 90%에 미달했다.
- `confidence: high`는 확률·문맥 검증·사람 승인이 아니라 alias 문자열 일치에 고정 부여된 값이므로 신뢰도 컬럼으로 사용하지 않는다.
- 검수완료본에서는 이를 `legacy_confidence`로만 보존하고, 근거 방식은 `evidence_level: explicit_lexical_match`, 최종 판정은 `human_review`로 분리한다.
- 부분 문자열 충돌, 동형어, 보험약관 문맥, 사건 시점 혼동, 위치와 차량 관계 혼동이 확인됐으므로 현재 C-2 운영 승인은 **불승인**이다.
- 이 100건은 규칙군 안전성 진단을 위한 개념별 층화 표본이므로 전체 8,904개 태그의 빈도가중 정확도 추정치로 해석하지 않는다.
- 상세 판정은 `04_metadata_tagging/03_validation/메타데이터_High태그_표본100건_검수완료.jsonl`, 집계는 `메타데이터_High태그_표본100건_검수요약.json`, 해석은 `C2_메타데이터_High태그_100건_전수검수_보고서.md`에 보존한다.

#### 8.9.2 문맥 규칙 v2 생성과 독립 표본 최종 판정

- v1 오탐을 줄이기 위해 문장 경계·교통사고 문맥·행위 표현을 함께 확인하는 v2를 별도 생성했다.
- 전체 987개 판례·8,334개 청크의 태그 근거는 v1 8,904건에서 v2 2,749건으로 줄었다. 이는 커버리지보다 오탐 억제를 우선한 결과다.
- v1 검수에서 거절된 30개 복합키의 v2 재발은 0건이고, 중복 키·근거 없는 태그·`confidence` 컬럼은 모두 0건이다.
- 개발 표본 RC1 100건은 승인 89건·거절 11건으로 89.0%였으며, 이 결과를 사용해 규칙을 한 번 수정했다.
- v1 검수표와 RC1 모두에 포함되지 않은 최종 독립 표본 100건을 원문 전체 문맥으로 다시 검수한 결과 승인 **86건**, 거절 **14건**, 정확도 **86.0%**였다.
- 행위·관계 태그는 **88.6%**로 별도 기준 90%에도 미달했다. 도로·환경은 80.8%, 차량은 86.7%였다.
- 새 오탐은 추격 중 선행 행동과 실제 충돌의 시점 혼합, 일반 법리·보험·제품 설명과 사건 사실의 혼합, 부정 행위 인식, 관계 귀속 실패에 집중됐다.
- 두 서로 다른 표본이 모두 95% 기준을 통과하지 못했으므로 v2는 **운영 불승인**한다. 파일은 삭제하지 않고 실패 실험 감사용으로 동결하되 B-1 검색, C 메타데이터 후보, D 결합, 리랭커 입력에는 사용하지 않는다.
- 최종 독립 표본의 14건을 보고 v2 정규식을 다시 맞추지 않는다. 같은 표본 재보정은 검증셋을 학습 자료로 바꿔 이후 정확도를 과대평가한다.
- 후속 v3를 만들 경우 단순 키워드 규칙을 추가하지 않고 `사건 경계`, `행위자`, `행동`, `대상`, `시점`, `부정`, `명제 종류(사실·주장·법리·가정)`를 구조화하고, 현재 표본과 겹치지 않는 새 홀드아웃에서 다시 승인받는다.

## 9. B단계: 키워드 보강 검색

### 9.1 적용 원칙

- 원본 질문 검색과 상황 키워드 보강 질문 검색을 별도로 수행한다.
- 원본 결과는 항상 보존하고 B 결과가 A 결과를 덮어쓰지 않는다.
- 키워드 강도를 퍼센트, 단어 반복 횟수 또는 임의의 가점으로 표현하지 않는다.
- 보강 질문에는 대표 개념과 승인된 상황 관계를 자연스러운 한 문장으로 한 번씩만 넣는다.
- 같은 `concept_id`의 동의어가 여러 개 감지되어도 대표 개념 하나만 사용한다.
- 키워드로 판례를 완전히 제외하지 않는다.
- q06·q36·q41·q44 관련 규칙은 비활성 상태로 유지한다.
- B에서 벡터 점수와 키워드 점수를 혼합하지 않는다. 채널 결합은 D에서 결정한다.

예를 들어 원문 질문에 `고속도로 본선 합류` 규칙이 발동하면 다음처럼 의미 조건의 구체성이 다른 보강 질문안을 만든다.

| 규칙안 | 보강 내용 예시 |
|---|---|
| 넓은 | 고속도로에서 본선으로 합류하는 사고 |
| 균형 | 진입로 차량이 본선으로 합류하고 상대 차량은 본선을 직진하는 사고 |
| 엄격 | 고속도로 진입로·가속차로 차량이 본선으로 합류하고 본선 차량이 직진하며 일반 차로변경은 아닌 사고 |

세 규칙안은 같은 실행을 확률적으로 반복하는 것이 아니라 **서로 다른 규칙의 적합성을 비교하는 결정적 실험안**이다. 각 보강 질문은 동일 Qwen3-Embedding-4B 모델로 한 번만 임베딩하고 동일 판례 벡터에서 검색한다.

### 9.2 규칙 구체성 선택 절차

1. 전체 질문 50개에 넓은·균형·엄격 규칙을 가상 발동한다.
2. 가상 발동 결과에서 동의어 중복, 문맥 오판, 규칙 충돌을 먼저 제거한다.
3. Gate 1-2에서 가상발동 검증을 통과한 시나리오별 `selected_variant`를 동결한다.
4. 동결된 선택 규칙을 동시에 적용한 보강 질문을 한 번 생성하고, A와 동일한 Qwen3-Embedding-4B·문서 벡터·정답지로 B 검색을 한 번 수행한다.
5. A 대비 정답 회수·오적용·기존 성공 회귀·오답 쏠림을 비교해 B-1을 잠정 후보로 기록한다.
6. 엄격 규칙이 표현 차이로 정답을 놓치면 다음 B 재시도에서 균형 또는 넓은 규칙으로 낮추되, 기존 B 결과를 덮어쓰지 않는다.
7. 넓은 규칙이 관련 없는 상황에 발동하면 다음 B 재시도에서 균형 또는 엄격 규칙으로 높인다.
8. 세 규칙안 모두 안전하지 않으면 해당 규칙을 수정하거나 `enabled: false`로 둔다.
9. B-1의 발동 조건은 유지한 채, 자연어 보강 문장의 사고 관계·행위자·법률 쟁점 표현을 더 구체화한 B-2를 별도 버전으로 실행한다. B-2도 8개만 따로 채점하지 않고 승인 질문지 50개 전체를 검색·평가한다. 보강 8개 외 42개는 원문을 그대로 사용한다.
10. B-1 대 B-2 비교에서는 nDCG@10·Hit@1·5·10·MRR@10, Top-1/Top-10 성공·실패 건수, 기존 Top-10 성공의 하락, 미보강 42문항 순위 변화, 특정 판례 쏠림을 함께 표로 확인한다.
11. B-2가 B-1보다 개선되고 회귀가 없을 때만 B-2를 채택한다. 그렇지 않으면 B-1을 유지한다. 현재 결과에서는 B-1을 유지했으며, 다음 단계는 C가 아니라 실패 기반 B-3다.

### 9.2.1 B-2 강도 비교 실행 결과와 현재 승자 B-1 확정

- B-2는 B-1과 동일한 8개 발동 조건을 사용하고, 보강 문장만 더 구체적으로 바꿔 승인 질문지 50개 전체를 평가했다. 비보강 42개 질문은 원문을 유지했다.
- B-2는 q09를 Top-10 밖에서 10위로 개선했으나, B-1에서 10위였던 q43을 Top-10 밖으로 하락시켰다.
- 두 변화가 상쇄되어 B-1과 B-2의 Hit@1·5·10, MRR@10, nDCG@10은 모두 동일했다. 당시 `Recall@50`으로 기록한 값도 같았지만 이는 상위 청크 50개 후보창 기준이다. B-2의 정식 고유 판례 Recall@50은 재계산하지 않았으며, 현재 후보 풀 결정은 A·B-1·B-3만 대상으로 한다.
- B-2에 기존 Top-10 성공 회귀가 1개 있으므로 안전 조건을 통과하지 못했다.
- 따라서 현재 키워드 승자는 **B-1**로 확정한다. 다음 주 실행은 C가 아니라 B-3이며, B-1을 비교 기준으로 사용한다.

따라서 모든 시나리오에 동일한 강도를 강제하지 않는다. 예를 들어 `정상 정차 후방추돌`은 엄격 규칙, `차로변경 후행 이륜차`는 균형 규칙, 정답 근거가 약한 `고속도로 본선합류`는 비활성으로 결정될 수 있다.

### 9.2.2 B-3 실패 기반 키워드 후보 회수 계획

B-3는 B-1 키워드를 단순히 더 강하게 만드는 단계가 아니다. B-1에서 Top-10 정답을 찾지 못한 9개를 정답의 현재 고유 판례 후보 위치에 따라 분리하고, **고유 판례 Top-50 밖 정답을 후보 안으로 회수하는 것**을 우선 목표로 한다.

분리 근거는 B-1 질문 벡터와 전체 8,334개 문서 청크를 exact cosine으로 다시 정렬하고, 동일 `case_id`의 최고 점수 청크만 남겨 50개 고유 판례를 채운 결과다. 과거 `b_raw_top50.jsonl`은 청크 50개뿐이므로 분리 근거로 사용하지 않는다. B-1의 고유 판례 Recall@50은 **29/34(85.3%)**이고 실패는 아래 5개다.

| B-1 실패 유형 | Query | 수 | B-3 처리 |
|---|---|---:|---|
| 정답이 고유 판례 Top-50 밖 | q21, q29, q36, q37, q41 | 5개 | 일반화된 상황 키워드로 후보 회수 시도 |
| 정답이 고유 판례 Top-50 안·Top-10 밖 | q06(26위), q09(11위), q44(32위), q45(16위) | 4개 | 후보를 보존하고 W-C50 확정 후 리랭커 대상으로 이관 |

A 기준선의 고유 판례 Recall@50은 **30/34(88.2%)**이며 q37 정답은 44위였다. B-1에서는 q37이 고유 판례 Top-50 밖으로 밀렸고 B-1이 새로 회수한 정답은 0개다. 따라서 B-1은 Top-10 검색 순위 승자이지만 리랭커 후보 풀 승자로 자동 채택하지 않는다.

#### B-3 규칙 생성 원칙

1. 실패 9개의 질문·정답 판례·Top-1 오답·고유 판례 Top-50 후보를 대조해 누락된 사고 조건을 찾는다.
2. Query ID, 정답 `case_id`, 정답 판례의 고유 문장을 실행 규칙에 넣지 않는다.
3. 규칙은 신호 상태, 도로 구조, 차량 종류, 양측 진행 방향, 합류·진입·차로변경 관계처럼 다른 질문에도 적용 가능한 대표 개념으로 작성한다.
4. 동의어는 하나의 `concept_id`로 정규화하며 같은 개념을 반복하거나 검색어 비중을 숫자로 가중하지 않는다.
5. 정답 원문에 질문의 세부 장면 근거가 부족하면 억지 규칙을 만들지 않고 `insufficient_evidence`로 기록한다.
6. B-3는 승인된 50개 질문 전체를 검색한다. 실패 9개만 따로 채점하지 않는다.
7. B-1에서 성공한 25개 Top-10 질문과 정답이 없는 16개 negative 질문의 회귀·오탐·쏠림을 함께 검사한다.

#### B-3 실행과 비교 순서

```text
B-1 결과 동결
  → 실패 9개 원인·현재 정답 위치 분리
  → B-3 규칙 JSON 작성·가상 발동 검수
  → B-3 전체 50문항 1회 검색
  → B-1 대 B-3 전체 50문항 비교
  → 검색 순위 승자 W-K 확정
  → A·B-1·B-3 고유 판례 Recall@50 비교
  → 후보 풀 승자 W-C50 확정
  → W-C50의 Query별 고유 판례 Top-50과 SHA-256 동결
```

비교표에는 다음 값을 실제 건수와 비율로 함께 기록한다.

- Top-1·5·10·50 성공과 실패
- Recall@50, MRR@10, nDCG@10
- 고유 판례 Top-50 밖에서 안으로 회수된 Query와 회수 규칙
- B-1 Top-10 성공에서 실패로 내려간 Query
- 정답이 고유 판례 Top-50 안에서 밖으로 밀려난 Query
- strict·weak-only·negative 분리 결과
- 특정 오답 판례 Top-1 집중도와 후보 다양성
- 평균·P95 검색시간과 오류율

B-3가 Top-10 순위 품질을 개선하고 기존 Top-10 성공 회귀가 0건이며 strict 성능과 negative 안전성을 해치지 않을 때만 `W-K = B-3`로 승인한다. 그렇지 않으면 `W-K = B-1`을 유지한다.

후보 풀 승자 W-C50은 별도로 정한다. B-3가 A의 고유 판례 Recall@50 30/34 이상이고 A에서 회수된 정답을 잃지 않으며 후보 다양성·지연 안전 조건을 통과하면 B-3 또는 B-1을 채택할 수 있다. 그렇지 않으면 `W-C50 = A`로 유지한다.

### 9.2.3 후보 풀 승자 W-C50 고유 판례 Top-50 동결

W-K 검색 순위 승자와 W-C50 후보 풀 승자가 결정되면 리랭커 실행 전에 다음 입력을 변경 불가능한 snapshot으로 저장한다.

- 전체 50문항의 고유 판례 Top-50 후보와 W-C50 원래 순위
- 후보별 `case_id`, 대표 `chunk_id`, 코사인 유사도, 후보 출처
- 정답 가능 34문항의 최초 정답 순위
- 질문·qrels·판례 코퍼스·키워드 규칙 JSON의 SHA-256
- W-K 검색 순위 결정표, W-C50 후보 풀 결정표와 회귀·쏠림 검사 결과

고유 판례 Top-50은 다음 절차로 생성한다.

1. 질문과 전체 8,334청크의 코사인 유사도를 계산한다.
2. 유사도 내림차순, 동률이면 `document_id` 오름차순으로 결정적으로 정렬한다.
3. 같은 `case_id`에서는 가장 먼저 나온 최고 점수 청크만 유지한다.
4. 서로 다른 `case_id`가 정확히 50개가 될 때까지 계속 수집한다.
5. 각 판례의 대표 청크와 원래 청크 순위·판례 순위를 함께 저장한다.
6. 50개를 채우지 못한 질문이 있으면 리랭커 실행을 중단한다.

리랭커 개발 중에는 이 고유 판례 Top-50에 문서를 추가하거나 삭제하지 않는다. 이로써 후보 회수 개선과 후보 내부 순위 개선의 효과를 분리한다.

규칙 선택 보고서에는 시나리오별로 다음 표를 만든다.

| 시나리오 | 규칙안 | 필수 개념·관계 | 적용 Query 수 | 정답 회수 | 오적용 | 기존 성공 회귀 | 오답 쏠림 | 신규 표현 통과 | 결정 |
|---|---|---|---:|---:|---:|---:|---|---|---|
| 예시 | 넓은 | 대표 개념 중심 | 실험값 | 실험값 | 실험값 | 실험값 | 검사 | 검사 | 채택·기각 |
| 예시 | 균형 | 핵심 관계 포함 | 실험값 | 실험값 | 실험값 | 실험값 | 검사 | 검사 | 채택·기각 |
| 예시 | 엄격 | 구별·충돌 조건 포함 | 실험값 | 실험값 | 실험값 | 실험값 | 검사 | 검사 | 채택·기각 |

강도를 넓은 → 균형 → 엄격 순서로 검증하되 중간 단계에서 쏠림이나 회귀가 발견됐다는 이유만으로 전체 B를 종료하지 않는다. 문제가 난 규칙안의 발동 근거를 수정하거나 기각하고, 수정된 다음 규칙안을 다시 가상 발동한다. 최종적으로 안전하게 채택할 규칙이 없는 시나리오만 비활성화한다.

### 9.3 B - A 비교

- Top-1·5·10·50 성공 수·성공률
- Top-1·5·10·50 실패 수·실패율
- Top-50 밖에서 안으로 들어온 Query
- Top-10 실패에서 성공으로 바뀐 Query
- 기존 성공에서 실패로 바뀐 Query
- Query별 첫 정답 순위와 코사인 변화
- 선택 규칙별 발동 질문 수와 Query별 보강 문장
- Gate 1-2의 넓은·균형·엄격 가상발동 결과 및 선택 근거
- 동일 개념 동의어 중복 계산 0건 여부
- 문맥 의존 표현의 오분류와 `unknown` 처리 수
- 고유 Top-1 판례 수와 특정 판례 쏠림
- negative 16개 오탐 변화
- 평균·P95 검색시간

B가 통과되지 않으면 사전과 규칙 구체성만 수정하고 B를 다시 평가하며 C로 넘어가지 않는다. B가 통과되면 시나리오별 대표 개념, 동의어, 문맥 조건과 `selected_variant`를 동결하고 C에서는 변경하지 않는다.

## 10. C단계: 승인 메타데이터 적용

> **현재 상태: 운영 불승인·별도 연구 경로 보류.** 이 절은 과거 설계와 재개 조건을 보존하기 위한 기록이며, 현재 B-3 → 리랭커 주 실행 경로의 선행조건이 아니다. v1 C-2는 정확도 69.7%, 문맥 규칙 v2는 독립 표본 정확도 86.0%로 모두 95% 게이트에 미달했으므로 어떤 태그도 W-C50 후보 또는 리랭커 입력에 넣지 않는다.

C는 B를 무조건 계승하지 않는다. A 대 B에서 결정된 현재 승자 W1의 검색 결과를 기준으로 승인 메타데이터 적합성 판정을 추가한다. B가 패했더라도 승인된 사고상황 분류체계와 동의어 개념군은 메타데이터 스키마에 재사용하되 B의 검색 순위는 계승하지 않는다.

v1은 법률관련성 평가로 보존한다. 사고장면 직접일치 관계 태그의 C 성능 평가는 `precedent_scenario_direct_v2` snapshot이 승인된 뒤에만 수행한다. v2 전수 감사에서 직접 사고 근거가 없는 판례는 C의 관계 태그 실패·성공 분모에 넣지 않으며, v1 결과와 별도 표로 보고한다.

### 10.1 메타데이터 적합성 등급

C단계에서도 임의의 퍼센트 가중치를 사용하지 않는다. B에서 승인한 상황 개념을 판례 메타데이터의 사건·행위자·관계 구조와 비교해 다음 등급을 만든다.

| 적합성 등급 | 판정 기준 |
|---|---|
| 관계 일치 | 핵심 사고유형과 양측 행위자·행동·상대관계가 모두 일치 |
| 핵심 일치 | 사고유형과 주요 행동은 일치하지만 일부 보조 속성이 `unknown` |
| 부분 일치 | 일반 주제는 같지만 행위자 관계 또는 핵심 조건이 부족 |
| 명시적 충돌 | 합류 대 일반 차로변경, 좌회전 대 우회전처럼 결론을 바꿀 조건이 반대 |
| 판단 보류 | 근거 부족, 복수 이벤트 충돌 또는 주체 불명확 |

도로유형, 신호, 차량종류, 충돌형태를 몇 퍼센트로 더하는 방식은 C에서 사용하지 않는다. 대신 각 시나리오별로 무엇이 필수 관계이고 무엇이 선택 속성인지 명시한다. C 결과는 메타데이터 후보 채널과 적합성 등급으로 보존하며, 다른 채널과의 결합은 D에서만 결정한다.

C의 성능 비교용 순위는 W1의 Top-50을 대상으로 다음 결정 규칙을 사용한다.

1. `관계 일치 → 핵심 일치 → 부분 일치 → 판단 보류 → 명시적 충돌` 순으로 적합성 등급을 정렬한다.
2. 같은 적합성 등급 안에서는 W1의 기존 순위를 그대로 유지한다.
3. 메타데이터가 `unknown`인 후보를 검색에서 제외하지 않는다.
4. 독립 메타데이터 채널에서 새로 발견한 후보는 감사용으로 보존하되 C 순위에 바로 합치지 않는다.
5. W1 밖 후보와 원본·키워드·메타데이터 후보의 합집합은 D에서만 처리한다.

이 방식으로 C는 수치 가중치 없이 메타데이터 관계 판정 자체가 순위에 도움이 되는지 검증할 수 있고, D와 역할도 분리된다.

### 10.2 관계 일치 우선

`자동차`, `이륜차`, `우회전`, `직진`의 개별 태그가 모두 같아도 누가 우회전하고 누가 직진했는지가 반대면 다른 사고다. 개별 태그 일치보다 `차량 종류 + 행동 + 상대관계` 묶음의 일치를 우선한다.

B의 동의어 개념군을 메타데이터에도 동일하게 재사용한다. 예를 들어 `오토바이`와 `이륜차`가 각각 태그로 생성되어도 대표 개념 `vehicle_motorcycle` 하나로만 저장하며, 같은 의미의 중복 태그가 적합성 등급을 높이지 않게 한다.

### 10.3 C 재개 시 비교와 별도 승자 결정

### 10.3.1 C단계 과거 분석과 현재 보류 상태

- 기존의 넓은 명시 개념 기반 C-1/C-2는 탐색 결과로만 보관한다. C-1은 Hit@10을 25/34에서 23/34로 낮춰 기각됐다. C-2는 High 태그 100건 원문 검수에서 정확도 69.7%, 행위·관계 정확도 66.7%로 각각의 품질 게이트 95%·90%를 통과하지 못했으므로 **W2 결정 근거로 사용하지 않는다.**
- C의 과거 분석 시작점은 B-1에서 남은 Top-10 실패 9개와 Top-1 오답 24개의 정답 판례·상위 오답 판례 원문 대조였다. 이 결과는 보류 근거로만 보존하며 B-3 실행 규칙에 자동 전달하지 않는다.
- 대조에서 `정답을 특정 판례 ID로 보내는 규칙`은 만들지 않는다. 정답과 오답을 구별한 도로 문맥, 양측 차량, 양측 행동, 진행 관계를 관계 필드·허용값·충돌 규칙으로 일반화한다.
- 실패 기반 파일럿은 대조 대상 49개 판례에 직접 근거가 모두 있는 관계만 생성해 시험한다. 엄격한 기준에서는 9개 Top-10 실패 중 q06만 정답·상위 오답을 구별했고, 나머지 8개는 단일 청크에 양측 행위자·행동·진행관계가 함께 명시되지 않아 `insufficient_evidence`로 남겼다. 이 결과를 근거로 관계 조건을 완화하거나 전체 987건에 적용하지 않는다.
- 다음 설계 확인으로 사건 개요(summary) 청크만을 동일 사고 이벤트 범위로 제한해 재검증했다. 이 안전한 범위에서는 9개 Top-10 실패 중 정답·상위 오답을 구별한 관계가 0개였다. 즉, 사건 개요 자체에 관계 근거가 부족하고 판단 이유 청크를 단순 병합하면 오탐 위험이 있다는 뜻이다.
- 정답 판례 색인 근거 감사에서도 High 관계 근거는 1/9개(q06)에만 있었고, 질문 대표 개념의 절반 미만만 현재 색인 텍스트에 확인된 정답 판례가 4/9개였다. 이는 C 규칙 선택 이전에 승인 정답과 현재 검색 입력 청크의 사고 사실관계 정렬을 점검해야 한다는 근거다.
- 원본의 `판례내용` 필드를 현재 사용 중인 `이유`와 비교한 결과도 9개 모두 질문 개념 커버리지가 동일했고, `판례내용`을 추가해 새로 확보되는 질문 핵심 개념은 0/9개였다. 따라서 단순 재청킹이나 필드 추가로 이 근거 부족을 해결할 수 없으며, 승인 없이 재임베딩하지 않는다.
- 따라서 C 재개 전에는 사람 검수 근거 라벨을 만들지, 또는 별도의 사건 관계 추출기를 도입할지 먼저 결정한다. 어느 경우든 청크를 무조건 합치거나 부족한 관계를 추론해 전체 987건에 채우지 않는다.
- 문맥 규칙 v2까지 전체 987건·8,334청크를 생성했으나 독립 표본 품질 게이트에 실패했으므로 전체 태그를 운영 승인하지 않는다.
- C를 재개하려면 사건 구조 기반 v3 설계 → 현재 표본과 겹치지 않는 새 품질 검수 → 전체 정확도 95%·행위관계 90% 통과 → W-K와 별도 50문항 비교 순서로 새 승인을 받아야 한다.

C는 W1의 Top-50 집합을 유지하므로 C의 Top-50 성공 수는 원칙적으로 W1과 같다. C의 직접 효과는 Top-50 안의 정답을 Top-10·Top-1에 더 가깝게 올리는지로 판단한다. 독립 메타데이터 채널의 추가 Top-50 회수 가능성은 별도 감사 지표로 보고하고 실제 합집합은 D에서 검증한다.

- 단계별 성공 수·성공률과 실패 수·실패율
- 태그 때문에 새로 성공한 Query와 악화된 Query
- 반대 조건 오답이 감소한 Query
- Query별 정답 순위 변화
- 관계 일치·핵심 일치·부분 일치·충돌·보류 후보 수
- 태그 정확도·완성률·unknown 비율
- 적용된 일치·충돌 태그와 근거
- 동의어 중복 태그와 상충 개념 발생 수
- 특정 판례 쏠림과 규칙 과다 발동
- 검색시간 변화

현재는 C 승자를 결정하지 않는다. 향후 재개하더라도 현재 W-K와 별도 비교하며, 품질 게이트와 검색 안전 조건을 모두 통과하지 못하면 W-K를 그대로 유지한다.

## 11. D단계: 통합 후보 검색

> **현재 상태: 보류.** 이 절의 D는 승인 메타데이터 후보까지 포함하는 통합 실험이므로 메타데이터 v2 불승인 상태에서는 실행하지 않는다. B-3는 D를 대신하는 메타데이터 없는 키워드 후보 회수 단계이며, A·B-1·B-3를 비교해 확정한 W-C50 고유 판례 후보 풀을 E-R 리랭커에 전달한다.

### 11.1 후보 생성

다음 후보를 독립적으로 생성한다.

1. 원본 pgvector 후보
2. 키워드 보강 후보
3. 승인 메타데이터 후보

각 후보의 출처와 원래 순위, 발동 규칙, 대표 개념, 메타데이터 적합성 등급을 보존한다. 점수 범위가 다른 cosine, 규칙 결과와 메타데이터 등급을 그대로 더하지 않는다.

D를 시작하기 전에 다음 결합안을 같은 입력 후보로 비교하는 설계표를 먼저 작성하고 사용자의 승인을 받는다.

1. 후보 합집합 후 원본 벡터 순위로 정렬
2. 채널별 순위만 사용하는 동일 조건 RRF
3. 메타데이터 적합성 등급을 우선하고 벡터 순위로 동률 해소

B와 C에서는 숫자 가중치를 사용하지 않는다. D에서도 먼저 가중치 없는 결합안을 비교하며, 채널별 가중 RRF나 수치 점수 혼합은 가중치 없는 방식의 한계가 확인되고 사용자가 별도로 승인한 경우에만 후속 실험으로 추가한다.

```text
벡터 후보
키워드 후보  → 승인된 무가중 결합 규칙 → 통합 판례 Top-50
메타데이터 후보
```

### 11.2 D단계 우선 목표

리랭커가 정답을 올리려면 정답이 후보 안에 있어야 하므로 D단계에서는 Hit@1보다 Recall@50을 우선한다.

| 지표 | A 기준선 | 제안 목표 |
|---|---:|---:|
| 고유 판례 Recall@50 | 30/34, 88.2% | 최소 31/34, 91.2% |
| 고유 판례 Top-50 실패 | 4개 | 3개 이하 |
| Hit@10 | 22/34, 64.7% | 최소 28/34, 82.4% |
| 기존 Top-10 성공 회귀 | 0개 | 0개 원칙 |

목표치는 통과 판단용 제안값이며 실제 결과를 목표에 맞추기 위해 정답을 하드코딩하지 않는다.

### 11.3 D - W2 비교와 W3 결정

- Recall@50과 Top-50 성공·실패
- Hit@10과 Top-10 성공·실패
- 정답이 새로 후보에 들어온 Query
- 정답을 회수한 후보 채널
- Query별 고유 판례 후보 수
- 중복 청크로 인한 후보 다양성 손실
- 기존 성공 회귀와 특정 판례 쏠림
- 평균·P95 검색시간

D는 사건 구조 메타데이터가 별도 승인된 경우에만 재개한다. 현재 실행에서는 이 절의 W2·W3를 생성하지 않으며, A·B-1·B-3에서 확정한 W-C50 고유 판례 Top-50을 사용한다.

## 12. E-R단계: 후보 풀 승자 W-C50 리랭커

### 12.1 역할

리랭커는 A·B-1·B-3의 고유 판례 Recall@50 비교에서 확정된 W-C50의 고정 후보 50건 순위만 바꾼다. 후보 밖의 정답을 새로 만들 수 없으므로 고유 판례 Top-50 밖 실패는 B-3 결과에서 먼저 분석하고, 리랭커 성능 분모와 별도로 보고한다.

적용 대상:

- W-K의 Top-1 오답·Top-10 정답 질문
- W-C50 안·W-K Top-10 밖 질문
- B-3에서 새롭게 Top-50에 들어온 정답
- W-K의 기존 Top-1·Top-10 성공 순위 유지 검사

### 12.2 입력

- 원본 질문
- 질문에서 추출한 사고 조건
- 판례 사건 개요·사실관계
- 판결요지·핵심 판단 이유

불승인된 메타데이터 v1·v2 태그는 입력하지 않는다. 리랭커가 사고 조건을 사용할 경우 질문과 후보 원문을 실행 시점에 직접 비교한 판단만 사용하고, 해당 판단 근거 문장을 결과에 보존한다.

판례 전체 원문을 무조건 넣지 않고 판례 단위 대표 정보를 구성한다.

### 12.3 판단 기준

| 비교 항목 | 중요도 |
|---|---|
| 사용자 행동과 판례 actor 행동의 일치 | 매우 높음 |
| 상대 행동과 판례 actor 행동의 일치 | 매우 높음 |
| 신호 상태 일치 | 매우 높음 |
| 법률 쟁점 일치 | 매우 높음 |
| 차량 종류·진행 관계 일치 | 높음 |
| 도로 유형 일치 | 높음 |
| 충돌 형태 일치 | 보통 |
| 전체 의미 유사도 | 보통 |

질문과 판례의 actor 방향은 두 방향으로 비교한다. 합류 대 일반 차로변경, 우회전 대 좌회전, 자동차 대 자전거처럼 결론을 바꾸는 명시적 반대 조건은 감점하되 후보를 완전히 제거하지 않는다.

초기 점수 구조:

```text
최종 리랭킹 점수
= 의미 기반 리랭커 점수
+ 사고 조건 일치 점수
+ 법률 쟁점 일치 점수
+ 기존 후보 순위 보조점수
- 핵심 조건 충돌 감점
```

구체 가중치는 개발 질문에서 후보를 만들고 신규 검증 질문을 보기 전에 동결한다.

### 12.4 학습·검증 자료

| 자료 | 용도 |
|---|---|
| relevance 2~3 승인 판례 | Positive |
| 기존 Top-1 오답 | Hard Negative |
| Top-10 내 유사 오답 | Hard Negative |
| 조건이 명백히 다른 판례 | 일반 Negative |
| relevance 1 판례 | 약한 참고, 강한 Positive로 사용 금지 |
| 신규 질문·정답 | 최종 일반화 검증 |

### 12.5 실행 자원 게이트

리랭커 모델, 실행 장치, 예상 VRAM·시간·비용을 먼저 보고한다. GPU, RunPod 또는 외부 API가 필요하면 사용자 승인 전에 실제 실행하지 않는다.

### 12.6 E-R - W-K 비교와 W-R 결정

- Top-1·5·10 성공·실패 수와 비율
- MRR@10·nDCG@10
- 오답 Top-1이 정답으로 바뀐 Query
- 기존 정답 Top-1이 오답으로 바뀐 Query
- Query별 정답 순위 변화
- strict와 weak-only 분리 성능
- 특정 판례 쏠림 변화
- 평균·P95 리랭킹 추가시간
- 오류율과 비용

### 13.3 Query 상태 이동

각 단계에서 다음 네 상태를 중복 없이 집계한다.

- 실패 → 성공
- 성공 → 성공
- 성공 → 실패
- 실패 → 실패

```text
순개선 = 실패 → 성공 수 - 성공 → 실패 수
```

성공률만 올랐더라도 기존 성공 Query가 악화되면 Query 목록과 원인을 공개한다.

### 13.4 절대·상대 개선

```text
절대 개선폭(%p) = 개선 후 비율 - 개선 전 비율
상대 개선율(%) = (개선 후 비율 - 개선 전 비율) / 개선 전 비율 × 100
```

보고서에는 백분율만 쓰지 않고 실제 질문 수를 함께 표시한다.

```text
예시: Hit@1 9개 → 17개, +8개
26.5% → 50.0%, +23.5%p, 상대 +88.9%
```

### 13.5 쏠림 감시

같은 판례가 여러 질문의 Top-1에 등장했다는 이유만으로 쏠림이라고 판정하지 않는다. 동일 판례가 실제 정답이고 사고유형·행위자 관계·법률 쟁점도 같은 질문들이 그 판례로 모이는 것은 **정상적인 정답 수렴**이다. 서로 관련 없는 사고유형이 같은 **오답 판례**로 몰릴 때만 오답 쏠림으로 판단한다.

| 지표 | 의미 |
|---|---|
| 고유 Top-1 판례 수 | 다양한 질문이 서로 다른 판례를 찾는가 |
| 특정 판례 최대 Top-1 등장 수 | 한 판례가 결과를 독점하는가 |
| Query 간 Top-10 중복률 | 서로 다른 질문의 후보가 지나치게 같은가 |
| 규칙별 발동 질문 수 | 하나의 규칙이 과도하게 넓은가 |
| 평균 고유 판례 후보 수 | 같은 판례 청크가 후보를 점유하는가 |
| negative 오탐률 | 정답 없는 질문에 억지 판례가 생기는가 |

다음 상황은 단계 실패 또는 규칙 재검토 사유다.

- 기존 Top-1 성공이 오답으로 변경
- 기존 Top-10 성공이 Top-10 밖으로 이동
- 두 개 이상의 서로 다른 사고 진행 유형에 속하는 질문 3개 이상이 동일한 오답 판례를 Top-1으로 선택
- 규칙을 더 구체적으로 바꿔도 정답 순위는 개선되지 않고 동일 오답 판례의 순위만 반복 상승
- 고유 Top-1 판례 수가 급격히 감소
- 일반어 하나가 많은 Query에 발동
- negative 질문의 오탐 증가

쏠림 여부를 보고할 때는 `동일 판례 등장 횟수`만 제시하지 않고, 해당 질문들의 사고 진행 유형, 규칙, 정답 여부와 핵심 관계가 실제로 같은지 대조표로 공개한다.

## 14. 신규 질문 일반화 검증 F

A 기준선 Top-1 실패 25개와 B-1 Top-1 실패 24개를 포함한 현재 50문항은 규칙·리랭커 설계 과정에서 이미 본 개발 데이터다. 같은 질문에서 점수가 올랐다는 사실만으로 운영을 확정하지 않는다.

신규 검증셋에는 다음을 포함한다.

- 기존 실패 유형과 같은 사고의 새로운 표현
- 비슷한 키워드를 포함하지만 법률 조건이 다른 반대 사례
- 차량 주체가 뒤바뀐 사례
- 합류와 일반 차로변경을 구별하는 사례
- 자동차·이륜차·자전거를 구별하는 사례
- 점멸 신호 조합이 다른 사례
- 관련 판례가 없는 질문

신규 질문지와 정답지 초안은 검색 실행 전에 별도로 검수·동결한다. 현재 50문항에서 결정한 W-R은 **최종 후보**일 뿐 운영 확정안이 아니다. 최종 검증은 신규셋에 A와 W-R을 각각 1회 적용해 비교하며, 신규셋의 성능·회귀·쏠림 게이트까지 통과한 뒤에만 운영안으로 확정한다. E-R이 W-K보다 나빠 채택되지 않았다면 E-R이 아니라 유지된 W-K를 W-R로 사용한다.

## 15. Elasticsearch 도입 조건

Elasticsearch는 A~F의 필수 단계가 아니다. 현재 987건·8,334청크에서는 PostgreSQL, pgvector, Python 기반 B-3 키워드 후보 회수와 리랭커를 먼저 검증한다. 불승인된 판례 메타데이터를 Elasticsearch 도입 근거로 사용하지 않는다.

다음이 수치로 확인될 때만 후속 계획으로 검토한다.

- PostgreSQL 방식으로 한국어 키워드 후보 회수가 충분하지 않음
- 판례 규모가 크게 증가함
- 복잡한 전문검색과 운영 모니터링이 필요함
- 후보 검색 지연이 허용 범위를 초과함

## 19. 실행 요청 문구

현재 다음 실행 요청은 아래 문구로 시작한다.

```text
B-1 실패 9개를 고유 판례 Top-50 밖 5개와 안 4개로 분리한 근거를 확인하고,
Gate 3의 B-3 실패 기반 일반화 규칙 JSON과 전체 50문항 가상 발동 검증을 진행해.
정답 case_id 직접 매핑과 수치 가중치는 사용하지 말고 결과를 보고해.
```

Gate 3 통과 후 실제 검색은 다음처럼 요청한다.

```text
Gate 4의 B-3 전체 50문항 검색을 1회 실행하고 B-1과 비교해.
Top-1·5·10, MRR@10, nDCG@10, 기존 성공 회귀, negative 오탐과 판례 쏠림을 비교해 검색 순위 승자 W-K를 결정해.
A·B-1·B-3의 고유 판례 Recall@50과 Query별 후보 회귀도 별도로 비교해 W-C50을 결정해.
```

W-K와 W-C50 확정 후에는 다음처럼 진행한다.

```text
W-C50의 전체 50문항 고유 판례 Top-50과 입력 SHA-256을 동결하고,
리랭커 모델·예상 시간·비용·실행 장치를 먼저 보고해.
사용자 승인 전에는 RunPod 또는 외부 API를 실행하지 마.
```
