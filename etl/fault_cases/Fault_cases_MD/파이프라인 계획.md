# RAG 데이터 파이프라인(ETL) 단계별 통합 구축 상세 계획

## 1. 개요
현재 `review_case`만 단일 진입점(`run_pipeline.py`)이 구성되어 있어, 나머지 `fault_standard`와 `traffic_precedents` 도메인도 동일하게 단일 진입점 스크립트를 구축합니다. 
이후 이들을 모두 아우르는 최상위 오케스트레이터 `run_all_etl.py`를 도입하여, 각 파이프라인의 조율, 부분 실패 제어, 최종 임베딩 단계 실행을 원클릭(딸깍)으로 가능케 합니다.

---

## 2. 도메인별 `run_pipeline.py` 상세 설계

### ① 심의사례 (`src/review_case/run_pipeline.py` 기존 및 기준점)
가장 먼저 완성되어 다른 파이프라인의 **표준 모델**이 된 구조입니다. PDF 수집부터 스테이징 적재까지 4단계로 구성됩니다.

```
[심의사례 파이프라인 단계]
crawl (수집)  ➔  preprocess (전처리)  ➔  schema (DB 스키마 준비)  ➔  load (DB 데이터 적재)
```

- **지원 스테이지 (`--stage`):** `crawl`, `preprocess`, `schema`, `load`, `all`
- **구체적인 매핑 실행 스크립트:**
  - `crawl`: `src/review_case/crawling/one_click_collect.py` 실행
  - `preprocess`: `src/review_case/preprocessing/preprocess_runner.py` 실행
  - `schema`: `src/review_case/db_loading/schema_manager.py` 실행 (DB 및 테이블 준비)
  - `load`: `src/review_case/db_loading/run_db_load.py` 실행 (전처리된 데이터를 DB 테이블에 적재)
  - `all`: 위의 모든 단계를 순차적으로 실행

---

### ② 인정기준 (`src/fault_standard/run_pipeline.py` 신규 생성)
심의사례의 표준 모델을 따라 기존에 분리되어 있던 4개 단계를 하나의 CLI 옵션(`--stage`)으로 통합합니다.

```
[인정기준 파이프라인 단계]
preprocess (전처리)  ➔  staging (스테이징 DB 적재)  ➔  core (코어 테이블 반영)  ➔  search (검색 문서 생성)
```

- **지원 스테이지 (`--stage`):** `preprocess`, `staging`, `core`, `search`, `all`
- **구체적인 매핑 실행 스크립트:**
  - `preprocess`: `src/fault_standard/preprocessing/run_all.py` 실행
  - `staging`: `src/fault_standard/loading/run_staging_pipeline.py` 실행
  - `core`: `src/fault_standard/loading/core/run_core_load.py` 실행
  - `search`: `src/fault_standard/loading/search/run_search_build.py` 실행
  - `all`: 위의 모든 단계를 순차적으로 실행

---

### ③ 판례 (`src/traffic_precedents/run_pipeline.py` 신규 생성)
심의사례 모델을 적용하되, 판례 특유의 1차/2차 분류 및 검증 과정을 정밀하게 조율하는 다단계 파이프라인을 구축합니다.

```
[판례 파이프라인 단계]
crawl (수집) ➔ preprocess (전처리) ➔ classify1 (1차 교통사고 분류) ➔ verify1 (1차 검증) 
➔ classify2 (2차 과실비율 분류) ➔ verify2 (2차 검증) ➔ chunk (청킹) ➔ load (DB 적재)
```

- **지원 스테이지 (`--stage`):** `crawl`, `preprocess`, `classify1`, `verify1`, `classify2`, `verify2`, `chunk`, `load`, `all`
- **구체적인 매핑 실행 스크립트:**
  - `crawl`: `src/traffic_precedents/traffic_precedents_crawling/traffic_prec_api_collector_all_raw_commented.py`
  - `preprocess`: `src/traffic_precedents/traffic_precedents_preprocessing/preprocess_run.py`
  - `classify1`: `src/traffic_precedents/traffic_precedents_1st_classification-traffic accident/traffic_relevance_reclassifier_stage1.py`
  - `verify1`: `src/traffic_precedents/traffic_precedents_1st_classification-verification/traffic_relevance_recheck.py`
  - `classify2`: `src/traffic_precedents/traffic_precedents_2nd_classification-fault_ratio/traffic_fault_ratio_stage2.py`
  - `verify2`: `src/traffic_precedents/traffic_precedents_2nd_classification-verification/traffic_fault_ratio_recheck.py`
  - `chunk`: `src/traffic_precedents/precedent_chunking/build_fault_ratio_precedent_chunks.py`
  - `load`:
    - `src/traffic_precedents/precedent_db_loading/schema_loader.py` 실행 (스키마 준비)
    - `src/traffic_precedents/precedent_db_loading/load_traffic_precedents.py` 실행 (원천 데이터 적재)
    - `src/traffic_precedents/precedent_db_loading/load_fault_ratio_precedents.py` 실행 (최종 청크 데이터 적재)
  - `all`: 위의 모든 단계를 순차 실행

## 3. 최상위 마스터 오케스트레이터 설계 (`src/run_all_etl.py` 신규 생성)

각 도메인별 `run_pipeline.py`를 서브프로세스로 실행하며, 최종 임베딩 작업까지 총괄 제어합니다.

```
[마스터 실행 흐름]
1. 심의사례 run_pipeline.py 실행 (all)
2. 인정기준 run_pipeline.py 실행 (all)
3. 판례 run_pipeline.py 실행 (all 또는 옵션에 따라 일부 생략)
4. (1~3번 중 성공한 결과물들을 모아) 최종 통합 Qwen4 임베딩 실행 (run_qwen4_three_corpora.py)
```

### ⚙️ 핵심 제어 옵션 (Command Line Arguments)
1. `--skip-crawl`: API 수집 단계를 전면 건너뛰어 속도를 단축하고 불필요한 API 비용을 예방합니다. (판례와 심의사례의 crawl 단계 스킵)
2. `--skip-classify`: 시간 소요가 큰 판례의 AI 분류(1차/2차) 및 검증 단계를 건너뛰고 기존 전처리된 캐시를 활용해 임베딩 단계로 바로 넘어갑니다.
3. `--exclude-domains`: 특정 도메인을 파이프라인에서 아예 제외합니다. (예: `--exclude-domains precedent` 지정 시 판례는 아예 수행하지 않고 심의사례와 인정기준만 업데이트)
4. `--ignore-errors`: 특정 도메인의 파이프라인 수행 중 예외/에러가 나더라도 마스터 파이프라인을 중단하지 않고 다음 도메인으로 넘어간 뒤, 성공한 데이터만 통합 임베딩 대상으로 넘깁니다.

## 4. 검증 계획

1. **도메인별 개별 스크립트 실행성 테스트:**
   - `python -m etl.fault_cases.src.review_case.run_pipeline --stage preprocess` 작동 검증.
   - `python -m etl.fault_cases.src.fault_standard.run_pipeline --stage preprocess` 작동 검증.
   - `python -m etl.fault_cases.src.traffic_precedents.run_pipeline --stage preprocess` 작동 검증.
2. **인자 상호작용 검증:**
   - `--skip-crawl`이나 `--skip-classify` 옵션을 걸었을 때, 판례 파이프라인에서 해당 단계들이 정말 우회되는지 확인.
   - `--ignore-errors` 설정 시 한 곳에 일부러 잘못된 입력을 유도하여 다른 도메인의 임베딩까지는 정상 수행되는지 확인.
3. **최종 산출물 검수:**
   - 모든 파이프라인 완료 후 최종 Parquet 파일의 데이터 유효성 및 DB 적재 상태 검증.
