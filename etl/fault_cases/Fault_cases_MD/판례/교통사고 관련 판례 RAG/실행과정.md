# 교통사고 관련 판례 RAG 실행과정

작성 기준일: 2026-07-05

---

## 0. 현재 작업 범위

이번 작업은 `traffic_precedent`를 이용한 **교통사고 일반판례 RAG/Search V1** 준비 작업이다.

중요한 전제:

```text
별도 Agent를 만드는 단계가 아니다.
Supervisor에 바로 연결하는 단계도 아니다.
text_ml_case_search V2 active source로 합치는 단계도 아니다.
```

현재 범위:

```text
traffic_precedent Elasticsearch index를 대상으로
BM25+Nori 기반 교통사고 일반판례 검색 모듈을 준비한다.
```

V1 검색 방식:

```text
BM25+Nori 단독
```

V1에서 제외한 것:

```text
법률용어 hint expansion
pgvector
Elasticsearch hybrid
local reranker A/B 평가
Graph-RAG
```

제외 이유:

```text
현재 프로젝트에 hint expansion 구조가 없고,
traffic_precedent는 아직 Agent가 아니라 검색/RAG standby 단계이므로
가장 단순하고 이미 검증 경험이 있는 BM25+Nori부터 확인하는 것이 맞다.
```

## 1. 1단계: traffic_precedent 검색 인프라 확인

### 목적

`traffic_precedent`가 실제로 Elasticsearch에서 검색 가능한 상태인지 확인한다.

### 왜 필요한가

검색 코드를 새로 만들기 전에 아래를 확인해야 한다.

```text
1. Elasticsearch index가 존재하는지
2. traffic_precedent chunk가 색인되어 있는지
3. 어떤 index명을 사용해야 하는지
4. 기존 판례 검색 코드 중 재사용 가능한 구조가 있는지
```

이 확인 없이 코드를 만들면 없는 index나 없는 field를 대상으로 검색하게 될 수 있다.

### 확인한 내용

기존 검색 설정 파일:

```text
etl/fault_cases/src/traffic_precedents/precedent_search/search_config.py
```

확인된 traffic dataset 설정:

```text
dataset = traffic
Elasticsearch BM25 index = precedent_traffic_chunks_bm25_nori_v1
case_table = traffic_precedent_cases
chunk_table = traffic_precedent_chunks
embedding_table = traffic_precedent_chunk_embeddings
```

기존 BM25 검색 코드:

```text
etl/fault_cases/src/traffic_precedents/precedent_search/elasticsearch/bm25_retriever.py
```

기존 BM25 indexer:

```text
etl/fault_cases/src/traffic_precedents/precedent_search/elasticsearch/bm25_indexer.py
```

기존 Elasticsearch client:

```text
etl/fault_cases/src/traffic_precedents/precedent_search/elasticsearch/client.py
```

기존 index report:

```text
etl/fault_cases/artifacts/traffic_precedents_output/elasticsearch_exports/traffic/traffic_elasticsearch_bm25_index_report.json
```

### 확인 결과

`traffic_precedent` BM25/Nori index는 이미 생성되어 있고, chunk 색인도 완료되어 있다.

```text
index = precedent_traffic_chunks_bm25_nori_v1
indexed_document_count_after = 25,952
bulk_error_count = 0
```

### 결과 해석

```text
traffic_precedent BM25+Nori 검색 인프라는 사용 가능하다.
따라서 V1에서는 새 index를 만들지 않고 기존 index를 사용한다.
```

## 2. 2단계: traffic_law sample query 10개 작성

### 목적

교통사고 일반판례 RAG/Search V1을 검증하기 위한 고정 query set을 만든다.

### 왜 필요한가

검색 품질을 확인하려면 같은 질문 세트가 필요하다.

```text

```

또한 `traffic_precedent`는 과실비율보다 교통사고 일반 법률 쟁점에 가깝기 때문에, query도 다음 주제를 중심으로 잡아야 한다.

```text

책임 판단
신호위반
중앙선 침범
보행자 보호의무
음주운전
사고 후 미조치
안전거리
```

### 생성한 파일

```text
etl/fault_cases/src/traffic_precedents/precedent_search/traffic_law/sample_queries.py
```

## 3. 3단계: BM25+Nori retriever 작성

### 목적

`traffic_precedent` Elasticsearch index에 BM25+Nori 검색 요청을 보내는 전용 retriever를 만든다.

### 왜 필요한가

기존 판례 검색 코드가 있지만, `traffic_law` RAG/Search V1은 별도 실험 흐름으로 관리하는 것이 좋다.

이유:

```text
1. traffic_precedent는 Agent가 아니라 검색/RAG 모듈이다.
2. text_ml_case_search V2와 섞지 않아야 한다.
3. 기존 precedent_search 구조 아래에 traffic_law 전용 코드를 두면 역할이 명확하다.
4. 추후 교통사고 법률 Agent가 생기면 이 검색 모듈만 가져다 쓸 수 있다.
```

### 생성한 파일

```text
etl/fault_cases/src/traffic_precedents/precedent_search/traffic_law/bm25_nori_retriever.py
```

패키지 초기화 파일:

```text
etl/fault_cases/src/traffic_precedents/precedent_search/traffic_law/__init__.py
```

### 검색 대상 index

```text
precedent_traffic_chunks_bm25_nori_v1
```

### 검색 field

```text
search_text^4
chunk_text^2
case_name^1.5
search_text_standard
chunk_text_standard
```

field 가중치 이유:

```text
search_text:
  검색용으로 정리된 필드이므로 가장 높게 본다.

chunk_text:
  실제 본문 근거이므로 중요하지만 search_text보다 낮게 둔다.

case_name:
  사건명에 사고 유형이 들어갈 수 있으므로 보조 신호로 사용한다.

standard field:
  Nori 분석과 다른 일반 분석 기준의 보조 매칭용으로 둔다.
```

### 검색 조건

```text
multi_match
type = best_fields
operator = or
highlight 사용
```

`operator="or"`를 쓰는 이유:

```text
교통사고 질의는 표현이 길고 다양하다.
and 조건을 쓰면 모든 단어가 들어간 문서만 찾게 되어 후보가 과하게 줄어들 수 있다.
or 조건으로 넓게 후보를 찾고, BM25 점수로 관련도를 정렬한다.
```

highlight를 쓰는 이유:

```text
검색 결과가 어떤 문구 때문에 매칭되었는지 확인하기 위해서다.
이후 보고서에서 matched_snippets로 보여줄 수 있다.
```

### 주요 함수

```text
build_traffic_law_bm25_query(...)
search_traffic_law_bm25(...)
build_traffic_law_source_reference(...)
```

### retriever 출력 구조

검색 결과는 다음 정보를 포함하도록 만들었다.

```text
query_source
retriever
source_type
rank
case_id
chunk_id
chunk_type
case_name
case_number
court_name
decision_date
retriever_score
score_type
source_reference
chunk_preview
search_preview
matched_snippets
metadata
```

### source_reference 형식

```text
precedent_traffic_db:{case_id}#{chunk_id}
```

예상 목적:

```text
나중에 검색 결과가 어떤 판례 chunk에서 온 것인지 추적하기 위해서다.
```

## 7. 4단계: sample query 실행 runner 작성

### 목적

2단계에서 만든 `traffic_law` query 10개를 BM25+Nori로 한 번에 실행하고, 결과를 JSON으로 저장한다.

### 왜 필요한가

단일 query 검색 테스트만으로는 전체 검색 품질을 판단하기 어렵다.

```text
traffic_law_q001 ~ traffic_law_q010 전체를 같은 조건으로 실행해야
BM25+Nori가 교통사고 일반판례 RAG V1로 쓸 만한지 검수할 수 있다.
```

### 생성한 파일

```text
etl/fault_cases/src/traffic_precedents/precedent_search/traffic_law/run_bm25_sample_queries.py
```

### 코드 역할

```text
1. sample_queries.py에서 query 10개를 읽는다.
2. Elasticsearch client를 만든다.
3. 각 query마다 search_traffic_law_bm25(...)를 호출한다.
4. query별 top_k 검색 결과를 모은다.
5. 전체 결과 JSON과 summary JSON을 저장한다.
```

### 예상 산출물

```text
etl/fault_cases/artifacts/traffic_precedents_output/traffic_law_rag/traffic_law_bm25_sample_queries.json
etl/fault_cases/artifacts/traffic_precedents_output/traffic_law_rag/traffic_law_bm25_summary.json
```

### 사용자가 실행할 명령

```powershell
.\.venv\Scripts\python.exe -B -m etl.fault_cases.src.traffic_precedents.precedent_search.traffic_law.run_bm25_sample_queries --top-k 5
```

### 예상 결과

```text
query_count = 10
total_result_count = 50
zero_result_query_ids = []
```

`top-k 5` 기준으로 모든 query가 5개씩 결과를 반환하면 총 50개 후보가 생긴다.

## 8. 5단계: 검색 평가 보고서 생성기 작성

따라서 query별로 아래 정보를 표와 preview로 보여줘야 한다.

```text
top1 판례
case_name
case_number
court_name
decision_date
source_reference
matched_snippets
chunk_preview
```

### 생성한 파일

```text
etl/fault_cases/src/traffic_precedents/precedent_search/traffic_law/build_rag_report.py
```

### 코드 역할

```text
1. traffic_law_bm25_sample_queries.json을 읽는다.
2. traffic_law_bm25_summary.json을 읽는다.
3. query별 top1 대표 판례를 추출한다.
4. matched_snippets와 chunk_preview를 정리한다.
5. JSON 보고서와 MD 보고서를 생성한다.
```

### 예상 산출물


BM25 sample query 실행 후 아래 명령을 실행한다.

```powershell
.\.venv\Scripts\python.exe -B -m etl.fault_cases.src.traffic_precedents.precedent_search.traffic_law.build_rag_report
```

### 예상 결과

```text

```

그리고 MD 보고서에서 query별 대표 판례와 본문 preview를 확인할 수 있다.
