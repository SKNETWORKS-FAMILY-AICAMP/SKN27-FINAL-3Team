## 1. 시스템 개요

과태료·범칙금 고지서 분석 Agent는 LangGraph StateGraph 기반 **2-노드 AI 파이프라인**이다. 사용자가 업로드한 고지서 이미지를 OCR로 판독하여 문서 유형을 분류하고 구조화 데이터를 Supervisor에게 반환한다.

감경 판단·이의신청서 생성은 Supervisor 또는 별도 Agent 책임이며, 본 에이전트는 **이미지 입력 → 분류 → 필드 추출** 역할에 집중한다.

### 1-1. 설계 원칙

| 원칙 | 내용 | 근거 |
|------|------|------|
| 이미지 전용 입력 | 텍스트 직접 입력·자연어 보완 경로 제거 — 이미지 없으면 즉시 failed | — |
| 단방향 데이터 흐름 | 노드 간 State 공유 — 역방향 의존 금지 | — |
| State 오염 방지 | 새 이미지 재입력 시 OCR 관련 필드 전체 초기화 | R-03 |
| 조기 검증 | 조합 유효성(fine_type × notice_stage)을 confidence_verification에서 차단 | R-01 |
| 보수적 판단 | 기한 파싱 불가 시 None 저장 — 과신 금지 | R-04 |
| 마스킹 선행 | GPT 응답 수신 직후 개인정보 마스킹 — State 저장 이전 | R-11 |
| 구조적 부재 허용 | 별지 168호(law_code·vehicle_number 없음) → degraded 반환 | — |

## 2. 컴포넌트 구성

### 2-1. 레이어 구조

```
┌─────────────────────────────────────────────────────────────────┐
│  Layer 1 — Interface Layer                                      │
│  Supervisor (LangGraph Entrypoint)                              │
│  graph.invoke() 호출 / agent_results 수신 / 사용자 메시지 중계   │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  Layer 2 — Pipeline Layer (LangGraph StateGraph)                │
│  ① ocr_node  →  ② confidence_verification_node                 │
└─────────────────────────────────────────────────────────────────┘
                ↓
┌──────────────────────────┐   ┌────────────────────────────────┐
│  Layer 3a — AI Provider  │   │  Layer 3b — Storage            │
│  GPT-4o Vision           │   │  pymupdf (PDF → PNG)           │
│  (이미지 → JSON 추출)      │   │                                │
└──────────────────────────┘   └────────────────────────────────┘
```

### 2-2. 노드별 역할 정의

| 노드 ID | 노드명 | 역할 | LLM 사용 | 주요 입력 | 주요 출력 |
|---------|--------|------|----------|----------|----------|
| ① | ocr_node | 이미지 수신·변환·OCR·마스킹·fine_type 분류·신뢰도 평가 | GPT-4o Vision | notice_image (base64) | ocr_status, fine_type, notice_stage, 추출 필드 전체 |
| ② | confidence_verification_node | 형식 검증 + fine_type×notice_stage 조합 검증 + 문서 유형 확정 | 없음 | ocr_node 출력 전체 | ocr_status (재판정), format_errors |

### 2-3. v2.0 대비 제거 항목

| 제거 항목 | 제거 이유 |
|----------|----------|
| violation_analysis_node | 위반 유형 정규화는 Supervisor 또는 이의신청서 Agent 책임 |
| reduction_rule_node | 감경 계산은 Supervisor 책임 |
| evidence_package_node | 필요 서류 안내는 Supervisor 책임 |
| objection_decision_node | 이의 가능 여부 판단은 Supervisor 책임 |
| FINE_RULES dict | reduction_rule_node 제거에 따라 불필요 |
| VIOLATION_DOCUMENTS dict | evidence_package_node 제거에 따라 불필요 |
| 텍스트 직접 입력 경로 | 이미지 전용 정책 — OCR 스킵 경로 제거 |
| ocr_source "text" / "text_supplement" | 이미지 경로만 유효 |
| attachments 입력 경로 | 이미지 해결은 Supervisor 책임 — OCR 에이전트는 notice_image(base64)만 수신 |

### 2-4. 외부 의존성

| 컴포넌트 | 유형 | 사용 노드 | 장애 시 영향 | 비고 |
|----------|------|----------|-------------|------|
| GPT-4o Vision API | 외부 AI API | ① | ocr_status=failed | JSON 파싱 실패 핸들러 필요 |
| pymupdf | 로컬 라이브러리 | ① | PDF 입력 불가 → failed | PDF→PNG 변환, 최대 10페이지 (R-08) |

## 3. 파이프라인 흐름 설계

### 3-1. 정상 흐름

```
┌────────────────────────────────────────────────────────────────┐
│  INTERFACE LAYER                                               │
│  Supervisor ──► graph.invoke({ notice_image, today })          │
└───────────────────────────────┬────────────────────────────────┘
                                │
┌───────────────────────────────▼────────────────────────────────┐
│  PIPELINE LAYER                                                │
│                                                                │
│  ① ocr_node                                                    │
│    · notice_image 없음 → failed (이미지 재업로드 요청)            │
│    · PDF: pdf_to_images() — >10p → failed (R-08)              │
│    · GPT-4o Vision 호출 → R-11 즉시 마스킹 → JSON 파싱         │
│    · _classify_fine_type() → fine_type 결정                    │
│    · 벌금·None → rejected 즉시 반환 (이후 단계 생략)             │
│    · evaluate_ocr() → ocr_status, missing_fields               │
│    · partial → rejected 없이 즉시 반환 (분류 불가)               │
│    · notice_image = None (개인정보 폐기)                        │
│    │                                                           │
│  ② confidence_verification_node                                │
│    · 형식 검증 (notice_stage / fine_type / fine_amount / law_code)│
│    · 조합 검증: fine_type × notice_stage (R-01)                │
│    │                                                           │
│    ▼                                                           │
│  agent_results 반환 (FineNoticeEnvelope)                       │
└───────────────────────────────┬────────────────────────────────┘
                                │
                 Supervisor가 사용자에게 결과 전달
```

### 3-2. 문서 유형 분류 흐름

```
fine_type?
  ├─ 벌금  → ocr_status=rejected  (형사벌금 서비스 범위 외)
  ├─ None  → ocr_status=rejected  (고지서 인식 불가)
  ├─ 과태료
  │    ├─ 사전통지 → ① 과태료 사전통지서 (별지 154·155호의2)
  │    └─ 1차 고지서 → ② 과태료 고지서 (별지 151·152호)
  └─ 범칙금
       ├─ 사전통지 → ③ 범칙금 사전통지서 (별지 159호의2·162·163호)
       └─ 즉결심판 → ④ 즉결심판 출석통지서 (별지 168호)
```

### 3-3. ocr_status 분기 매트릭스

| 조건 | ocr_status | Supervisor 액션 |
|------|-----------|----------------|
| critical + important 필드 모두 정상 | success | 결과 활용 |
| critical 정상 / important 일부 누락 | degraded | 이미지 재업로드 요청 |
| critical 누락 또는 형식·조합 오류 | partial | 이미지 재업로드 요청 |
| 이미지 판독 불가 / JSON 실패 / PDF 초과 | failed | 이미지 재업로드 요청 |
| 벌금 또는 인식 불가 | rejected | 서비스 범위 외 안내 |
| 별지 168호 (law_code 구조적 부재) | degraded | 허용 수준 판단 |

## 4. State 설계

### 4-1. LangGraph State 필드 목록

| 필드명 | 타입 | 공급자 | 소비자 | 비고 |
|--------|------|--------|--------|------|
| notice_image | str\|None | Supervisor | ① | OCR 완료 후 None 대체 |
| notice_mime_type | str | Supervisor | ① | "image/jpeg"\|"image/png"\|"application/pdf" |
| ocr_status | str | ①② | Supervisor | "success"\|"degraded"\|"partial"\|"failed"\|"rejected" |
| ocr_error | str\|None | ① | Supervisor | PDF 초과 등 구조 오류 (R-08) |
| fine_type | str\|None | ① | ② | "과태료"\|"범칙금"\|"벌금"\|None |
| notice_stage | str\|None | ① | ② | "사전통지"\|"1차 고지서"\|"즉결심판" |
| law_code | str\|None | ① | ② | |
| violation_text | str\|None | ① | ② | 위반 내용 원문 (마스킹 후) |
| fine_amount | int\|None | ① | ② | |
| prepayment_amount | int\|None | ① | Supervisor | 범칙금·즉결심판은 None (R-06) |
| opinion_deadline | str\|None | ① | Supervisor | YYYY-MM-DD (R-04). ② 과태료 1차 고지서는 납부기한 — 이의신청 기한(수령일+60일)과 다를 수 있어 Supervisor 별도 계산 필요 |
| payment_deadline_2nd | str\|None | ① | Supervisor | YYYY-MM-DD. ③ 전용 — 2차 납부기한 (1차+20일 가산) |
| additional_amount | int\|None | ① | Supervisor | ③ 전용 — 2차 납부 시 가산금액 (fine_amount × 1.2) |
| vehicle_number | str\|None | ① | Supervisor | 마스킹됨 |
| violation_datetime | str\|None | ① | Supervisor | |
| violation_location | str\|None | ① | Supervisor | |
| issuing_authority | str\|None | ① | Supervisor | |
| demerit_points_base | int\|None | ① | Supervisor | 범칙금 전용 |
| demerit_points_accumulated | int\|None | ① | Supervisor | 범칙금 전용 |
| charge_number | str\|None | ① | Supervisor | 과태료·범칙금 통고서 전용 |
| court_venue | str\|None | ① | Supervisor | ④ 즉결심판 전용 — 출석 장소 |
| missing_fields | list | ①② | Supervisor | |
| format_errors | list | ② | Supervisor | R-01 조합 오류 포함 |

> R-03: notice_image가 새로 도착하면 ocr_node 진입 시 OCR 관련 필드 전체 초기화. 이전 실패에서 남은 ocr_error도 `flat["ocr_error"] = result.get("ocr_error")`로 덮어씀.

## 5. 오류 처리 설계

| 오류 유형 | 발생 위치 | 감지 조건 | 처리 방식 |
|----------|----------|----------|----------|
| 이미지 없음 | ① | notice_image=None | ocr_status=failed |
| PDF 페이지 초과 | ① | len(pages) > 10 | ocr_status=failed, ocr_error="PDF 페이지 초과" (R-08) |
| PDF 빈 페이지 | ① | pages=[] | ocr_status=failed, ocr_error="PDF 변환 결과 페이지 없음" |
| GPT JSON 파싱 실패 | ① | json.JSONDecodeError | ocr_status=failed, ocr_error="GPT 응답 파싱 실패" |
| 무효 조합 | ② | fine_type × notice_stage 매트릭스 불일치 | format_errors 추가, ocr_status=partial (R-01) |
| fine_type=None 또는 벌금 | ① FT 분류 즉시 | 서비스 범위 외 / 인식 불가 | ocr_status=rejected |
| law_code 구조적 부재 | ② | 범칙금 즉결심판 + law_code=None | ocr_status=degraded (별지 168호) |

## 6. 보안 / 개인정보 처리 설계
